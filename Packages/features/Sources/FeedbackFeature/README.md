# FeedbackFeature

Help › Report a Problem… (DEV-887). `ProblemReportFeature` holds one report: the description, Include diagnostics (on by default for the report, since the person is filing it on purpose), and what `DiagnosticsClient` reads when the sheet appears: the versions and the diagnostics (the Mac's model and memory, and crash reports from the last 7 days). Reading collects first, so a crash from this session can go with the report.

`ProblemReportView` shows exactly what goes: the description, a line naming the versions filled in on the issue (Arx, Helium and Chromium, macOS, architecture), and Include diagnostics with the number of crash reports it adds. Open Issue on GitHub (Return) sends `delegate(.openIssue(url))` with the Arx repository's new issue page (`GitHubIssue`), prefilled with the description and versions. With Include diagnostics on, or with a description too long for the address (`GitHubIssue.fits`), it first saves the report as a file in Arx's Problem Reports folder, selects it in Finder, and names the file (never its folder) on the issue for the person to attach. Arx sends nothing itself: the person files the issue with their GitHub account. The sheet then stays (`.opened(file:)`) and names the saved file and its folder, with Show in Finder (`ui(.showFile)`), or offers Save Report… when no file was saved, because the issue page only opens for people the repository is open to; until it's public, they send the file another way. Save Report… writes the same JSON to a file the person picks. A failed save says why and keeps the text; editing clears the message. Cancel or Escape closes it, except while the report file is being saved. Done closes it.

AppFeature presents it as a sheet on the main window, opens it from the Help menu and from Settings › Privacy, and opens the issue page in a new tab.

## Send Feedback

Help › Send Feedback… (DEV-1284), also a `BrowserCommand` (`sendFeedback`, ⌘⌥⇧I) in the command bar and Settings › Shortcuts. Reports go privately to Arx's maintainer: the backend (`arx-browser-backend`, `POST /v1/feedback`) files each one in the private Linear project "Arx Reports" and keeps nothing.

- `SendFeedbackFeature` holds the draft (`FeedbackDraft`: kind, text, email, Include diagnostics, files). It's read from disk when the card opens and saved half a second after each edit and on close, so an unsent draft, files included, is there next time. Sent, only the email stays. Sending with nothing written says "Write something first"; an email that isn't an address stops it too.
- Kinds: bug report, feature request, vulnerability (Urgent in Linear, with the `security` label) and other. The text field's prompt follows the kind.
- Files come from the attach button, a drop or ⌘V (a screenshot from the clipboard, as PNG): up to 5, 4 MB together, of the types the backend takes (`SendFeedback.attachmentTypes`). A large still picture re-encodes as a JPEG no larger than a Retina screen (`FeedbackAttachments`); anything else that doesn't fit is refused with the total it would make.
- Include diagnostics sends the versions and what Report a Problem saves (`DiagnosticsClient.diagnostics()`), with the oldest entries left out past 1 MB (`FeedbackForm.diagnostics`). Never page content, addresses or history.
- `SendFeedbackClient` posts the multipart form (`FeedbackForm.body`) to `ArxService.backendURL()` (BrowserCore), and maps the answer to a `FeedbackFailure` the card words plainly. Debug builds use a fake that takes every report unless `ARX_BACKEND_URL` names a backend; tests set the closures they use.
- `SendFeedbackView` draws the card as a Raised modal (DEV-1308): the title on an `ArxHeaderBar` with no Close, since Cancel closes it; it says the report is private and links to GitHub's issue forms (`ArxService.publicIssueForms`). The kinds are AppUI's `ArxSegmentedControl` with text labels, the selected one kept filled; only Vulnerability has a tooltip, a short hint, and its note shows under the text while it's the kind. The email is a `SettingsTextField`, Include diagnostics a `SettingsToggle` in a `SettingsSection`, under which "By sending this report, you agree to our Privacy Policy." links the policy's name (`ArxService.privacyPolicy`). The versions are a footnote beside Cancel and Send.

AppFeature puts it as a sheet on the window it was asked from (`SendFeedbackPresentation`, `AppFeature.FeedbackHost`): a browser window, or the Settings window when it was asked from there (DEV-1308), where closing Settings closes the card and keeps the draft, or, while a report is going or a file is being read, moves the card to the main window. It opens links in a tab of the main window after closing the card, and, with the `ARX_FEEDBACK_FORM` feature flag off, opens Report a Problem instead. The app smoke's `validateAuxiliaryWindows.SendFeedbackSmoke` stage covers the sheet.
