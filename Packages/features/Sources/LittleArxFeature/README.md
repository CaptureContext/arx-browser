# LittleArxFeature

Command-bar execution carries its selected entry and presentation sequence. The host captures the temporary tab, profile, space, viewer generation and mode when opening the bar, consumes that context once, and rejects missing or stale origins. Closing, switching profile, promotion and dismissal invalidate the bar, including canceled transitions; reopening is a fresh request. Query edits and leaving site-search mode preserve the same origin.

An independent temporary browser window reusing ViewerItemFeature and CommandBarFeature. Each invocation creates a unique tab and window identity with explicit space/profile context. It does not persist or restore temporary sessions. The shared Settings shortcuts apply here too.

Close asks the engine for before-unload approval. Promotion delegates to AppFeature: same-profile promotion transfers the existing page, while cross-profile promotion creates an isolated destination session after explicit disclosure. With `ARX_PAGE_PIP_SPACES` (DEV-1184) that disclosure is AppUI's `ProfileMoveConfirmation` (a sheet, or over the page while the window is Page PiP), saying the page reloads in the space's profile without its sign-ins; Escape cancels. As Page PiP, the header's space picker opens the page in the chosen space the same way. Failure retains the source. Native hosting owns display placement, focus and fullscreen behavior; verify those on the user's displays.

Cmd+Option+A starts with only the command bar and no native page. URL/search submission creates the page and expands the panel; Escape dismisses the initial panel. Incoming URLs open directly into the viewer.

An empty launcher query offers the profile's recent history, open tabs and Favorites with favicons and “host/path” subtitles, frozen when the window opens by AppFeature; every suggestion opens in this temporary window. Commands appear on a text match, and New Little Arx window is never offered here.

The launcher's profile picker (DEV-1331, `LauncherProfilePicker.swift`) sits at the bar's bottom-left corner as Actions ⌘K's twin: the same `CommandBarFloatingButton` and, open, the same `CommandBarActionsPanel` at the leading edge. It shows while `offersProfilePicker`: an open launcher bar, not private, with more than one of `launcherProfileIDs` (AppFeature's profiles with a space). ⌘I (`profilePickerShortcut`, unless a command has the key) or the button toggles it; Return chooses, Esc closes, and ⌘K's actions and the list close each other. Choosing another profile sends `delegate.launcherProfileRequested`; AppFeature answers with `useLauncherProfile`: that profile's space, search engine and suggestions, which replace the previous profile's, and the bar is presented again with the same text. The launcher bar moves by its background (DEV-1335, AppUI's `WindowBackgroundDragArea` behind the bar, which moves the panel in Arx's own event loop: a window server drag cost the bar the keyboard, which closes it); `LittleArxPanel` keeps a dragged bar on screen, and every new bar opens at `launcherFrame` again. A Little Arx showing a page moves as before.

The command-only panel fits the measured command bar with eight-point padding, keeps its top edge fixed while results change, and closes on focus loss. It uses a borderless native panel to avoid title-bar corner artifacts. Expanded viewers remain open on focus loss.

The expanded toolbar is a minimal 36-point row: native window controls, navigation and a profile picker on the leading side, a compact URL bar centered in the window, and the Peek control and a primary “Open in <space>” action with alternate destinations on the trailing side. The page sits in the shared AppUI page card. Changing profile honors before-unload, closes the old session, and opens only the current URL under a fresh tab identity in the selected profile. Cookies, history, and session state are not transferred. Profiles need a destination space before they can be selected.

Clicking the expanded toolbar URL field opens the address editor over that field, with the full URL selected. Keyboard command entry remains centered; a submitted destination navigates the temporary page.

The shared Downloads command becomes available with the application queue and preserves Little Arx when opening its utility.

Accepted registry commands and raw URL submissions retain their source through the remaining dispatch hop. Immediately after revalidation, the feature reduces the existing command or ViewerItem action synchronously, so native effects capture that session identity. Lifecycle invalidation advances the bar sequence even when a close or promotion is later canceled.

Peek owns the overlay and its separate temporary session; the original viewer stays mounted but inert. A host-owned preview ID blocks underlying commands, profile changes and promotion and redirects host close to the preview first. Normal Little close approval carries a request token, tab/profile identity and viewer generation through the parent removal, rejecting a late approval after session replacement. Closing only the preview restores the original viewer; promoting it retains the original Little window.

The window is one 44-point row: window controls, a Back button only while there is history to go back to, a URL bar with the shared `ProfileBadge` inside it and its site-information and copy-link buttons always shown, and an Open in button with a searchable space list. Open in is AppUI's `ChromeSplitButton` (DEV-768): the URL bar's surface, with "Open in <Space> ⌘O" and the ⌄ list as two parts that each light on hover and press. The page card sits 1 pt in from the window's sides and bottom, with corners concentric with the window's and the main window's soft shadow. Forward and reload stay on the keyboard and menus. There is no separate Peek URL-entry button. Clicking the URL bar opens the command bar centered in the window, and its input is always one line.

The panel never activates Arx, so opening it leaves other Arx windows where they are and stays on a full-screen app's Space. The bar opens where Settings > Links says, top right by default. Only moving a page into a normal window brings Arx forward.

Links stay in Little Arx (DEV-855). AppFeature opens a page's new tabs and popups in a new Little Arx whose `openerWindowID` names this one, and gives focus back to the opener when such a window closes while focused. A popup from a main window or Peek opens in a new Little Arx too (DEV-1186), its `openerWindowID` naming that window.
