# ViewerFeature

Composes one to four identified ViewerPaneFeature placements, with each pane's share of the length in `fractions`. A pane's actions are its item's (`item`); its `ui`, `event`, `delegate` and `observation` domains are empty. Each pane owns a ViewerItemFeature observation lifetime; native sessions remain service-owned. Explicit pane and tab identities isolate navigation, retries and renderer events from focus changes. Split placement supports horizontal or vertical orientation, an accessible resizable divider, focus, swapping and closing a pane without closing its tab.

Requires macOS 27 and Swift 6.4. Features use core, services, AppUI and lower-level features; services never import features. Verify with `make test-all`.

Per-space presentation snapshots retain pane IDs, active pane, orientation and divider proportion. Space transitions cancel outgoing observations, sanitize missing or moved references, then resume each restored pane. A pane that already shows a restored page, such as a Favorite selected in both spaces, keeps its identity, item and observation: `apply` lists it in `continuingPaneIDs` and the next `resume` leaves it alone, so the page's host view never changes and it neither reloads nor flashes (DEV-771). Superseded transition requests are ignored.

A viewer retains its observation generation across removed panes and allocates fresh generations when restoring or observing placements. Queued callbacks cannot regain authority when a saved pane and tab return. Exhausting the generation counter refuses further restoration and observations instead of wrapping; clearing and suspending remain available.

An explicit requested tab is placed in the saved active pane before stale identities are removed. This preserves a valid neighboring split pane when a cross-profile move or Undo replaces the active tab with a fresh identity. Claimed tabs and tabs outside the destination space/profile cannot be inserted.

`layout` replaces the panes with a list of tabs, keeping panes that already show one of them and lending other panes' identities to the rest in order (a single tab takes the active pane), leaving out `tabsShownElsewhere`, which AppFeature fills in just before a window lays out a group. Its shows are `showInLayout`, so MainFeature never takes them for the user changing a pane. `capacity` is how many panes fit at 280 pt along each axis; the view reports it only when that number changes, and `split`, `insert` and `toggleOrientation` refuse what doesn't fit. ViewerView keeps divider drags and drop-zone hover as local state and sends `resize` with the final shares once.

`splitEmpty(at:orientation:)` adds an empty pane at a position, turning the split to that orientation (the developer header's Add Split, DEV-733). `ViewerView` shows `DeveloperHeader` instead of the split pane header over local pages when its host asks for it, and squares the viewport's top corners under it (DEV-786). A split pane's header shows `PaneAddress`, the whole URL without its scheme, and a click on it selects the pane and calls `onEditAddress`, which the window maps to the `address` pane command: the command bar edits that pane's address (DEV-993). While the pane shows a page, its header also shows `PaneHeaderActions` before the close button; the link button calls `onCopyURL`, which the window maps to the `copyURL` pane command (DEV-995). `PaneClickMonitor`, behind each pane of a split, selects the pane on any mouse-down inside it (header, page, empty pane or chat tab) with a local monitor that hands the event back unchanged and never takes part in hit testing, so the click still reaches what's under the pointer.
