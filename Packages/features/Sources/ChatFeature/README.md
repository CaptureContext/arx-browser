# ChatFeature

The built-in assistant's chat panel (DEV-720, designed in DEV-645): one `ChatFeature` per profile, its panel views and Settings › Assistant. Settings › Assistant opens with two page rows (DEV-745): AI Commands lists the actions you'd run (organize today's tabs, tidy pinned-tab titles, tidy downloaded filenames, summarize links on hover, open the top search result), and Assistant Features holds assistant search shortcuts and automatically enabling future features. Every row there is "Not yet available" and nothing runs; release builds show AI Commands as "Coming soon" and hide Assistant Features, as with Settings' other unfinished options. SettingsFeature owns both pages (`SettingsPage`). `ChatSettingsView` follows as grouped sections: Providers, then under a Profiles header one section per profile with its default provider (with the provider's mark), default model and how long chats are kept. Providers lists each provider with its mark, the tool Arx runs for it (`AgentProvider.toolName`: Claude Code, Codex) and a status dot with the signed-in account and plan when the provider reports them. Connections are app-wide, so the list shows the first profile's check. There is no effort setting: the adapters take one per request but the chat never sets it. It runs on the agent layer in [AgentClient](../../../services/Sources/AgentClient/README.md).

## Where things live

- **One `ChatFeature` per profile.** `AppFeature` keeps them in `chats`, outside any window, so hiding the panel or closing the window never stops a turn. A window only owns `MainFeature.State.isChatOpen`, the panel's width (`chatWidth`) and its pins (`chatPins`). Private windows have no chat.
- **Surfaces (DEV-761).** The profile's chats can show in several places at once, each a `ChatSurfaceID` with its own `ChatSurface` (chat, screen, composer, Your Chats' filters): `.window(id)` is a window's global chat, `.pinned(tab)` the panel on a tab a chat is pinned to, `.tab(tab)` a chat tab. A view scopes to `state[surface:]` and its actions arrive as `.surfaces(.element(id, action))`, which makes that surface the active one before the action runs, so the reducer reads `selectedID`, `draft` and the rest through the active surface. `activeSurfaceID` is a cursor and isn't observed (DEV-789): `state[surface:]` sets it on a copy that shares the state's observation registrar, so an observed cursor made every view on a surface other than the last active one invalidate itself on each read and render forever (the Pin to This Tab and Open in Tab hang). Chats, turns, failures, unread and settings stay profile-wide; ending a chat or changing the defaults updates every surface. A surface that moves to another chat sends `delegate(.surfaceChanged)`, and a renamed chat `delegate(.titlesChanged)`, so the app keeps pins and chat tabs following their chats. `ui.show(_:)` places a chat on a surface even before the chats are read. `ChatPlacement` tells the view where it shows and which of Pin to This Tab, Unpin from This Tab, Open in Tab and Move to Sidebar it offers; `AppFeature`'s `ChatPlacements` carries them out.
- **Turns** run in an effect that iterates `AgentProviderClient.send(_:).coalesced()`. Text reaches the store in batches, at most about ten a second (`event.turnEvents`). Each turn is cancellable by its chat's ID; Stop cancels it.
- **Providers** come from `AgentProviders` (`@Dependency(\.agentProviders)`), a list of adapters: Claude Code (`ClaudeAgentClient`, DEV-644) and ChatGPT through the Codex CLI (`CodexAgentClient`, DEV-643). Another provider is added by appending its `AgentProviderClient` to `liveValue`; the per-chat picker and Settings read the list. A chat's provider can change only before its first turn, because a provider's handle can't move to another provider. Its model can change at any time.

## Behavior

- **Entry:** `ui.start(text)` comes from text + Tab in the command bar. When the profile's settings haven't been read yet, the prompt waits in `pendingPrompt` so the chat starts with the profile's provider, model and retention.
- **Retention:** chats start with the profile's `AgentRetention`. An ephemeral chat's idle timer (`ExpiryID`, `continuousClock`) restarts after each answer, Stop or failure and is paused while a turn runs. After 20 idle minutes the chat ends: `AgentConversationStore.delete(_:provider:)` discards the provider's transcript. Its transcript is remembered as soon as the turn reports `started`, so the app's launch and quit sweeps catch it after a crash.
- **Pin** keeps an ephemeral chat (saved, transcript forgotten by the ledger); unpinning makes it temporary again. **Archive** applies to kept chats only (`AgentConversation.archivedAt`). **Delete** ends any chat.
- **Failures** (`AgentFailure`) are shown with plain text and a Try Again button, as a note under the transcript (DEV-643). The prompt always stays in the transcript, and a kept chat is saved with it before the provider runs and again when the turn fails, so a message is never lost. Only an empty reply is dropped, and none is ever written; a partial answer stays. Saves of one chat are written in the order they were asked for (`ChatSaves`): each runs in its own effect, so without it the save made as a turn starts could land after the failure's or the answer's and replace it. Try Again sends the same prompt again under the same message (`ChatFailure.promptID`). A chat with a failure is never shown as a new chat, so its note is always visible.
- **Silence** (`TurnWatchID`, `continuousClock`): a running turn fails with `AgentFailure.timedOut` when the provider sends nothing for `ChatFeature.turnSilenceLimit` (three minutes). Each batch of events starts the wait over, and a browser tool that's still running, such as one waiting for approval, doesn't count as silence.
- **Attachments** come only from what the person attaches: the + picker (`ChatAttachable`: this tab, folders, the profile's tabs), and files, images and page captures (DEV-798). Typing never sends page content. Files dropped on the panel, picked with Files… or pasted arrive as `ui.filesAdded`; a pasted image or a capture as `ui.imageAdded`. `ChatAttachmentLoader` reads them in an effect (images scaled to at most 2,048 px and 3.5 MB, with a 160 px preview) and `event.attachmentsLoaded` adds them to the surface they came from, checked against the chat's provider (`AgentAttachmentLimits`). What doesn't fit becomes the surface's `attachmentIssue`, shown under the chips; sending re-checks, as the provider may have changed. The turn carries the bytes; the transcript keeps each file `withoutData`.
- **Browser tools:** the turn asks `AgentBrowserAccess` for the profile's connection. Without one it runs without tools, and the panel offers Allow (`delegate.allowBrowserTools`), which AppFeature turns into a profile-scoped automation client.
- **Unread:** an answer that lands while the person looks at another chat or screen marks its chat unread for Your Chats' Unread filter.

## Views

`ChatPanelView` is the panel, and also a chat tab's content (`ChatPlacement.Kind.tab`: no ×, and ⇧esc does nothing). It keeps the ⋯ actions (`ChatActionsMenu`, searchable), Rename, the Archive and Delete confirmations, chat info (`ChatInfoView`, opened from the title), ⇧esc to hide and the card behind the panel, and hands the rest to `ChatStudioPanel` with a `ChatPanelContext`. `ChatSettingsView` is Settings › Assistant's chat section. Markdown links open only for `http` and `https`; images are never loaded.

Not in this version: Projects, inline chat in the command bar, and ⌘N for New Chat (it's New Window).

`event(.providerConnected(_:))` comes from onboarding's connect-your-agent page (DEV-700) and makes the provider the profile's default, clearing the model and account. When it arrives before the profile's defaults are read, it waits in `pendingProvider`, starts reading them if nothing is, and replaces the read provider once they are, so a load already in flight can't undo it.

## Panel look (DEV-760, DEV-778)

The panel is a card over the window's own tint and grain (`BrowserChromeBackground` with `BrowserTheme.fill` on top). Inside it is quiet and tactile (`ChatStudioPanel.swift`). Every header button is AppUI's glassy squircle (`ArxRaisedButtonStyle` since DEV-797: a translucent fill, a lighter top rim and a soft shadow; hover lightens it, press darkens it), and related actions share one squircle (`ArxRaisedGroup`). The header is a squircle list button for Your Chats, a centered title tile with the provider's mark (`ChatProviderMark`, ✳︎ for Claude) and model under the title, a pin tile that unpins while the panel shows a pinned chat, and ⋯ and × together as equal square items (`ArxRaisedButtonStyle`'s `isSquare`) with the same glyph weight. The header, Your Chats' title row and search, and chat info's header pin over their scroll views with AppUI's `arxScrollBar(background: nil)`, so the transcript and lists scroll under them and blur and dim out softly beneath, with no line (DEV-806); hover and press light a squircle inset inside each tile.

The person's messages sit on raised cards at the trailing side; answers are plain text (`ChatMarkdownView`) with the browser's work in a pale accent chip (`ChatStudioTools`) and "Thinking…" under a reply being written (`ChatProgress`). Answers are Markdown (DEV-998): `ChatMarkdown` reads them with Foundation's GitHub-flavored parser (`AttributedString(markdown:)` with full syntax) and builds blocks from each run's `PresentationIntent`; `ChatMarkdownView` draws headings, emphasis, inline code, strikethrough, web links (others stay text; images show their description and are never loaded), nested and task lists, quotes, code blocks with their language and a copy button, rules, and tables with a header row and each column's alignment. A table wider than the panel scrolls sideways, cells wrapping past `ChatMarkdownStyle.cellWidth`, so its columns stay aligned. While a reply is being written, its tail is drawn as it will settle: open `**`, `~~` and `` ` `` are closed, innermost first, each closer kept only when the parser then shows fewer marks as text (DEV-1031: `**bold `co` and `~~strike **bold` settle with both spans, and `2 ** 3` gets no closer), and a table waits for its delimiter row. A row of empty cells, which the parser reports no text for, counts in a table when the parser puts a mark in its first cell into that table, whatever its outer pipes and indentation (DEV-1031); one extra read of the answer, with every such row marked, serves all its tables. An answer up to `ChatMarkdownView.synchronousLength` characters is read while it's drawn; a longer one is read off the main actor by `ChatMarkdownReader`, which finishes every read and then reads only the newest text, so a long streaming answer keeps updating without holding up the browser, and its text shows until the first read. The copy button under an answer (shown on hover, and a VoiceOver action) copies its Markdown source; selecting text copies what's drawn. Failures, usage warnings, the browser tools request and a temporary chat's note follow the transcript (`ChatNotes`, drawn as raised `ChatNote` cards).

A new chat's body stays empty down to Suggestions by the composer and Recent Chats. It lists up to three `ChatSuggestion`s, the first in the accent with ›, built from the window's current tab (`ChatAttachable.currentID`): its title, or its site when it has none, and its host. Pages off the web offer none. `ui.suggestionTapped` attaches that tab and sends the prompt, so a page reaches the assistant only when the person picks a suggestion about it. On a surface the app places, the tap first goes up as `delegate.suggestionTapped`: the app answers with `event.suggestionResolved`, the same request about the page the surface stands for at that moment (a window's focused pane, or a pinned chat's own tab), so a split view never summarizes a pane the person left (DEV-835).

The composer is a raised card, see-through over a material: in a chat with messages it floats over the transcript, which scrolls and overscrolls under it and stays visible through it (`arxScrollBar`'s footer, DEV-826); a new chat keeps it below the suggestions. It holds attachment chips (a tab's favicon through AppUI's `BrowserSiteIcon`, an image's thumbnail, a file's icon and name, each with ×), the draft ("Message the assistant…", then "Ask a follow-up…"), + and the model in its own tile, and send or Stop. The draft is `ChatComposerTextView`, an `NSTextView` that grows with its text up to 200 points and then scrolls (DEV-798). ⌘Return always sends and Shift-Return (or Option-Return) always starts a line; plain Return follows `ChatReturnKeyBehavior` (Send, New line, Send one-liners), an app-wide `@Shared(.chatReturnKey)` set in Settings › Assistant › Composer. Paste attaches copied files and images and pastes anything with text as text; the text view takes only text drags, so files fall through to the panel's drop target, which outlines the composer while they hover. + opens a search-first menu with Files…, Capture Visible Area and Capture Area… (when `ChatPlacement.capture` is set), then This Tab, Folders and Tabs under small headings, tabs with their favicons. Before the first message a line names the plan the chat uses. The transcript and the composer are capped at `ChatMetrics.transcriptMaxWidth` and `composerMaxWidth` (720 points) and centered, so a wide chat tab stays readable. Suggestion and recent-chat rows always show their › in a fixed column at the trailing edge.

Your Chats lists chats by Today, Previous 7 Days, Previous 30 Days and then by month (`ChatTimelineSection`), each with a page-like thumbnail, the title over the provider and latest answer, and the time on the right. The header has squircle ‹ and + buttons, and All, Unread and Archived are AppUI's `ArxSegmentedControl` (`ChatListFilter`): the chosen one sits in a darker inset squircle, and resting on a segment shows its name in a small tooltip under it, so the header row sits above the glassy search field under it (DEV-797).

Chat info (DEV-799) has a header row of AppUI's raised square `ArxHeaderIconButton`s (‹ and ✕) around the bar title, laid out with `ArxHeaderBarMetrics` but without `ArxHeaderBar`'s ⌘[ and Escape shortcuts, which belong to the page beside the panel. Under it are the face (`ChatAvatar`, drawn from AppUI's shared `ArxFace`, the same eyes and smile as `ProfileSmiley`), the chat's title, its provider and start, Pin, Copy Answer and Archive as equal `.arxRaised` tiles, and a `SettingsSection` of provider, start, message count and retention (Pinned, Temporary or Archived) with the plan or expiry note as its footer.

`ChatPanelParts.swift` holds the pieces with behavior: `ChatScrollingTranscript`, `ChatNotes`, `ChatComposerField`, `ChatModelPicker`, `ChatActionsButton`, the list's filters and sections. Snapshots: `ARX_DESIGN_SNAPSHOTS=<dir> swift test --filter ChatPanelSnapshotTests` writes the panel in light and dark with a new chat, a short answer, a long one with tool activity, a failure, Your Chats, each placement (panel, pinned panel, chat tab), and the composer with one line, several lines, attachments, and in a wide chat tab.
