# OnboardingFeature

The paged onboarding window. One window shows one page at a time over a footer with Back, page dots, Skip and Continue (also on Return). It never reads or writes BrowserOrganization, profiles or browser sessions itself.

`OnboardingFlow.steps` is the ordered list of pages: welcome, tour, make it yours (`migration`), connect your agent (`connectAgent`), outside agents and default browser. `connectAgent` is listed only when `AgentProviders` ships at least one provider and `isEnabled` allows agents in this run, so test, smoke and headless runs never show it; `steps(includesConnectAgent:)` builds either list. `steps(offersICloud:)` adds "Sync with iCloud" (`iCloud`) right after the welcome page (DEV-1215); AppFeature passes `offersICloud` to `State.init` only while the first launch's Default profile is held back for it and sync can run, so Settings, test, smoke and headless runs never list it. `OnboardingFlow.page(for:)` builds each step's page, so adding or replacing one is a change to this file and a new child feature. Every step has its own page now; `OnboardingPlaceholder` remains for a future step without one.

Each page is a child feature scoped from `OnboardingFeature.Page`:

- `OnboardingWelcome`: the animated Arx app logo, the "arx" wordmark at its heaviest weight, a tagline and Get Started (also on Return). Get Started records `.welcome` and moves on. The footer offers Skip Setup, which goes straight to the hand-off without recording anything.
- `OnboardingICloud`: "Your Arx on every Mac" (DEV-1215), through `WorkspaceSyncClient`. When the page appears it checks the iCloud account (`accountIsAvailable`); without one it steps aside the way the person was going, reporting `unavailable`. When sync is on already (`statusUpdates`), the step's join started before a relaunch, and the page resumes syncing instead of offering Not now. The footer offers Not now and Sync with iCloud, which runs `joinFromOnboarding(true)`: sync turns on and each category that's on fetches once, and the page's line says which one it's on. A `finished` result with a workspace is `adopted` (with the space any Mac used last), one without is `empty`. After `OnboardingICloud.patience` (20 seconds), or when iCloud can't be reached or a fetch fails, the footer offers Continue without waiting (`continuedWithoutWaiting`: sync goes on, and AppFeature keeps waiting for iCloud's answer in the background), and after a failure Try again, which also starts a category that didn't start. Leaving the page undecided is Not now, or Continue without waiting once it started syncing; leaving cancels the account check, the page's wait and its timer, never sync itself. The flow keeps the outcome (`iCloudResolution`), reports it with `delegate(.iCloudResolved(_:))`, and records `.iCloud` for `adopted`, `empty` and `continuedWithoutWaiting`; going back shows what happened instead of asking again. AppFeature adopts iCloud's workspace or lets Default sync. The view is AppUI's `OnboardingICloudPage`.
- `OnboardingTour`: five pages, Peek, Split View, the command bar, chats and Little Arx (`OnboardingTour.Page`), each with a headline, one line and a looping demo. The state is only the visible page. Continue (Return) shows the next tour page and Back the previous one, both sliding like any page; Continue on the last tour page records `.tour` and moves on, and Back from the step after the tour lands on its last page. The footer's Skip Tour leaves every tour page without recording anything. Page dots count each tour page (`OnboardingFeature.State.progress`), and VoiceOver announces each tour page's headline. The view is AppUI's `OnboardingTourPage`, whose demo plays on its own `TimelineView` (see AppUI's README): no frame goes through the store, and the demos make no engine or network calls.
- `OnboardingImport`: "Make it yours", a one-page import summary over MigrationAssistant. When the page appears it discovers browsers once, lists browsers that aren't offered as unavailable (none while unchecked sources are on, the default), and preselects the system default browser when Arx can read it, otherwise the one used most recently (`preferredSource`). It inspects every category of the chosen browser once per `Choice` (browser and Keep its spaces) and caches the preview, so switching categories never reads again and switching back reuses it; choosing a browser again retries a failed inspection. Keep its spaces on sends the browser's spaces into new profiles like its own (`defaultRoute = .newProfile`); off, everything goes into the current space. Categories the browser lacks are listed as not yet available with a reason. For browsers, Passwords and sign-ins (DEV-842) is a row with Set Up… (`ui(.setUpPasswords)`), which opens Customize with the page's choices and the kind already on, since it needs macOS's prompt explained and its own choices; for Arx files it's listed as not available. The footer offers Start Fresh (Skip, records nothing) and "Bring from <browser>" (Return), which plans only the switched-on categories with something to bring and runs it inline; progress is throttled to ten updates a second (`OnboardingImportProgressThrottle`), Cancel asks the service to stop at the next category and keeps consuming until the cancelled report arrives, and a changed source is read again. Partial, failed and cancelled runs show a compact result with Try Again, which reruns the same idempotent plan. For Arc, History and Extensions are switches like the others (DEV-845); the Extensions row says how many come from the Chrome Web Store. After a run that wasn't cancelled, the page installs those through MigrationAssistantFeature's `ExtensionImportFeature`, showing `ExtensionImportReview` for each (with Install All, which installs the rest without their reviews) and a progress line, then how many were installed and how many weren't; failures never wait for a press. The page can't close meanwhile, and Skip All ends it. Only a `completed` run records `.migration`, once the extensions are done, and the page stays for Continue. When Customize ran the import, its extension results come back with it and nothing installs twice. Customize… opens MigrationAssistantFeature at its selection with the same browser and categories, and Keep its spaces as new profiles in its profile mapping; its result comes back to the page. `ui(.importData)` (Settings' Import) opens the assistant from the start. The footer hides while the assistant shows its own controls. Safari needs Full Disk Access (DEV-840): selecting it checks `FullDiskAccessClient` instead of inspecting, and while access is missing the page shows the Full Disk Access card (why, and Open System Settings) in place of the categories. `event(.applicationBecameActive)`, forwarded by AppFeature while the page shows, checks again and reads Safari once access is granted; while the assistant is open the event goes to it, and its answer comes back when it closes. The view is AppUI's `OnboardingImportSummaryPage`, built from `OnboardingImport.State.summary`; browser icons come from `NSWorkspace` by bundle identifier and nothing in the other browser is opened. A new inspection cancels the previous one synchronously in reducer order (DEV-606); a late older one is for another choice and is ignored. When the flow adopted iCloud's workspace (`workspaceCameFromICloud`, DEV-1215) the card says the profiles and spaces came from iCloud, and the page offers only what iCloud doesn't sync: `MigrationCategory.outsideICloud` (open tabs, History and Extensions) and Passwords and sign-ins through Set Up…, into the current space, without Keep its spaces. Its parent passes `existingData` (DEV-833) on to the full assistant, which offers Clear Arx data first only with it; once Arx is cleared, the page and the flow take the fresh destination and drop `existingData`.
- `OnboardingConnectAgent`: "Connect your agent" (DEV-700). One row per provider in `AgentProviders` (Claude through Claude Code, ChatGPT through Codex), each with its status: Signed in, Not set up (not installed, signed out, or signed in with an API key or another method billed separately), Needs a paid plan (a provider that reports a free plan) or Not available right now (agents are off in this run). The page reads each provider's `account()` when it appears, on Check Again and on `event(.applicationBecameActive)`, since people sign in with the provider's own tool in Terminal. It never starts a sign-in, changes one or sends a turn. A signed-in row offers Connect, and the footer offers Later (Skip, records nothing) and "Connect <provider>" for the first ready provider, otherwise Continue. Connect records `.connectAgent`, sends `delegate(.agentConnected(_:))` and moves on; AppFeature makes that provider every ordinary profile's assistant. Leaving the page cancels its check. The page has no demo yet.
- `OutsideAgents` (from OutsideAgentsFeature): "Work with outside agents", the same component Settings shows in the Local assistants sheet, inside the page layout and a scroll view. Install, Update and Uninstall the `arx` command, the MCP switch (off by default, owned by AppFeature) with what a connected agent may do, and each agent app with Add… or Copy Setup. Adding Arx to an app records `.outsideAgents`; the footer's Skip and Continue move on without recording. Closing and leaving the page are refused while the command is being installed or an app's file written, and leaving cancels its checks.
- `OnboardingDefaultBrowser`: "Links from other apps", through `DefaultBrowserClient`. The page reads the default when it appears and again on `event(.applicationBecameActive)`. While another browser is the default, the footer offers Not Now (Skip, which records nothing) and Make Default (Return). Make Default asks macOS; `accepted` or `alreadyDefault` records `.defaultBrowser` and moves on, `declined` stays on the page and says Arx isn't the default yet. When the page finds Arx already is the default it records the step, says so, and the footer offers only Continue. Closing and leaving the page are refused while macOS's confirmation may be showing, and leaving cancels its status check.
- `OnboardingPlaceholder`: a step whose page doesn't exist yet. It never records its step. No step uses it today.

Actions follow the `ui`/`event`/`delegate`/`observation` domains. Continue and Skip move on without recording a step; a page records its step itself when its work actually finishes, through `delegate(.stepCompleted)`. Back returns to the previous page. After the last page the flow sends `delegate(.handOff(_:))` with the space an import created, reported by the parent through `event(.importCreatedSpace)`. `ui(.dismiss)` (close button, Escape, Command-W) sends `delegate(.dismissed)` and cancels the import page's discovery or inspection. `canClose` is false while an import may be committing, and closing and moving on are refused until it ends.

`State.init(mode:completedSteps:…)` opens at the first step of the mode that isn't in `completedSteps`, or at the first step when all have finished. `Mode.flow` is the whole flow; `Mode.step(_:)` is one step opened from Settings, without Back or page dots, and finishing it closes the window instead of handing off.

AppFeature owns presentation, persistence and the hand-off to the main window. OnboardingView draws the window's content: it springs in on appear and slides pages in the direction of travel, and under Reduce Motion both become crossfades. These animations are view-local and keyed on values that change once per page. Page headings are accessibility headers, the progress reads as "Step 2 of 5", and VoiceOver announces each new page's headline. The visual parts (welcome page, page layout, progress and footer) live in AppUI's `Onboarding` folder; strings use AppUI's catalog (`onboarding.*` keys).
