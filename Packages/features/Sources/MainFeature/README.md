# MainFeature

Composes sidebar, command entry and a single viewer; routes typed intents to browser sessions. `MainPageStaging` gets the page that is about to be shown drawing ahead of time: a sidebar tab a left mouse down lands on (the row selects it when the click ends), or the space a swipe uncovers. A hover alone stages nothing, because a staged page is shown to Chromium: it would unfreeze, run its timers at full rate and take a place among the recently used tabs protected from freezing (DEV-941). The mouse-down monitor is installed only while a sidebar tab is hovered, and ignores Shift-, Command- and Control-clicks and other windows. While the sidebar settles on a swiped-to space it shows that space's page over the card until the selection lands and the card takes the page, so a switch never shows an empty card. It works outside SwiftUI and stages nothing while the viewer is split. URL-field clicks use an anchored editor; Cmd-T favors browsing candidates, while Cmd-K and Cmd-L open command-first entry. History suggestions use the active page's live navigation history and are restricted to the selected profile.

Requires macOS 27 and Swift 6.4. Features use core, services, AppUI and lower-level features; services never import features. Verify with `make test-all`.

All spaces appear in persisted order across profiles, both in the sidebar pager and space buttons. Each page gets only its own profile’s favorites. The chrome passes the pager space summaries, and each mounted space's page reads its own tabs from the store, so a change in one space renders no other (DEV-937). The page's navigation is read only where it shows: the toolbar's buttons, the site menu (`MainSiteMenuEnvironment`) and the Library button's menu, whose commands follow the page, each in a view of its own, so the active tab's loads render neither the chrome nor any space's sidebar; the footer reads its spaces in `MainLeaf` too; the Library's Spaces page reads every space in `MainLeaf`, apart from the chrome. Space navigation changes the local browsing context; there is no global profile filter. A space's context menu opens Appearance… in a floating panel on its space button (`SpaceAppearancePanel`), which can be dragged by its handle and keeps its place until it closes (`movableFloatingPanel`, DEV-1286): tint, grain and theme, each inherited from the profile until chosen, and Use Profile Appearance to clear them. While a slider is dragged, the window's chrome previews the value from view state only; one organization change is sent on release. MainView passes the selected space as the chrome's transition key, so switching to a space with a different appearance crossfades it. Reconciliation preserves each window’s selection, maps it to fresh tab IDs after profile reassignment, and clears stale organization undo snapshots. MainView gives the pager a `SidebarSpaceCreation` outside private windows (DEV-1109): the organization's profiles with their appearances, and `SidebarFeature.UI.createSpace(name:profileID:appearance:)`, which appends the space after the others with its trimmed name, profile and theme (none when left as the profile's), selects it and closes the Library; a blank name or a profile that's gone makes nothing.

`ProfileTabTransfer` moves ordered tab/folder roots as one tree edit. Same-profile moves retain native identities. Every cross-profile path captures its sources before explicit identity-change confirmation, stages replacements for live source sessions, obtains their close approvals, and commits only against unchanged selection/tree and source pages: the same page, profile, document, address and history (`moveIdentity`; a page without a document stamp, such as a WebKit page, keeps its revision too, so a same-address reload counts). A color, title or visibility a page reports meanwhile, such as a just-loaded page's site color on Undo, doesn't make it stale (TabMoveSmoke). A deny-by-default host authorization rejects private, shared, borrowed, closed, or quitting sources. Dormant saved pages remain unloaded, and a missing snapshot for a presented page or a native URL newer than captured metadata rejects the request. Failed/stale work disposes only staged sessions. Cross-profile Undo uses the same approval path and fresh identities; it restores organization, not transient page state. Ordinary navigation and disclosure do not invalidate Undo, while structural edits do. Moving a whole space to another profile (the sidebar's profile capsule, or a space's Set Profile menu) plans it with `BrowserOrganization.movingSpace` on top of the same tree move, so it gets the same confirmation, staging, rollback and Undo; the profile's Favorites stay behind, and private windows cannot start it. With `ARX_PAGE_PIP_SPACES` (DEV-1184) the confirmation is AppUI's `ProfileMoveConfirmation` as a sheet (`TabMoveRequest.profileMoveConfirmation`: the tab, the number of tabs, or the whole space, and the destination's profile), saying the pages reload in that profile without their sign-ins; Escape cancels (`ui.cancelProfileMove`). Off, it's the system dialog with the older wording.

Committed moves, Undo and archive restoration explicitly follow the selected page into a destination's stored presentation. Synchronization requests this selection only while it still matches the current sidebar selection, so queued completion cannot replace a later selection. Ordinary space switches continue to restore their saved active pane.

The Move Items picker exposes searchable full profile/space/folder paths, keyboard selection and VoiceOver actions. Command-click or Shift-Space marks items in selection order; Command-Shift-M opens their picker from a focused row. Drag payloads carry the complete ordered selection; folders include descendants once, and invalid destinations/cycles are rejected atomically. Dragging pins into open tabs cannot implicitly unpin them.

FolderLifecycle obtains every descendant page’s close approval before deleting one saved subtree. A refusal leaves all metadata and sessions intact; structural changes during approval reject the stale deletion. Successful deletion is one undoable edit. Undo restores saved metadata and the selected page, while native navigation history is intentionally not serialized. Folder opening visits immediate pins by default, includes descendants only explicitly, and reuses the engine’s existing identities without issuing navigation commands.
`TabArchiving` composes the profile-scoped TabArchiveFeature. It records unpinned closes only after native close approval/completion, rejects stale location approvals, restores groups through fresh native sessions, and commits only against an unchanged workspace. Failed or conflicting restores close only their new sessions and retain the archive. Sidebar multiselection and command availability share the same ordered unpinned-tab resolution. Cross-profile restoration captures and revalidates the explicitly confirmed destination profile before staging fresh sessions. MainView exposes the archive and explicit archive/reopen actions; application command routing can invoke the matching MainFeature UI actions.

`sidebar.message` (a changed workspace, an invalid tab move, a split refusal) shows as AppUI's `ArxToast` at the window's top-right corner over the page (`SidebarNoticeToast`, DEV-777), below the copy-link toast when both show (`arxToastStackOffset`). Every write of `message`, even the same text again, makes a new `SidebarNotice` with a new `id`. `SidebarNotices` times it like the copy-link toast: the toast sends `ui.noticeShown(id)` for each notice, `event.noticeExpired(id)` clears it 2.5 s later, and `ui.noticeHovered` holds it while the pointer is over it, then gives it 1.5 s more. A notice that replaces one under the pointer keeps the hover; `ui.noticeRemoved(id)` ends it when the toast leaves. An expiry for an older notice never clears a newer one. The timer is keyed by the window's `id`, so the main window and other windows never cancel each other's. Each timer cancels the window's earlier one synchronously in reducer order rather than with `cancelInFlight`, which cancels only once the task registers off the main actor and could let an older timer cancel the newer one (DEV-606); an older timer that registers late expires only its own notice.

Split View keeps sidebar tab ownership intact, validates the command bar’s originating pane, and removes placements for tabs deleted or moved out of the active space. Existing-tab split requests go through AppFeature so a tab already hosted in another window focuses its owner.

CommandBarContext captures the source pane/tab generation, space and profile at presentation. Execution requires that source plus the result's displayed destination identity to remain valid; moved tabs/folders and reassigned spaces cannot execute under a stale label. Dismissal clears the context, and a presentation sequence rejects queued results from an older bar without invalidating a newer one. Focus changes between panes and query edits retain the original source.

`TabPresentationReset` captures pane generations and saved layouts before a saved page unloads. Application reset completion broadcasts presentation cleanup without closing the session again. MainFeature clears unchanged selections and saved placements, and ViewerFeature rechecks native absence and pane generation before clearing the visible page. A newly opened session or changed pane survives a late completion.

Downloads appears in the space switcher as an application utility when the native service is ready; opening it preserves the selected space, panes and sessions.


Command-bar history comes from ProfileHistory’s per-profile snapshots. It stays current-profile only, deduplicates against open tabs, and includes the destination profile/space label. Persistent selections validate their profile, space, entry ID and exact URL at execution. Private windows use only transient page history; already-presented result arrays stay frozen as new visits arrive.

Command-bar execution rejects a closing host even for raw URL or organization results. Main-window closure clears its captured context synchronously before suspending the viewer, so a queued result cannot execute while the hidden window still has its previous page generation.

Accepted registry results retain their captured command-bar source through App dispatch. The final local dispatch checks that source and current command availability, then resolves the existing action synchronously, preserving explicit pane/tab targeting. Closing or dismissing a presented bar advances its sequence so an already-accepted deferred action cannot revive afterward.

Application automation reuses `archiveClosedTab`, `SidebarFeature.State.commitTabClose`, and captured reset-placement cleanup after native close succeeds. `pendingTabCloses` includes token-owned automation requests; ordinary UI insert/remove calls cannot acquire or clear those tokens. Removing a token clears only that operation's guard and preserves unrelated UI closes.

Creating an empty split pane presents the new-tab command bar centered over it, and dismissing that bar closes the pane if it is still empty. `splitTabIDs` projects the split's members to the sidebar, which highlights them together and joins adjacent rows. Selecting a member focuses its pane.

`SplitGroups` owns Split View groups (DEV-692): dropping sidebar tabs onto an open tab or a group's row joins them (up to four, refused when the window can't keep every pane at 280 pt), dropping a tab on a page edge inserts a pane on that side (AppUI's `SplitDropZones` cuts the page along its diagonals into a triangle per edge, `SplitDropEdge(point:size:)`, and highlights the half the new pane takes; DEV-793), a chat tab that Open in Tab put in place of a page and that still shows alone splits with that page when dropped on its own page (`chatTabOpenedOver`), a tab a press selected (`SidebarAction.selectOnPress`) and then dragged into the page joins what the page showed before the press, as the drop would have before the page switched (`pressSelection`, DEV-994; a click, another selection, a space change, a sidebar move, a tear-off or any drag after the press's own (`ui.tabDragStarted`) ends it), and the group row's menu actions (separate, separate all, add tab, convert orientation, rename, icon, duplicate, Tab Options) edit `BrowserOrganization.splits`. Any tab can join (DEV-1006). A split's tabs share one list, the space's open tabs, its Pinned or one folder, so a tab of another list or space of the profile first moves into the split's list beside it through SidebarFeature's `gatherForSplit`, in the same undo step: dropped onto an open tab it becomes open, onto a pinned tab it's pinned, and onto a tab in a folder it goes into the folder. A Favorite of the profile joins from the grid and stays there (`shownSplitTabs` counts it). That covers a sidebar drop, a page drop (`paneAnchor` picks the pane tab it joins), a press's drag, Add to Split View (`addPane`, the app's answer to `requestSplit` once the tab enters a new pane here, not when another window already shows it), a split's empty pane (`present` or the command bar, `gatherTabForPane`, before the pane takes the tab, so it loads as it will be) and `ui.openSplit`, where the others join the first tab's list. Closing a pane only takes its tab out of the group: a pinned tab isn't reset. Duplicate puts the copies after the group in its list, pinned in Pinned or a folder. Selecting a member shows its whole group through `ViewerFeature`'s `layout`; selecting another tab while a group is shown shows that tab alone and leaves the group in the sidebar. The group follows the panes only when a layout change ends (pane added or closed, swap, orientation, resize end, equalize), never during a divider drag or drop hover, and not while a layout's panes are still waiting for their tabs.

Each window owns its sidebar width. Finishing a resize saves it with the window's presentation through AppFeature, and new windows start from the most recently saved width. Private windows inherit a width but never save one.

The chat panel (DEV-720) sits right of the page when `isChatOpen`. The window owns only that flag: the Chats command and the panel's close button toggle it, text + Tab from the command bar opens it and sends `delegate.startChat` with the window's profile, and AppFeature supplies the panel view because it owns each profile's chats. Private windows never open it.

DEV-761: `MainChatPanelRow` lays out the page and the panel and makes the panel's leading edge a resize handle; `ui.chatWidthCommitted` clamps to `BrowserChatWidth` and saves `chatWidth` with the window's presentation (double-click resets it). `chatPins` maps a tab to the chat pinned to it (`ui.chatPinned`, `ui.chatUnpinned`), is saved with the presentation as `BrowserChatPin`s, and loses a pin when its tab closes. `ui.openChatTab` adds a chat tab (`ChatTabAddress`, `arx://chat/<id>`) after the current tab, and `retargetChatTab` keeps its address and title on its chat. The Pin Chat to This Tab and Open Chat in Tab commands become `delegate(.chatPlacement)`, which the app carries out with the chat the window shows.

SiteMenuFeature (DEV-633) backs the URL bar's site menu. Opening it reads the active pane's page and profile (`siteMenuContext`), the profile's enabled extensions through BrowserExtensionsClient, and its site settings through BrowserEngineClient, which it keeps current while open. Permission rows and Reset zoom apply `SiteSettingsEdit`s for the page's origin or host only; a managed setting can't change. Clear Cache and Clear Cookies ask the engine for the site's scope (its registrable domain) first and clear only after the person confirms; closing the menu drops an unanswered question but lets a clear finish. Private windows get Share and Capture only. Share, Manage Extensions and All Site Settings leave as `shareURL`, `manageExtensions` and `openSiteSettings` delegates; an extension's tile runs the extension's action for the page through BrowserEngineClient (`runExtension`, ABI48, DEV-828), so its popup opens at the tile, only while the menu's tab is still the one shown. The engine call runs in an effect with the click's tab and point, which closing the menu doesn't cancel; when the engine can't run it (an older engine, a page that needs a reload, a side panel) the tile leaves as `showExtension`, as before. Its menu's Options leaves as `openExtensionOptions` and Manage Extensions as `showExtension` (DEV-801); capture sends the capture commands; Add Extension opens the Chrome Web Store in a new tab of the current space. MainView puts the menu in the sidebar's environment. Its `host` (`SiteMenu.Host`, DEV-1257) is the window it opens in: a main window's by default, Little Arx's or Page PiP's for AppFeature's floating menus; an action from an item that window leaves out does nothing, and Translate's language and Hide Element's filters aren't read where they don't show. Its scope read, settings read and settings observation each cancel the one they replace synchronously in reducer order (DEV-606); a late older one reports another request or profile and is ignored.

The site menu's Block ads and trackers switch (DEV-884) shows while Settings › General › Content blocking is on (it reads the shared general preferences) and the engine lists the Ads site setting; it applies `setContentBlocking` for the page's origin. An extension tile's menu has Turn Off and Remove… for extensions the person may change (DEV-891), and Allow in Private Windows for one whose engine offers the switch (DEV-889). Remove… asks under the tiles first; closing the menu drops the question. All of them read the profile's inventory again, so the change is checked against what the engine says now, then reload the tiles and leave as `extensionsChanged`, which AppFeature turns into a refresh of Settings › Extensions.

Hidden Elements (DEV-1019): while the `ARX_HIDE_ELEMENT` feature flag is on (`SiteMenuFeature.State.hideElementEnabled`, which the app sets; it also gates the window's `canHideElements`), on an ordinary http(s) page with content blocking on and an engine that hides elements, opening the menu reads the profile's hidden elements (`browserEngine.hiddenElements`) and keeps the filters for the page's site and its parent domains (an IPv6 site in brackets, as uBlock names it). Show takes only a listed filter out of My filters and, once the engine accepts, drops the row, waits until uBlock lists the site's elements without it (its filters have reloaded; looking every 150 ms on the `continuousClock` dependency, `showPolls` times, about five seconds), then reloads that tab's page itself (`browserEngine.command(tabID, .reload)`), even if the window has moved on, so the element comes back; not if the tab has gone on to another document meanwhile (its `documentRevision` changed). Hide Element… sends `.command(.hideElement)`; it's offered only while the site has blocking on (`canHideElement`), since uBlock doesn't apply filters on a trusted site.

The developer header (DEV-733) shows over local pages while `showsDeveloperHeader` is on (developer mode and its setting, kept by AppFeature). `ui(.developerHeader(action, paneID))` makes the pane active, then copies its address, captures it, toggles its DevTools or opens Console, Network or Inspect Element, or adds an empty pane on a side with `ViewerFeature.splitEmpty`, checking room in that side's orientation.

A tab row's speaker and menu (DEV-800) send `SidebarAction.setMuted` and `.setVolume`. MainView passes them straight to the sidebar without switching spaces, and MainFeature turns them into `delegate.setTabMuted` and `delegate.setTabVolume` for the app, which owns the tabs' audio.

`WindowUndo` (DEV-1030): after the sidebar takes a step back, the window shows the step's space again with `ARX_WINDOW_UNDO` (`spaceSelected`) and tells the app (`delegate.undid`); `appendUndo`, `dropUndo`, `dropWindowMoves` and `dropStepsMaking` add and remove steps from elsewhere. Reconciling another window's or an agent's change, ⇧⌘T, archiving and a tear-off end the open step (`sealUndo`) instead of clearing history. An unpinned tab closed here (`archiveClosedTab`) is a step that brings it back while Recently Closed holds it; an agent's close is the app's to record. Without the flag these clear the history and a close isn't a step, as before.

`TabTearOff` (DEV-793): a single open tab dropped from the sidebar outside every Arx window (AppUI's `SidebarTabTearOff`, `ui.dropTabOutsideWindows`) asks the app with `delegate.requestTearOff`; the app answers with `tearOff` unless a Peek, a pending tear-off or a Little Arx window holds the tab. The tab then leaves the window's space without closing its page: it is removed from the organization and from `knownTabIDs` before `synchronize`, the window's open ⌘Z step ends there, so no step brings it back while Little Arx shows it (a step only puts back tabs it removed; without `ARX_WINDOW_UNDO` the history clears, DEV-1030), and `delegate.moveToLittleArx` hands the tab to the app. Saved tabs, Favorites, private windows and tabs being closed or moved stay.

The Library's History page (DEV-817) is `HistoryFeature`, scoped through `historyPage`: a computed state built from `browsingHistory` and `unreadableHistory` for the current space's profile, with only its search and pending deletion stored here (`historyQuery`, `historyDeletion`), so it updates live whatever changes the history. Its open delegate opens a new tab; its removals become the `removeHistory` delegate the command bar's Delete from History sends too. Show History (⌘Y) opens the Library on it. Private windows have no History page.

`TabBulkActions` (DEV-883) carries out the tab menu's bulk actions on the current space's tabs, in sidebar order. Close Other Tabs (every open tab outside the clicked row, or outside its selection), Close Tabs Below (the open tabs after the row or its Split View group), Close N Tabs and Archive N Tabs ask every page first, like Archive Selected Tab, then close them together: open tabs go to the archive as one group (a private window just removes them), and Close N Tabs also unloads pinned tabs and Favorites back to their saved page, through the same `resetTab` the single close sends, so the app clears them from other windows and Peek too. Each commits as one organization edit with the earlier organization pushed onto the undo stack, so one Undo Organization Change brings every tab back. Duplicate N Tabs and Pin or Unpin N Tabs are single `sidebar.edit`s. Move to Window sends `delegate.moveTabsToWindow` with the tabs and the window, or none for Open in New Window. Only once the app allows it does `releaseTabsForWindowMove` close the split panes that show a leaving tab (a split keeps one) and select a neighbouring tab if the selected one leaves, so a refused move changes nothing here; the app then sends `completeWindowMove`, which moves them into the other window's space as they are, pinned or open, as one undo. With independent windows or `ARX_WINDOW_UNDO` that undo is an `OrganizationUndo` from the organization before the move, whose `windowMove` names the tabs handed over and both windows; taking it back sends `delegate.undid`, and the app gives this window back its open tabs, any window that has them now lets them go, pinned ones too, and the tab this window showed before shows again (DEV-1156). With `ARX_WINDOW_UNDO` the step goes to the other window too (`delegate.shareUndo`), and either can take it back (DEV-1030).

DEV-878: Duplicate Tab, Duplicate N Tabs and reopening from the archive call `BrowserEngineClient.cloneNavigation` before the copy opens, so its first page takes the tab's back/forward history. Undoing a bulk close brings back the same tabs, whose saved history the engine restores itself.

DEV-1325: every tab MainFeature makes out of another tab goes through `BrowserOrganization.placeOpenedTab(_:inSpaceAt:opener:)`: Open in New Tab, Duplicate Tab from a pane (`paneCommand(.duplicateTab, _)`, which ⌘D, the Tab menu and the command bar send) and from the sidebar (`ui.duplicateTab`, Duplicate N Tabs), and Open Link in Split (`splitURL`). The tab goes directly after its source, every time, or first among the open tabs for a bookmark's: a Favorite's or a pinned tab's, in a folder or not.

`takePageNavigation(tab, navigation)` keeps a tab's URL and title from its settled page when no pane shows it, with the same rules as a pane's report: loading and failed states change nothing, an empty title keeps the last one, and an unchanged page publishes nothing.

DEV-913: `openNewTab` places a new tab with `BrowserOrganization.placeNewTab` and the `newTabPlacement` setting, read through `@SharedReader(.newTabPlacement)`. DEV-1174: a tab the command bar opens, which is how the New Tab button, ⌘T and ⌘K open one, goes where `openedTabPlacement` says instead: Settings › General › New tabs open (`@SharedReader(.openedTabPlacement)`, at the top by default) while `newTabsAtTop` (the `ARX_NEW_TABS_AT_TOP` flag as Arx launched with it, `NewTabsAtTopFeatureFlag.atLaunch`, which Settings shows too) is on, else `newTabPlacement`. The tab is added in one `sidebar.edit`, so one Undo Organization Change closes it. `ui.openInNewTab`, which links, the site menu and other windows send, and chat tabs keep `newTabPlacement`.

DEV-906: MainView takes an optional `mediaPlayer` view from the app and shows it above the sidebar's footer.

The switch sends the Dark Page command, and the open menu follows the profile's sites.

`translationOffers` (DEV-996, behind `ARX_TRANSLATE`) holds the app's Translation Available offers by tab; the URL bar's environment gets the active pane's (`MainSiteMenuEnvironment`), and the popover's actions go to the app as a `pageTranslation` delegate for that tab.

The site menu's Reading Mode tile (DEV-1028) shows with the feature flag on, dimmed on a page reading mode can't read, and sends the `readingMode` command for the active pane. `MainSiteMenuEnvironment` also gives the address bar the active page's `readingModeIndicator` when the item's `urlBarPageButton` is reading mode, and `urlBarReservesPageButton` while it holds the button's room (DEV-1254); `readingModeEnabled` carries the flag into the window's commands.

Recent tabs (DEV-544, `ARX_RECENT_TAB_SWITCHER`, `RecentTabSwitcher.swift`): each window keeps `recentTabs`, the tabs it showed, most recent first, each with the space it was shown in (a Favorite goes back to that space; a pinned or open tab to its own). `RecentTabRecording`, after every other reducer, puts the tab the window shows at the front and drops closed tabs, from the list and from an open switcher; the window starts with its opening tab, so the first action changes nothing. `ui.tabSwitcher(.step)` freezes `recentTabSwitcherTabs` into `tabSwitcher` (the shown tab, the other recent tabs this window can still go to, then the space's never-shown tabs in the sidebar's order; not another window's open tabs, nor one closing) on the previous tab, or the oldest for a step back, and starts the beat (`MainFeature.tabSwitcherBeat`, 0.15 s, on the `continuousClock` dependency). `tabSwitcherBeat` shows it; a second step shows it at once. `commit` goes there as Switch to Tab does (`switchToRecentTab`), `choose` is a click, and `cancel` leaves the selection and the order alone. Listing loads nothing: rows only read the organization and `sidebar.unloadedTabs`, which `MainTabSwitcherHost` dims. With the flag off, no order is kept and the actions do nothing.

Back to the previous tab (DEV-1228, `ARX_RETURN_TO_PREVIOUS_TAB`, `PreviousTabSelection.swift`): the same recording keeps `lastShownRecentTab`, the tab the window shows or showed last, closed or not, and `previousRecentTab`, the one it showed before that. It's one tab back: once that tab closes there's none, rather than an older one, and a tab shown after a closed one has none. `recentTabs` is kept while either flag is on. The first reducer notes, before a close commits (`sidebar.event.closeApproved`, reset or not, and `event.bulkCloseFinished`), whether the window's selected tab is among the tabs leaving and the previous tab is still there, not among them, and both recorded in and now in this space (or a Favorite of its profile) (`leavingSelection`, which never outlives the action). `PreviousTabSelection`, just before `RecentTabRecording`, selects it as Switch to Tab does when the close cleared the selection and the window is still on that space. A previous tab in another space isn't gone back to, so closing a tab never changes the space. With the flag off, or nothing to go back to, the selection clears as before. Each window keeps its own; selecting a tab in another window changes nothing here.

Pin reset shake (DEV-1225): `TabBulkActions` counts each bulk reset with `SidebarFeature.State.noteReset`, as the sidebar does for one, and `MainView` hands `sidebar.resetPulses` to the pager as `sidebarResetPulses`.

DEV-1189: a command bar result that opens an `arx://settings/…` or `chrome://settings/…` address doesn't load a page. Translucent chrome (DEV-1286, `ARX_TRANSLUCENT_CHROME`): with the flag on for this launch, `MainView` draws the window's `BrowserChromeBackground(isTranslucent: true)` and passes `chromeIsTranslucent` to `BrowserSidebarLayout`, so the docked sidebar and the window around the page let the desktop through as the tint's intensity says. The page card, the chat panel and everything floating stay solid.
