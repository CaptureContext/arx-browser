# TabArchiveFeature

Profile-scoped search, selection, restoration requests and explicit deletion for Tab Archive. The feature depends on BrowserCore, AppUI localization resources, and the TCA wrapper; it does not own native pages, files or the full workspace.

`TabArchiveFeature` and `TabArchiveView` provide an accessible list, destination choices grouped by profile, explicit cross-profile account confirmation and a scoped clear confirmation. MainFeature's `TabArchiving` adapter obtains native close approval, closes sessions before recording entries, opens restored groups before committing them, and rolls back new sessions on failure or concurrent workspace edits. IntegrationFeatureTests cover the reducer and persistence boundaries.

Successful restoration activates the first restored tab in its destination. Previously visited spaces keep their stored split arrangement and neighboring page; the restored tab occupies the saved active pane. A newer selection made before queued synchronization is not overridden.

Only successful closes of ordinary unpinned tabs are archived. Private windows, temporary Little Arx sessions, pin/Favorite resets and folder deletion do not create entries. Archive Selected uses the sidebar’s selected unpinned rows in sidebar order, including mixed selections with saved items. A saved-only selection does not fall back to an unrelated active tab. Without a sidebar selection, the command targets its originating pane. Explicit batch archive obtains every close approval before closing anything and publishes group/order metadata only after close completion. Entries retain the last URL and title, original profile and space identity, closed time, and original tab identity; restoring creates fresh session identities in the chosen profile. Each attempt commits only against its unchanged source snapshot, so retries and concurrent windows cannot duplicate entries or close another attempt’s pages. No form state is kept; a tab restored in its own profile reopens with its back/forward history (DEV-878). Cross-profile restoration requires choosing a named destination profile and confirming that its accounts and cookies will be used. The captured destination includes both Space and profile identity; reassignment, removal or stale confirmation cannot silently change the account. Default Restore still requires the original profile. Restoration transfers URL/title metadata and provenance, not live sessions, page state, navigation history or old tab-scoped grants.

Archive records are stored in workspace format 4 with the same atomic-save/backup/retry semantics as organization metadata. Entries have no expiry or automatic cleanup. AppFeature's `TabAutoArchiving` archives regular tabs left unviewed for their profile's interval, six hours unless the profile chose otherwise (DEV-1326); an empty archive says so, with the interval, or that only closed tabs come here when the profile chose Never. Clear and delete affect only the presented profile, never live tabs or another profile's archive.
