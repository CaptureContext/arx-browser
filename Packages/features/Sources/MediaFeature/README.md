# MediaFeature

Testable ArxPiP orchestration, composed by AppMedia with the runtime-gated Media page in the Library and manual video PiP. The feature consumes BrowserMediaClient state for an explicit profile/privacy scope. It requests supported play/pause and manual video PiP actions, exposes typed failures, and emits stable Return-to-Tab identities for AppFeature to resolve through the current tab/window/space/pane owner. It creates no window, WebContents, navigation, stream or speculative playback state.

Snapshots are monotonic within an observation. Observation epochs reject old streams after scope changes, and source disappearance cancels queued commands. Observation and command effects never use `cancelInFlight`: every reset cancels them synchronously, and an older observation that registers late is cancelled by its first stale event instead of cancelling the current one. The native adapter must still revalidate at execution; reducer validation cannot close that asynchronous race. A pending Return-to-Tab only emits after successful exit while its exact source generation still exists.

Automatic PiP is on by default and can be turned off per profile and exact HTTP(S) origin. Two triggers owe a source an entry (`AutomaticEntry`, DEV-848), each recorded once, when it happens, and only for a non-private source that wasn't turned off and is playing video outside PiP at that moment:

- **Hidden**: a hidden-source event (another tab, space or pane took its place, or its window was hidden, minimised or covered). It asks for Chromium's automatic entry when the site advertises it, so a page's own `enterpictureinpicture` handler runs. After a failed request, or with no automatic action, it falls back to the manual entry Arx asks for on the browser's behalf. A source owes it only if it qualifies as it leaves view; one whose Picture in Picture Arx's own return is still folding back onto the page qualifies too (DEV-1213: the person came back to Arx and switched tabs at once), since it was playing as it left: its exit is in flight, or it finished while no snapshot has shown the source inline yet (`AutomaticEntry.landing`). It waits in `awaitingInline` for the snapshot that shows it on the page, then floats. If that exit fails, it still floats and is owed nothing more, so closing its Picture in Picture later doesn't float it again.
- **Deactivated**: `event(.applicationActivityChanged(isActive: false))`, which the host reports, while the source was last reported visible. Chromium's automatic route refuses a visible source, so this always takes the manual entry, and never replaces another video's PiP. Activation (reported when a browser window becomes key, so clicking ArxPiP itself doesn't count) drops entries not yet sent and closes the PiP of a source that floated this way and is still showing, when `closesOnReturn` is on (`returns`, kept until the exit can be sent: after a command in flight, or once the snapshot shows it floating). An entry already sent isn't cancelled, because Chromium quarantines a source whose entry is cancelled; it finishes and then returns. While Arx is inactive, a source becoming visible again keeps its PiP until activation. Once one video has floated this way, no other one replaces it, even before its snapshot arrives.

An owed entry waits for a free command slot instead of being dropped, and is retried up to `AutomaticEntry.maximumFailures` (3) times: one rejected as stale waits until a snapshot brings its source a newer revision (`staleRevisions`), other failures retry at once. Automatic failures never set `failure`. A video that starts playing after its tab was left isn't owed one. A manual request is independent of this setting. Repeated hidden events do not reopen a user-dismissed PiP until the source is visible again. Preferences are persisted through BrowserPreferences and the existing workspace save path. The Library's Media page exposes the per-origin toggle in a row's context menu when the native action is advertised, and always permits turning a site off. Private preferences cannot be enabled by this feature. Returning to a visible source or turning its site off cancels only a pending automatic request; late completions cannot revive it or show a stale failure. Manual entry remains independent.

Native supported paths and the required ABI/service contract are in [BrowserMediaClient](../../../services/Sources/BrowserMediaClient/README.md). The Library's Media page and the Media command are available only when the injected client reports availability; the default dependency remains unavailable, while explicit runtime composition provides live readiness. Closing the Library does not pause media or stop native Return-to-Tab observation. The source-supported window uses Chromium's existing video surface; a Little Arx panel does not establish PiP behavior. Verify with MediaFeatureTests and `make check`.

Native Return-to-Tab activations have their own stream. The reducer accepts them only for the active observation epoch and visible source identity, then delegates application routing without issuing another native exit. Dismissal and scope replacement cancel both observation streams.

An app-owned utility can set `includesAllOrdinaryProfiles` to receive ordinary sources across profile scopes and route native activations when another profile is focused. That mode always excludes private sources, regardless of the selected privacy flag. The default initializer preserves per-profile/per-privacy behavior.

DEV-906: `ui.perform(id, .nextTrack)` and `.previousTrack` go through the same pending command when the source advertises them.

DEV-906: `ui.seek(id, to:)` seeks a visible source, for the sidebar player's bar, through the same pending command as the other controls.

Calls (DEV-948): a source with `call` (a page using the camera or microphone that offers call controls or automatic PiP, such as Google Meet) is eligible for automatic entry without playing video. Hidden, it floats its whole tab in Page PiP (DEV-1246): the reducer sends `delegate(.presentPagePictureInPicture(id))` instead of a media request, and AppFeature opens it. A tab whose choice is `.video` takes Chromium's automatic route instead, so the site's own handler opens its Document PiP; there's no manual fallback, since only the site can open its window. Arx leaving the front floats nothing, a call or a video, while its window stays on the display. Its return closes that window as it does a video's. `toggleMicrophone`, `toggleCamera` and `hangUp` go through `ui(.perform)` like play and pause, and leave a pending return in place. The Media page shows them on a call's row, with the microphone and camera the site reports. The per-site automatic PiP switch covers calls too.

DEV-1245: `MediaStackOrder` ranks tabs by when their media was opened, for the sidebar's media stack and the Media page. `update(listing:)` keeps the ranks of listed tabs, gives new ones the next ranks in the order given, and forgets the rest; `sorted(_:)` orders sources by their tab's rank, unranked last.
