# DownloadsFeature

Utility presentation for the application-owned BrowserDownloadsClient queue. The parent provides the active ordinary profile identity and presents this destination from the space switcher or command registry. Dismissing the utility cancels its observation only; downloads survive tab and window closure.

The initial filter is Current Profile; All Profiles includes ordinary profiles only. In the Library panel (DEV-770), Filter is a quiet button that opens a pane under the header with profile chips and Private Transfers. Picked profiles (`profileFilter`) narrow every profile's downloads and show as removable chips under the search field; removing the last returns to Current Profile. Private Transfers replaces profile chips and shows as its own chip. The button turns accent with a count while filters are on, and drops its title in a narrow panel. Choosing a scope in the Downloads window clears picked profiles. The Library button's recent downloads (DEV-758) keep the queue observed through `panelAppeared`/`panelDisappeared` while they're hovered, and open through `openRecent`, which accepts any openable download in the queue because those rows list their window's profile whatever the panel filters. Its failures go to the parent as `delegate.recentOpenFailed`, because the rows have closed by then, and the app shows them as its command-failure alert. Private Transfers is a separate explicit view, accessible from a normal window even after the private source window closes. Its explanation makes continued background work visible. Private transfer records, URLs, paths and origin labels are never persisted, exported to MCP, or mixed into ordinary history. Chromium retains the private context until the last transfer terminates, then releases a context whose source window requested closure. Deliberately downloaded files remain on disk. Quit must present an explicit choice to keep downloading or cancel active ordinary and private transfers before quitting.

Chromium selects the user's default Downloads folder and reserves unique filenames, preserving existing files. The UI never invents completion, starts a replacement transfer, or opens a file automatically. Open and Show in Finder require native completion, safety approval and a file existence check. Missing files are reported without deleting history. Pause and Resume (DEV-892) are Chromium's own `DownloadItem::Pause` and `Resume`, offered only when the engine reports `canPause` or `canResume`; Resume also continues a transfer interrupted by a quit or a dropped connection, from the bytes on disk when the server honours the range request. Pause state is never saved: after a relaunch the engine reports it again. Each row's menu (`DownloadActions`) adds Copy Link (the source address, copied by the parent through `delegate.copyLink`), Remove from List (finished ordinary transfers; Chromium forgets them too, the file stays) and Move to Trash (a finished, safe file that still exists). Private transfers have no Remove from List; they leave with their session. Dangerous/insecure items remain blocked and cancellable.

Ordinary metadata is atomically persisted in the service. On restart, Chromium's initialized download-manager enumeration reconciles missing active entries as interrupted; native history owns actual state. Persistence failures remain visible without cancelling transfers. Reducer tests verify filters, event transitions, cancellation, failure presentation and subscription lifetime; native runtime smoke must additionally prove real bytes, filename collision, source closure, private closure and restart.

`soundOutcomes` (DEV-1256), sent once by AppFeature when downloads are ready, watches the queue for as long as the app runs, whether or not a downloads surface shows, and plays `SoundFeedbackClient`'s `done` for a transfer that finished and `couldNot` for one that failed. `DownloadOutcomes` compares each snapshot with the last: a transfer counts if it was seen running, or first seen already over but started since watching began (a small file can finish between snapshots). A transfer resumed and finished between snapshots counts too. Cancelling, and Chromium's `USER_CANCELED`, `USER_SHUTDOWN`, `CRASH` and `NONE` interruptions (the last is a relaunch reconciling a saved transfer), are silent, and so are history and transfers a relaunch reconciled. Each sound is asked for once a snapshot; the client turns several within two seconds into one.

AppFeature owns presentation and origin filtering. Closing this utility cancels its observation, not transfers; reopening subscribes to the latest service snapshot. The native queue remains independent of every browser and utility window.

Failure messages (DEV-1291): `downloadFailureMessage(_:)` shows a `BrowserDownloadsClient.Failure` in the interface's language from AppUI's `downloads.failure.*` keys, and any other error by its description. The client's `errorDescription` stays English, for agents and logs. AppFeature and ViewerItemFeature's downloading page use it too.
