# IntegrationFeatureTests

Every suite takes `@Suite(.dependencies)` (DEV-970). Without it, every test in the process shares one set of dependency test values, including swift-sharing's storage and its `@Shared` references, such as AppFeature's `.windows` and `.tabsLastViewed`. A store's late effects in one test then change what another reads, so a test that passes alone fails after another, on a repeat, or depending on what runs alongside it. Prefer a plain `Store` and `send(…).finish()` to a `TestStore` with `Task.yield()` loops when a test only needs an effect to finish: TestStore waits for each effect through background-priority yields, which a loaded machine starves.

CommandBarContextTests cover source-profile reassignment, stale space/tab/folder destinations, queued actions from dismissed/reopened bars, source-pane replacement/generation changes, and legitimate query edits plus labeled cross-profile switching. Existing history, private-window and pane tests use actual command-bar presentation before execution.

Reducer and ownership regression tests with injected clients; no Chromium runtime required.

LittlePromotionPublicationTests cover publication before effects, background selection and private-window preservation, stale ordinary/transfer Undo invalidation, interleaved background navigation, Favorite carryover and saved-layout selection, release-before-presentation ordering, and newer selection/window closure during the handoff.

WindowOrganizationPublicationTests hold actual main/additional-window delegate notifications across additive publication and newer folder edits, verify current-source saving without a later notification, reject delayed recipient reconciliation over the next edit, and retain private publication exclusion.
