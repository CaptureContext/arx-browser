# OnboardingFeatureTests

Every suite that uses dependencies, a store or `@Shared` takes `@Suite(.dependencies)` (DEV-970). Without it, every test in the process shares one set of dependency test values, including swift-sharing's storage and `@Shared` references. A test then reads what another left behind, so it passes alone but fails on a repeat or next to another.

Reducer tests for OnboardingFeature. A first launch opens the welcome page; Get Started records `.welcome` once and moves to the tour. Continue and Back move through pages, and Skip moves on, without recording steps. On the tour, Continue steps through every tour page and records `.tour` only when it leaves the last one; Back moves between tour pages and, from the step after the tour, lands on its last page; Skip leaves the whole tour without recording it; the page dots count each tour page; and the tour opened on its own pages with Back and closes after its last page. Skip Setup on the welcome page and Continue on the last page hand off, carrying the space an import created. Reopening resumes at the first unfinished step. A step opened on its own has no Back or progress and closes when done. Dismissal never records a step and is refused while an import is running. The import page opens the assistant with the parent's destination, returns to the page on either assistant delegate with the assistant's result shown there, and records `.migration` only for a completed import and only once. `OnboardingDefaultBrowserTests` cover the default-browser page with a Launch Services double: it reads the default when it appears; already default records `.defaultBrowser` once and waits for Continue; Make Default accepted records it and moves on; declined records nothing, stays, and Not Now moves on without recording; `alreadyDefault` from Make Default records and moves on without asking; the window can't be closed or left while macOS's prompt may be showing; and unavailable runs offer nothing. `OnboardingImportTests` cover the import summary with a fixture migration service whose runs the test drives (no real browser profile is read): discovery preselects the default browser and inspects it once; an unsupported default falls back to the most recently used browser; `preferredSource`'s order; no browsers; switching categories never inspects and browsers are read once each; Keep its spaces inspects once per choice with the matching destination; a failed inspection retries on reselect; Bring runs only switched-on categories with throttled progress and records completion; the throttle admits ten updates a second; Cancel asks the service to stop and keeps the cancelled report; partial and failed results retry with the same plan; a changed source is read again; Customize… opens the assistant with the same choices and its result returns to the page; Set Up… opens it with Passwords and sign-ins on, and the page lists passwords for browsers; Safari asks for Full Disk Access before anything is read, Open System Settings goes through the client, coming back to Arx checks again and reads Safari once granted, and while the assistant is open the activation goes to it and its answer comes back when it closes; Start Fresh moves on without recording; and a completed import records `.migration` once and waits for Continue while moving on is refused during the run. `OnboardingOutsideAgentsTests` cover the outside-agents page with doubles that record every request: it opens with MCP off and checks the command and apps; the switch only asks the parent; Install, Update and Uninstall go through the client and the window can't be left meanwhile; a failed install is shown; Add needs the command and MCP on; nothing is written without confirming the shown change (Add with nothing under review, an app with no supported way, Cancel); confirming writes once, connects the agent and records `.outsideAgents`; a failed write records nothing; Copy goes to the parent; and Skip records nothing. `OnboardingConnectAgentTests` cover the connect-your-agent page with provider doubles whose `send` fails the test: the page is listed only when a provider ships and agents may run; it reads every provider's sign-in when it appears, on Check Again and when the app becomes active; statuses map to Signed in, Needs a paid plan, Not set up and Not available; nothing is suggested until a provider is ready; Connect records `.connectAgent`, reports the provider to the parent and moves on; a provider that isn't ready can't be connected; Later records nothing; and the step opened on its own closes after Connect. AppFeature presentation, persistence, the hand-off and reopening are covered by `OnboardingPresentationTests` in IntegrationFeatureTests.
