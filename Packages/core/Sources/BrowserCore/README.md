# BrowserCore

Browser domain values and contracts, independent of Chromium, UI, and persistence implementations.

`ArxService` holds Arx's own addresses, shared by the feedback form and the member number: `privacyPolicy` (`https://arxbrowser.net/privacy-policy`), `backend` (`https://api.arxbrowser.net`, `arx-browser-backend`) and `backendURL()`, which `ARX_BACKEND_URL` overrides for a local server. `MemberNumber` is the identity card's member number from that server (DEV-701): the index, the UTC day as `yyyy-MM-dd` (kept and checked with `registrationDate`, no longer shown: the card's Member since is the install date, DEV-1323), and the `MemberSignInProvider` that claimed it; `MemberNumberFailure` is why a claim didn't finish. `InstallDate` (DEV-1323) decides when this Arx was first installed on this Mac: a date already in `BrowserPreferences.installedAt` stays; otherwise the earliest creation date of the edition's data folder or its `Browser` profile folder that isn't in the future, else now. `installedAt` is a device-local preference: not one of the synced `PreferenceDomain`s, never sent to Arx's server.

`ArxEdition` says which Arx a process belongs to (DEV-1013): the installed Arx (`dev.capturecontext.arx`) or Arx Dev, the Debug build (`dev.capturecontext.arx.dev`), from the main bundle or, for `arx` in `Contents/Helpers`, the app around it. It names the edition's folders in `~/Library/Application Support`: the bundle identifier's for profiles and crash reports, and the app's name (`Arx`, `Arx Dev`) for agents' files.

## Organization

- `Profile` has a stable typed ID, name, and ordered Favorite tab references. Several spaces can share this one Favorites collection.
- `Space` belongs to one profile and has an optional `SpaceIcon` (older snapshots use the default icon). `savedItems` is its implicit ordered root, containing pins and folders. `unpinnedTabs` is a separate ordered list. Selection can reference one of the space's tabs or a Favorite from its profile.
- `Profile` and `Space` each carry an optional `AppearanceOverride` (theme, tint hue and intensity, grain on/off, intensity and size). Every field is optional and inherited on its own: `ChromeAppearance.resolve(global:profile:space:)` takes the space's choice, then the profile's, then `BrowserPreferences.chromeAppearance`. Setting an empty override stores nil. `ChromePalette` derives the chrome's gradient stops from a `ChromeTint`: it turns the shipped colors around a constant-luma plane, so the default tint (hue 240, intensity 0.2) reproduces them, 0 is grey and 1 is vibrant, and every tint keeps the lightness rows, hover, selection and the page hairline are drawn against (light stops darken by at most 0.04 at full intensity).
- `Folder` belongs to one space, with ordered pin/folder references and disclosure state. The space root is not a synthetic Folder that could be moved or deleted.
- `Tab` keeps its identity when changing organizational location. Its optional saved destination holds the saved name, URL, and icon URL. Restoration metadata holds the last current title and URL separately. An optional custom title preserves explicit renames independently of page navigation; displayTitle prefers that name, then the saved title, then the current page title. Older snapshots decode with no custom title. Equal URLs do not imply equal tabs.
- `SplitGroup` is a Split View group of two to four tabs of one space, with orientation, pane `fractions`, and an optional title and icon. Its tabs share one `SplitList` (DEV-1006): the space's open tabs, its Pinned, or one folder; Favorites of the space's profile can be members too, and stay in the Favorites grid. `BrowserOrganization.splits` holds them; `normalizeSplits()` (run on every `update` and on decoding) keeps each group to the list holding most of its tabs and the longest run of them there, plus its Favorites, follows that list to another space, and dissolves groups left with one member or with none in a list; `gatherSplit` puts a group's tabs next to each other in its list when one is formed. `joinSplit` takes only tabs already in the list `splitList(joining:adding:)` names, or Favorites, and throws `notInOneList` otherwise. `SplitLayout` has the pure rules: equal shares, the 280 pt minimum, how many panes fit, and resizing that trades length only between neighbours. `BrowserSpacePresentation` keeps up to four panes with `fractions`, reading older snapshots' `proportion`.
- `TabGroup` (DEV-911) is a named, collapsible group of one space's open tabs, held in `BrowserOrganization.tabGroups`. `normalizeTabGroups()` (run with `normalizeSplits()`) keeps a group to its members still open in its space plus any open tab that lands between two of them, in sidebar order; a tab belongs to the earlier group and empty groups go. `groupTabs` gathers tabs into a new group where the first of them is, `ungroupTabs` leaves them where they are, `pinTabGroup` turns a group into a pinned folder of its name holding its tabs (with `members`, only those, the rest staying grouped, as `ungroupTabs(_:members:)` takes only those out, for a group split across independent windows, DEV-1160), and `leaveTabGroups`/`joinTabGroup` move single tabs in and out.
- `BrowsingSession` describes a loaded tab's session identity, profile, and current navigation. It is transient and is not Codable or included in the organization snapshot. Actual engine pages, navigation history, and window hosts belong to later services/features.

`BrowserOrganization` is a Codable value snapshot with normalized entity arrays and ordered references. Profile/space array order is presentation order; folder/tab record order is not membership. IDs are supplied by callers, allowing dependency-controlled generation in services and deterministic tests.

Call `validate()` after decoding or direct editing and before accepting a snapshot. It rejects duplicate identities, missing references, cycles, orphaned entries, multiple owners, invalid saved metadata, cross-profile tabs, cross-space folders, and invalid selections. `location(of:)` derives location from membership; use it on validated snapshots. `validate(sessions:)` additionally enforces one live session per tab and matching profile identity for organization-owned tabs. Temporary Peek/Little Arx session ownership is outside this draft.

`update` applies an in-memory edit to a copy and commits only after successful validation. Validation records each tab's location as it places it, so checking every space's selection costs no further search, and `update` checks the archive only when the edit changed it, since an archive the value already held was validated with it (DEV-947). This does not implement database transactions, Undo history, engine creation/close, or before-unload cancellation. Services must obtain engine success before committing affected organization changes. Public snapshot fields permit assembly and decoding, so direct mutation still requires explicit validation.

Saved tabs can remain unloaded. Reopening a closed pin uses its saved URL; reopening an unpinned tab uses its last URL. This is distinct from restoring an already-open session. Navigating does not update the saved destination. No cookies, credentials, storage paths, renderer objects, or UI selection hosts are serialized here. Codable is draft interchange support, not a versioned on-disk storage contract.

## Existing engine values

BrowserEngineStatus distinguishes ready and notIntegrated. BrowserNavigation carries URL, title, loading state, and optional navigation error. `BrowserNavigation.Failure` classifies that error with the URL: the renderer-stopped sentinel, loopback connection refused (with the effective port), loopback certificate errors (Chromium's `-200…-219`), a loopback `https` page that failed its TLS handshake with `ERR_SSL_PROTOCOL_ERROR` (`-107`, usually a plain-HTTP server; it carries the same URL over `http` with the effective port kept), or any other code. Compare with `.rendererStopped` rather than the `-10000` sentinel; `rendererStoppedCode` is the one Swift copy of the native value. Loopback means `localhost`, `*.localhost`, `127.0.0.0/8`, or `::1` over HTTP(S). DEV-1226: `committedErrorPage(after:)` says a failed navigation committed the engine's own error page: `document` moved past the document seen before it (a failure that commits nothing leaves it), or, seen for the first time, the current history entry is the failed address; never for a stopped renderer or an engine that doesn't count documents. `Failure.addsToEngineErrorPage` is false only for the generic failure, which would repeat that page.

## Work probe

`WorkProbe` counts work that must grow with what changed rather than with the number of tabs, archived tabs or history entries, on paths that run for every store action, keystroke or edit (DEV-682). Production code calls `WorkProbe.record(_:)`, which costs one task-local read; nothing counts unless a test binds `WorkProbe.$counts` around the work. Each module names its own `WorkProbe.Work` values; BrowserCore's are `tabLocationSearch` (`location(of:)`) and `archiveValidation`.

## Boundaries and validation

May depend on foundational extensions. Must not depend on features, UI frameworks, service implementations, or Chromium. `BrowserCoreTests` covers model invariants, serialization, saved/current destinations, session ownership, and rollback without launching an engine. Run `make test` or `make test-all`.

Requirements are tracked in [DEV-517](https://linear.app/capturecontext/issue/DEV-517/model-and-persist-spaces-nested-folders-pins-and-tab-metadata), [DEV-518](https://linear.app/capturecontext/issue/DEV-518/implement-profile-isolation-and-browser-tab-session-ownership), [DEV-520](https://linear.app/capturecontext/issue/DEV-520/implement-nested-folders-and-pinned-tab-lifecycle), and [DEV-539](https://linear.app/capturecontext/issue/DEV-539/add-favorites-shared-across-spaces-within-a-profile).

`OrganizationChange` validates profile and space creation, renaming, icon changes, ordering, removal, and profile reassignment. The last profile and space are protected; removing a profile requires no remaining spaces. Reassignment gives all space-owned tabs fresh IDs while retaining folder structure, saved destinations, and explicit names. Profile favorites stay with their owner. The caller must prepare the destination profile and obtain close approval before publishing destructive changes. `legacyProfileID` permanently identifies the owner of Chromium's original Default directory, including after that profile is removed.

BrowserCommand contains stable command identities, default character shortcuts and host availability rules. BrowserPreferences stores explicit ShortcutBinding overrides, including disabled defaults. Validation rejects reserved editing keys, invalid modifiers and collisions with defaults. Shortcut characters follow the active keyboard layout; platform event codes are not persisted.

A default added after shortcuts became bindable (`defaultShortcutYieldsToUserBindings`, today only Open Focused Link in Peek, ⇧⌘P) yields to a binding the user already gave another command: that command keeps the keys, the new default reads as unbound, and saved preferences stay valid. Other defaults still conflict as before.

Folder edits preserve ordered ownership: ungroup replaces the folder at its parent position with its children, and delete removes its complete saved subtree and affected selections. `tabs(in:includingDescendants:)` makes immediate versus recursive opening explicit. `folderSubtree` provides a structural snapshot for asynchronous close validation. Updating a saved URL changes only that URL; names, icons, and current navigation remain independent.

## Link transformations

`LinkTransformer` implements explicit original, clean, original-Markdown, proxy and proxy-Markdown modes over ordered `LinkCopyItem` values. Clean Copy removes only what `CleanLinkRules` names (DEV-918): the data file `Resources/CleanLinkRules.json` lists about 60 parameters removed everywhere, name prefixes (`utm_`, `pk_`, `piwik_`, `mtm_`, `matomo_`, `hsa_`, `itm_`), and per-site rules matched by host and subdomain (YouTube and Spotify `si`, X `s` and `t`, LinkedIn `trk`, Amazon `ref`, `pd_rd_*`, `pf_rd_*` and a trailing `/ref=…` path segment, and Instagram, TikTok, Reddit and Facebook share tags). Names compare lowercased; a missing or damaged file falls back to the twelve names Arx removed before; recognized signed/authentication URLs are preserved whole. Encoded paths, unknown query items, repeated-item order and fragments are retained. Markdown uses angle-delimited URLs and escaped titles.

`ProxyLinkRule` is a locally Codable ordered rule with normalized exact source hosts and a validated destination template. `{path}`, `{query}` and `{fragment}` preserve their encoded components, including delimiters for optional query/fragment values. Unknown/repeated/misplaced placeholders, credentials, non-HTTP(S) URLs and nonstandard ports are rejected. Source hosts include subdomains explicitly. One enabled match is applied, or an explicit matching alternative; no redirects or network requests occur. No provider presets are shipped.

`BrowserPreferences.proxyLinkRules` defaults to an empty list when decoding older snapshots. `offerDefaultProxyLinkRules` adds each of `ProxyLinkRule.defaults` once per Mac (`offeredProxyLinkDefaults`, local) and never one in `removedProxyLinkDefaults`, the defaults the person deleted, which syncs (DEV-1113); `ProxyLinkRule.removedDefaults(_:deleting:)` records a deleted default. Invalid rules and duplicate IDs fail validation before persistence. `BrowserCoreTests/LinkTransformationTests` covers encoding, boundary attacks, signed URLs, ordering, alternatives and Markdown.
Tab Archive is represented by `ArchivedTab` records inside `BrowserOrganization`. Records retain profile/space identity, last URL/title, close time and group order without live renderer state. Transactional helpers capture successful unpinned closes and prepare restoration with fresh session identities. An explicit ArchiveDestination binds Space and profile identity for confirmed cross-profile restoration; default restoration retains the original profile. Live and archived tab IDs are reserved so restoration cannot reuse an old session or tab grant. Missing archive fields decode as empty for older snapshots; invalid duplicate records are rejected.

URL routing uses ordered, enabled HTTP(S) host rules, optional standard/explicit ports and literal encoded path prefixes. Spaces determine profiles. A destination is the most recent space, a profile (its space used most recently, from the caller's `recentSpaceIDs`, else its first space), a specific space, or `.ask`, which resolves to `missingDestination` so nothing opens until a person picks one; a `nil` fallback asks the same way. Decisions retain exact input URLs and report missing destinations instead of silently falling through. Rules persist in BrowserPreferences with a backward-compatible current-space Little Arx fallback; the old per-profile default spaces are no longer read.

App Links (DEV-857, `AppLinks.swift`) are handlers for pages' links to other apps, kept in `RoutingPreferences.appLinks` (older preferences decode with none, and handlers a later Arx writes that this one can't read are dropped rather than losing the routes). A handler matches a scheme (lowercase, no web schemes), with an optional host and path prefix; the first enabled match wins. Its handling is Open app or Run script, by default and per profile (`AppLinkOverride`). Open app carries an optional `AppLinkApplication` (DEV-862): a path, bundle ID, display name and bookmark for an app chosen anywhere on disk; nil is System Default, which is also how rules saved before DEV-862 decode. The handler keeps the app its picker chose (`application`); private windows always get Open app (`fallback`: the default's app, or else the handler's), and so does a script's fallback. `validate` names the rule a scheme breaks (`invalidScheme`, RFC 3986; `reservedScheme`), and `normalizedScheme` and `example` give Settings the saved form and the "Catches claude://login/callback…" line. `AppLinkValidation` refuses a link a script would get unless it parses, has the handler's scheme, has no control characters or line breaks and is at most 8 KB. `AppLinkPreferences.decide` returns the handler, the handling, a validation failure (the prompt then offers Open app only) and whether the page's origin is always allowed for that handler, which skips the prompt; nil leaves the link to Chrome.

Automation preferences persist only credential digests, explicit profile/location-bound scopes (including whole-profile scopes), capability classes (`AutomationCapability`), a standing `AutomationApprovalPolicy`, the focused-tab opt-in and grant expiry. Operations declare `requiredCapabilities` and an `AutomationRiskTier`; `AutomationGrantSummary` is what the MCP helper sees of a grant. `AutomationBatchPlan` lists up to 16 distinct operations for one approval (no sign-in or nested batches); its tier is the highest of its steps. Command actions declare their `capability` (organize or browser admin), `targetKind` and risk tier; deleting a profile, space, folder or saved entry is destructive. Inventory items can be profiles, for whole-profile grants; `AutomationWindowItem` describes windows, `isMain` marking the main one; with independent windows an open tab's inventory item carries the `windowID` that keeps it, and `openTab` can name one (`AutomationCommand.windowID`, never with `route`; DEV-1157). Older payloads decode without either. `AutomationDataRequest`, `AutomationDataItem` and `AutomationDataPage` carry bounded history, archive and download reads; `AutomationLinkRequest` covers Clean Copy, Proxy Links and bangs. `AutomationLoadRequest` loads a saved tab in the background as a read-tier page-content operation. `AutomationCaptureRequest` carries `scale`, `format` (png/jpeg) and `quality`; `AutomationCaptureImage` is the delivered encoding, capped at 4 MiB. Captures can be `offscreen` or crop to an `element` reference. `AutomationPDFRequest` exports a page or reads a PDF document's text, as a read of page content. `AutomationFindInPageRequest` drives native find; it is a mutate-tier interaction because highlights and the final selection are visible. `AutomationProfileItem` and `AutomationChangeDigest` carry granted profile names and granted tab revisions. Profile and space inventory items carry their own `AppearanceOverride`, and inventory carries the app-wide `ChromeAppearance` they apply to; `AutomationAppearanceChange` chooses override fields, returns some to inheriting or clears the whole override for `setSpaceAppearance` and `setProfileAppearance` (hue 0–360, intensities 0–1, grain size 1–3; a hue of 360 is stored as 0). `AutomationSettingsRequest` (DEV-666) reads a Settings section, tests a URL against Air Traffic Control, or carries an `AutomationSettingsEdit` with the section's revision; it needs the browser admin class, and deleting a routing rule or search shortcut is destructive. `AutomationPreferenceKey` is the allowlist of writable preferences, each with a schema; `protectedNames` lists settings (developer mode, automation, onboarding and others) that are never readable or writable. Routing destinations outside the grant are hidden (`AutomationAccess.permitsRoutingDestination`). `AutomationScriptRequest` and `AutomationLogRequest` (DEV-668, `AutomationDeveloper.swift`) are the developer tier: a script needs the script class, is the mutate tier and ignores temporary grants, and its `AutomationScriptResult` is bounded to 262144 bytes of JSON text; console and network log reads need the devtools class, are the read tier, and return at most 200 `AutomationConsoleEntry` or `AutomationNetworkEntry` values. `developerModeRequired` is their refusal while developer mode is off. `AutomationPasswordSignInRequest` (DEV-708) asks Arx to sign in with a password saved in the tab's profile, bound to the tab, its revision, the exact origin and optionally a frame; it needs the sign-in class, is the mutate tier and can't be a batch step, and its `AutomationPasswordSignInResult` is an outcome and a fixed reason only. `AutomationPreferences.agentSignInSites` lists the `AgentSignInSite`s (profile and exact origin) where agents may do so without asking; older preferences decode with none. `AutomationOperation.pageTargets` names the tabs an operation reads or acts in. Clients saved with the older per-toggle fields decode into the same effective classes. New/legacy preferences disable automation. BrowserSessionSnapshot carries non-invasive navigation metadata and a conservative session revision. Tab metadata optionally records its creating automation client; older records decode without it.

BrowserNavigation validates history identity/current-entry invariants and returns directional nearest-first entries; it never combines history across sessions. Back/forward command availability uses the current host navigation boundaries.

BrowserDownload models stable transfer identities, native status and progress, origin labels and file-opening eligibility. DownloadQueue separates ordinary history from memory-only private transfers.
`HoverPreviewSources` (DEV-802) is what Settings › General › Previews turns on beyond a tab's hover card: folder lists, unread Gmail on an open Gmail favorite, and recent Linear, Notion and Figma pages from the profile's history. All three default on. DEV-730 adds `pageDetails` (a page that isn't loaded shows its site's Open Graph picture and description, fetched without cookies, or with the profile's cookies for the page's own host under `ARX_SITE_PREVIEW_IMAGES`, DEV-1142; on) and `fullPages` (Full previews: such a page loads off screen for its picture; off). DEV-1029 adds `shiftLoadsPages` (Shift + hover loads the page instantly: Shift-hover over such a page loads it off screen at once, whatever `fullPages` says; off). A missing or unreadable key keeps its default without failing other preferences. `AutomationPreferenceKey` exposes `hoverPreviewsEnabled`, `hoverPageDetails` and `fullHoverPreviews` to `browser_settings`.

DEV-804 adds `calendars` (Live Calendar: a Google Calendar favorite shows today's day; on, but only while the `ARX_LIVE_CALENDAR` feature flag is) and `disabledCalendars`, the favorites whose card turned it off with Disable Live Calendar; turning `calendars` on again clears it. `LiveCalendar.isEnabled` reads the flag like the other `ARX_*` flags: the environment first, then user defaults, and only `1`, `true` or `yes` turn it on.
BrowserWindowPresentation stores window and space placement separately from tabs. Restoring a placement removes missing, moved or already-hosted tab references and clamps its divider proportion. Legacy preferences default to no window presentation records. A record also keeps the chat panel's width (`chatWidth`, clamped by `BrowserChatWidth`) and the chats pinned to the window's tabs (`chatPins`, DEV-761); both are absent in older snapshots.

`ChatTabAddress` is a chat tab's address, `arx://chat/<conversation>` or `arx://chat` for a new chat (DEV-761). `Tab.chatAddress` and `Tab.isChat` read it from the tab's restoration URL; such a tab is saved and moved like any other but never reaches the engine.

The Downloads command is available only after application-owned native queue configuration, including when no browser window is open. Its utility context supports Close without closing a browser tab.


BrowsingHistorySnapshot models bounded, exact-URL history for one explicit profile. Revisits preserve result identity; failed/unsupported/credential-bearing URLs are excluded by hosts and URL validation. It remains separate from BrowserOrganization and its Undo snapshots.

`DeviceCapture.swift` (DEV-757) holds the developer header's device capture: `DeviceCaptureStyle` (Portrait Mode, the background slider's place, dark or light), its gradient and device colours, the phone-shaped `portraitRegion(in:)` of a viewport, `DeviceCaptureLayout`, which places the canvas, device, screen and details for a screen size, and `DeviceCaptureFeatureFlag`, the `ARX_DEVICE_CAPTURE` feature flag (environment, then user defaults; on by default since DEV-1143).

`SitePreviewImagesFeatureFlag.swift` (DEV-1142) is the `ARX_SITE_PREVIEW_IMAGES` feature flag, on by default: `1`, `true`, `yes` or `on` turns it on, `0`, `false`, `no` or `off` off, anything else keeps the default. `UnloadedPagePreview` is its Settings choice for pages that aren't loaded (`sitePicture`, `loadPage`, `savedPicture`), read and written through `HoverPreviewSources.unloadedPages` on top of `pageDetails` and `fullPages`, so saved preferences keep their shape.

`CaptureBeyondViewportFeatureFlag.swift` (DEV-1208) is the `ARX_CAPTURE_BEYOND_VIEWPORT` feature flag, read through `FeatureFlag` at launch and on by default: Capture Page's frame shows the whole page, and Capture Area scrolls the page while drawing. `PageCaptureOffset` is the scroll distance in viewport points that `BrowserCaptureClient.scrollAuthorized` takes and returns.

`CopySubmenuFeatureFlag.swift` (DEV-1162) is the `ARX_COPY_SUBMENU` feature flag, read through `FeatureFlag` and on by default. `LinkCopyMenu` lays out its Copy ▸ submenu for every menu that copies links: `sections(modes:offersSavedLink:sharesProxy:)` gives the copies in menu order (a pinned tab's Saved Link last), then Share Proxy Link after a separator; `nests` keeps a lone item, such as a mailto: link's Copy Email Address, at the top level; and each item's `command` is the browser command the Tabs menu shows with its shortcut. `tabSections(proxies:offersSavedLink:)` is a tab's or the page's Copy ▸, with the proxy items only when `proxies`.

The proxy link items show only on a site a proxy link rule matches (DEV-1262): `LinkTransformer.proxies(_:rules:)` says whether an enabled rule matches a link without its credentials, on the default port. `LinkMenuAvailability(_:rules:)` and `BrowserLinkContext.availability(rules:)` decide a link's menu with it; context menus leave the items out elsewhere. `BrowserCommandContext.canProxyLink` carries it for the page, so `BrowserCommand.isEnabled(in:)` disables Copy Proxy Link, Copy Proxy Link as Markdown and Share Proxy Link (`BrowserCommand.proxyLinkCommands`) in the menu bar, and `isListedDisabled(in:)` has the command bar list them disabled rather than leave them out.

`HideElementFeatureFlag.swift` (DEV-1019) is the `ARX_HIDE_ELEMENT` feature flag, read through `FeatureFlag` and on by default since DEV-1143: Hide Element's menu item, shortcut and command bar entry, and the site menu's Hidden Elements.

`ElementPickerFeatureFlag.swift` (DEV-1201) is the `ARX_ELEMENT_PICKER` feature flag, on by default: Hide Element opens Arx's own element picker where the engine has it; off, uBlock Origin's picker.

PageCapture values bind a tab revision and captured document token to immutable viewport pixels and bounded top-left coordinate mapping. Full-document capture is not exposed until its native behavior is validated.

BrowserMedia models transient source identities, monotonic native snapshots and revision-checked media requests. AutomaticPiPPreferences stores only explicit normal-profile, exact-origin opt-ins. These values do not enable native PiP; the client capability remains disabled until the runtime adapter is validated.

OrganizationMove plans atomic ordered root/subtree moves, preserves saved/open placement and same-profile IDs, rejects cycles/partial subtrees, remaps every nested tab for cross-profile moves, and constructs fresh-identity organizational Undo. Each copy a cross-profile move, its Undo or a space's new profile makes carries `Tab.movedFrom`, the tab it copies, in memory only (not encoded, not part of equality), so the workspace store can tell the move from a deletion (DEV-1089). Destination anchors are resolved after removing the whole selection to preserve order. Undo preserves unrelated current restoration metadata, disclosure and valid selection.

`OrganizationUndo` is one step ⌘Z takes back (DEV-1030): an `id` its copies in other windows keep (not part of equality; `isSameChange` compares it), the workspace before and after it, the space it was made in, its author (a person or an agent), an optional end (a deleted space's `deletedSpaceGracePeriod`), an optional Move to Window and the windows the open tabs it removed were in (`openTabOwners`). `reverting(_:to:)` takes a step back on top of the workspace as it is now: what the step removed comes back and what it made goes unless changed since, what it moved goes back unless moved again, the fields it changed go back where nothing changed them since (a saved page's title and address each on its own), and each list keeps the step's earlier order unless something rearranged it since. A tab the step closed comes back only while the archive still holds its entry, so a tab reopened with ⇧⌘T isn't reopened twice. Restoration, selection and everything else changed since stay. It returns nil when nothing is left to take back and throws when what's left can't be put back validly, or would leave no space.

BrowserExtension values retain permission groups, native disable reasons, install origin and profile-bound inventory/request identity. They describe capabilities without granting permissions or persisting runtime authority.

AutomationCaptureRequest binds a viewport/region read to one explicit tab and inventory revision. AutomationCaptureResult contains immutable PNG pixels, profile/session/native-document identity, geometry and a unique capture ID with bounded validation. The separate AutomationClient screenshot grant decodes absent fields as false. BrowserSessionSnapshot's live native document epoch and host-visibility flag fail closed when unavailable; neither represents DOM/action authority. PageCaptureRequest adds optional ordinary-profile/document constraints for automation while explicit user capture retains its existing defaults.

AutomationInspectionRequest binds a historical semantic read to an explicit tab/revision and finite node/text budgets. PageInspectionSource is app-supplied ordinary profile, session, native document and per-connection scope identity. Snapshots carry main-frame/document/snapshot IDs, canonical decimal DOM version, ordered semantic nodes and explicit coverage omissions. Validation bounds nodes, references, each UTF-8 text/name and total text; references are never action authority. The separate page-content grant decodes absent fields as false.

Reference-scoped click values keep request identity separate from authority: explicit tab/revision, snapshot/reference and operation ID. `allowsPageInteraction` is independently default-off, including old saved-client decoding. Results distinguish no dispatch, initiated dispatch and uncertainty, with no page content or navigation-success claim. Inspection delivery adds a conservative 80 KiB encoded-result budget before latest-released bookkeeping, reserving MCP's duplicated text/structured envelope without truncation.

`AutomationWaitRequest` supports only explicit current-generation `loadingStopped` observations with a 1–10,000 ms deadline. `PageWaitTarget` freezes entry identity; `AutomationWaitResult` reports a historical observed revision and native error separately from navigation or website success. No new permission is inferred from these values.

Ordinary AutomationFormRequest actions provide whole-value replacement for supported text/search inputs and textarea, and exact single-select option values. Requests reuse explicit operation/tab/inventory/snapshot/reference identities. UTF-8 limits are 32 KiB for replacement and 4 KiB for selection; empty values remain exact, NUL is rejected, and text rejects CR. Native control validation additionally rejects LF in single-line inputs. Receipts contain no values and distinguish validated unchanged (no setter/events, consumed ID) from dispatch or uncertainty.

AutomationScrollRequest binds a physical axis and finite CSS-pixel delta (inclusive ±8192) to an explicit inspection reference. Signed zero is canonicalized for dispatch and digest binding. Scroll receipts contain only operation identity, dispatch certainty and typed failure; unchanged consumes the ID and does not claim offsets or website completion.

`BrowserLinkContext` is an ephemeral, non-Codable renderer menu target. It binds the clicked HTTP(S) link to its original native tab, profile, session and document revision; current navigation and saved pin identity never supply a fallback.

`ProfileRetirementIntent` retains an immutable consent request/profile/original revision plus the latest attempt revision. Acknowledged retirement adds a permanent `retiredProfileIDs` tombstone. Organization validation rejects reuse of those identities; root-local acknowledgments filter restored workspace backups before any page opens. A backup containing only retired owners fails recovery rather than inventing a new identity or borrowing the old Default storage.

Capture requests explicitly distinguish viewport from staged full-document mode. Document geometry keeps exact document/visible rectangles, fractional scroll and zoom separate from live viewport DIP and device scale; image-point selections start at the frozen document origin. The initial supported raster policy is one pixel per layout pixel. Request mode and geometry must agree before any crop/preview/automation delivery.

`AutomationFormRequest.Kind.keyPress` binds one permitted Unicode scalar or the
named basic editing keys to the same explicit target and operation identities.
It accepts at most 32 UTF-8 bytes and rejects controls, multi-scalar sequences,
modifiers and unsupported named keys before transport. Native availability and
focused-field/selection authority are independently checked; this is no implicit
focused-target fallback. Receipts never carry the key or field contents.

BrowserExtensionViewRequest authorizes one manifest-defined options view using
the current inventory token, ordinary profile, revision and extension ID. It
contains no caller-provided URL or selected-tab fallback. The service refreshes
its authority after an accepted request.

## Profile storage aliases (DEV-1216)

`ProfileStorageAliases.shared` maps a profile to the ID its website data is kept under on this Mac, when that isn't its own: a profile merged into iCloud's keeps this Mac's cookies and storage under the kept profile's ID, as an alias, never a copy. The workspace store sets it at every load from its `profileStorage` table; the engines read it when they name a profile's storage (`storageID(for:)`) and map what they report back (`profileID(forStorage:)`). `observe(_:)` calls back with every change.
