# ChromiumEngine

ABI11 inspection reads only already loaded ordinary main documents. The runtime
returns historical semantic nodes with declared omissions, never form values or
raw DOM. Trusted per-client/grant scopes, monotonic requests and page generations
reject late or foreign callbacks. `inspectionDocumentIsCurrent` checks native
document/page/scope liveness; DOM validity requires the asynchronous renderer
reference validation seam and never authorizes a later action. Scope revocation
cancels pending reads and invalidates retained snapshots. Native hard output and
handle limits are checked again before decoding/copying into Swift.

Swift runtime, page ownership, framework loading, and navigation API. The main actor confines calls to Chromium’s UI thread. The framework remains loaded for the process lifetime. Features consume domain contracts through services, not this native implementation directly.

ABI 2 adds asynchronous profile preparation, before-unload decisions, renderer failure and navigation-entry history. `makePage(profile:)` uses a dedicated native profile per UUID; nil preserves the legacy Default profile. Profile keep-alives remain owned by the runtime until shutdown.

DEV-1116: Chromium ends a navigation it doesn't commit, such as one that became a download or a stop, with `ERR_ABORTED` and no error page. `ChromiumPage` keeps the error the page already had, usually none, instead of reporting `ERR_ABORTED` as a page error.

ABI 3 adds preparePrivateProfile/releasePrivateProfile and clearCacheAndReload. A released private ID cannot be reopened as a disk-backed profile.

prepareProfile initializes persistent profile storage without a webpage; makePage(profile:) reuses that preparation. Nil continues to refer only to Chromium’s original Default directory.

ABI 4 exposes copied `ChromiumDownloadEvent` values and profile/GUID cancellation. Subscriptions replay current records and initialization markers, then observe updates independently of page lifetime. Native strings never escape the callback; runtime shutdown finishes subscriptions and drops in-memory records. Cancellation after shutdown is rejected before calling native code.

ABI5 exposes `capture(_:limits:)` and copied `ChromiumCapture` values. The runtime validates limits before dispatch and native lengths before copying borrowed bytes. Task cancellation removes and resumes the continuation immediately, then cancels native work; page close and shutdown drain outstanding continuations. Late callbacks cannot resume a canceled request or another capture. Native rendering, PNG encoding, and protected-surface behavior require the real framework fixture gate.

ABI5 also appends an explicit run option for Chromium’s supported mock Keychain. `mockKeychainForTesting` defaults to false, preserving the real Keychain path. Only the standalone runner passes true after validating its own fresh disposable fixture. Mock mode cannot establish production Keychain persistence or security.

`prepareHostAllocator()` forwards to the guarded host-only startup wrapper before Foundation configuration. Callers must stop on failure, which emits a native diagnostic without using AppKit. The framework loader checks the owned delegating zone before `dlopen` and PartitionAlloc replacement afterward; startup-order failures are typed `allocatorBootstrapFailed` errors. Missing files retain `frameworkMissing`. The Debug entry probe remains read-only and only logs when the runner supplies a nonempty smoke title.

ABI6 adds opt-in `observeMedia`, copied media snapshot/activation streams, and revision-checked `performMedia`. Requests drain once on cancellation, page close, or shutdown; stale generations cannot acknowledge a replacement source. Observation never starts a player. Private pages are refused before native dispatch. The boolean-only private metadata policy probe is for controlled validation, not permission to expose private media. Controlled native video fixtures complement wrapper tests; OS surface behavior remains separate acceptance.

ABI7 adds opt-in, profile-scoped extension inventories and revision-bound enable/disable/remove. The runtime copies bounded native metadata, preserves unknown disable reasons, rejects inventories from another runtime, and cancels/drains pending callbacks. Enable is limited to an MV3 extension disabled solely by the user; pending permission review is never granted. Private profiles are unavailable. `enableExtensions` defaults to false. The separate `extensionFixtureForTesting` option requires mock Keychain, uses native-owned fresh storage, and can load only the compiled-in MV3 fixture. Fixture-only permission escalation exercises rejection, not CRX update permission review.

ABI8 adds synchronous `isMediaSourceCurrent(_:generation:)`. Runtime state, exact page object ownership, non-private context and nonzero generation are checked before querying the live native observer. Cached media snapshots are not validation authority. Call immediately before focus on the same actor turn; missing native support is rejected at framework loading.

ABI32 adds `seekMedia(_:generation:revision:to:)`, which shares the media request queue, cancellation and generation checks with `performMedia` and needs the source's `.seek` action, plus synchronous `mediaPosition(_:)` and `setAudioMuted(_:_:)` for observed ordinary pages. `setAudioVolume(_:_:)` (DEV-800) calls `ArxEngineSetPageAudioVolume`, which `ChromiumFramework` looks up beside the ABI table; `supportsAudioVolume` is false on engines built before it. A position read copies one native value; nothing is published per frame.

DEV-873 adds `unload(_:reason:)`, `isUnloaded(_:)`, `restoreUnloadedPage(_:)` and `supportsPageUnloading`, over the engine's `ArxEngineUnloadPage`, `ArxEnginePageIsUnloaded` and `ArxEngineRestoreUnloadedPage` exports, which `ChromiumFramework` looks up beside the ABI table (all three, or none). `unload` answers `unloaded`, `alreadyUnloaded`, `refused` with the engine's `ChromiumPageUnloadBlockers`, `busy` while the page loads, or `unavailable` for older engines, closed pages and a stopped runtime. `ChromiumPage.Navigation.isUnloaded` follows each `page_changed`. DEV-1107 adds `ChromiumPageUnloadReason.windowClosedAnswered`, `unloadBlockers(_:reason:)` and `supportsAnsweredUnloads` over `ArxEnginePageUnloadBlockers` and `ArxEngineUnloadAnsweredPage`, looked up with the others but optional: without them nothing is asked and the answered reason is unavailable.

DEV-1293: `setSharedHistory(_:back:forward:)` tells a page's swipe that the tab's WebKit page is right behind or ahead of its current entry, and `observeSharedHistorySwipes(_:)` hears a swipe released that way, through `ArxEngineSetPageSharedHistory` and `ArxEngineSetSharedHistoryHandler`, optional exports beside the ABI table; `supportsSharedHistory` is false on engines built before them, whose swipe reaches only the page's own history.

DEV-878: `navigationState(_:)` copies an ordinary page's back/forward entries through `ArxEngineCopyNavigationState`, `makePage(profile:restoring:at:)` makes a page that takes them (nil when the engine can't, the bytes are unreadable or they don't end at the address), and `loadRestoredPage(_:)` loads it. `ChromiumFramework` looks the three exports up beside the ABI table; `supportsNavigationState` is false on engines built before them.

DEV-907: `observePageBadges()` registers with `ArxEngineSetPageBadgeHandler`, when the engine has it, and hands each page's Badging API report to `onPageBadge`: nil clears it, `.some(nil)` is a badge without a number, else the count. The engine also clears it when the page commits a new document (a reload included); same-document navigation keeps it.

ABI53 (DEV-906) gives `ChromiumMediaSource` the `.nextTrack` and `.previousTrack` actions, which `performMedia` sends like the others and which complete once the session has them, plus the session's `artist` and `artwork` (PNG bytes, at most 256 px a side; larger than `maximumArtworkSize` is dropped). A snapshot with an action bit past the ABI's is refused.

ABI33 adds `startDownload(profileKey:url:)`, which returns the new item's GUID once Chromium has created it; the item's first `downloadEvents()` change arrives before it returns. It throws `ChromiumDownloadStartFailure` (`unavailable`, `failed(interruptReason:)`, `timedOut`) and refuses private profile keys and non-http(s) URLs or URLs with credentials. It isn't cancellable once sent; shutdown answers pending starts with `unavailable`.

ABI9 adds `approveClose`, `consumeClose` and `cancelClose`. Approval caches the native epoch accompanying the last published navigation, never substitutes a newly queried epoch for stale Swift state, and is bound to one runtime/page/request. Requests time out and cancel promptly while native retains its exact tagged physical callback slot until callback or reset. Consumption is synchronous: native validates/destroys, then Swift removes ownership and invalidates the page without a second destroy. Page closure/shutdown drain pending requests and revoke outstanding grants. `supportsAuthorizedClosing` reports the immutable native function set, so dependencies composed before startup retain the capability. Execution separately requires a running runtime.

Favorite icon reads require an explicit ordinary-profile allowlist and use Chromium's exact-page favicon database lookup; on a miss, native fetches the site's icon from its root page or `/favicon.ico` (never the saved URL) without cookies and stores it in that profile. The wrapper copies and validates PNG metadata within 32px/64KiB limits. Monotonic request IDs and profile-membership generations reject queued callbacks after cancellation, profile removal/recreation, and completion-before-task-resume races. No request may turn a private or released-private identity into ordinary storage. Missing icons return nil; unavailable/invalid/limited/timeout/busy responses remain typed failures.

Change notifications capture the ordinary profile membership generation while the page is alive. Their validity survives page closure, allowing a just-written favicon to refresh Favorites, but profile removal/recreation invalidates queued events and old-page callbacks.

Ordinary page close and terminal loading/URL/error transitions also emit generation-bound refreshes, recovering database updates whose weak native notification was discarded during document teardown. Every page change carries `pageURLs`: the address Chromium reported or the page showed, plus the web addresses its current load went through (redirects, same-document changes; at most eight, reset when a new load starts, after one change names the outgoing addresses, since a replaced document's notification can be lost), because Chromium's favicon database updates those aliases alongside it (DEV-940). Server redirects whose middle addresses no snapshot showed arrive through ABI51's `site_icon_redirects`; addresses new to the page then send one more change, and a chain native reports as truncated (more than eight addresses, or one too long) makes that load's changes profile-wide until the next load starts, so earlier aliases refresh after the favicon is stored. Until Chromium reports the page's icon, native also sends each same-document commit's address (Chromium maps the coming icon to those too), and a trail that overflows in that window turns the load profile-wide the same way. A native change also carries the favicon's `iconURL`, and each lookup answer its bitmap's `iconURL`, since every page mapped to one favicon shares its bitmap. A page that never showed a web address emits nothing. Only clearing a profile's history emits a profile-wide change (`pageID` nil, `pageURLs` empty, `isProfileWide`). When a subscriber's bounded buffer drops an older change, a profile-wide change for that profile takes its place. Changes carry no icon bytes. Loading progress, title and history-only snapshots do not trigger refreshes; private, removed and replaced profile scopes remain excluded.

`documentRevision(for:)` synchronously reads the existing ABI9 page close-generation authority for an exactly owned live page. It returns nil before readiness, after disposal, for foreign pages or when the native query is absent. Screenshot authorization uses this value to reject native navigation that precedes queued Swift page-change delivery. It introduces no ABI change and makes no DOM/action-reference guarantee.

Reference clicks use `ChromiumReferenceClickRequest` and return a nonthrowing
`ChromiumReferenceClickResult`, preserving whether the input was not dispatched,
was dispatched, or might have been dispatched when cancellation or timeout wins.
A dispatch receipt is not proof of website success or navigation completion.
Requests retain the exact inspection snapshot and an independent operation UUID;
page and trusted client/grant scope remain separate runtime arguments. The app
must require its latest snapshot actually released to that client. Native code
may conservatively reject an older snapshot as soon as a newer scoped snapshot
is created, even if that newer read is never released. Neither layer replays a
mutation automatically, and duplicate receipts preserve the earlier disposition.

`clickInspectionReference(_:on:scope:authorize:)` checks the live source and calls
its MainActor authorization closure immediately before C submission without
suspension. The app must also recheck grants before returning current page data.
`supportsReferenceClick` describes immutable ABI availability; it is not readiness
or permission. Both Swift and native retain bounded operation receipts through
shutdown/disposal so an old operation cannot be replayed through a new scope or
connection. Timeout is bounded to 1...2000 milliseconds.

ABI13 exposes `performInspectionFormAction(_:on:scope:authorize:)` and immutable
`supportsReferenceFormActions`. It shares the click wrapper's receipt ledger,
monotonic request IDs and physical pending slots. SHA-256 bindings include kind
and exact bytes; receipts never store text. The final synchronous authorization
callback is followed by cancellation and live source checks without suspension
before C submission. Results preserve `unchanged`, typed failures and possible
effects after cancellation; they never throw away uncertainty. Unchanged is a
successful fully validated no-op, not permission to overwrite an interleaved
edit. Input byte limits are enforced before copying or hashing unbounded values.


ABI14 exposes `scrollInspectionReference(_:on:scope:authorize:)` with the same operation receipts,
physical slots, final authorization and lifecycle rules. The axis and exact
finite CSS-pixel delta (absolute value at most 8192) bind the operation; negative
zero is canonicalized to zero before a fixed-width SHA-256 input. Native code
selects the nearest containing-block scroll area with user-scrollable positive
extent on that axis, clamps its current offset and requests instant movement.
There is no residual chaining, focus/activation, wheel input, or website
completion promise. A fully validated clamped no-op returns `unchanged` without
invoking the setter. The public receipt contains no page offsets. Capability
availability is separate from readiness and authorization. The existing native
click cancellation entry also cancels this shared action family.

`referenceSubmissionsAreSettled(on:)` is the trusted sign-in handoff's readiness
check. Every submitted reference action records its native page and the page's
close/navigation epoch at submission. Only a validated success reply releases
it; an early cancellation, timeout or failure keeps it uncertain. Uncertainty
is scoped to that page document: other pages are unaffected, an epoch change
(a primary main-frame navigation start) or page closure releases it, and runtime
teardown clears everything. An entry submitted without a known epoch blocks
every document of its page. Released entries no longer count toward the 16-entry
uncertainty admission bound.

`linkContextEvents()` copies bounded native menu bytes into ephemeral values. The wrapper retains exact original payload authority until dismissal, page close, observer replacement or shutdown; forged payloads with a valid token fail synchronous `linkContextIsCurrent`. No selection, history or MCP read is exposed.

ABI15 adds a user-triggered renderer link-context callback and synchronous current/dismiss functions. URL and own link-text pointers are bounded and borrowed only during that callback. A unique token binds source and primary documents; coordinates are proven root-page viewport DIP with a top-left origin. The app must revalidate the original page/profile/session and token synchronously at menu selection. The runtime requires the matching framework before launch.

ABI16 exposes explicit profile retirement through an opt-in run configuration with a stable persisted installation UUID and permanent Default owner. The default run remains unconfigured. Typed bounded snapshots distinguish durable retirement from quarantine, a required Mac restart, verification, and erased data. Paths and boot UUIDs remain native-private. Queue callbacks survive task cancellation after dispatch, because cancellation cannot undo a committed retirement; shutdown fails unresolved requests for reconciliation against persisted intent. Actual packaged startup and reboot acceptance remain separate gates.

The ABI16 document-capture adapter adds `capture(_:limits:fullDocument:)`, a separate borrowed native snapshot and copied `ChromiumDocumentCaptureGeometry`. Output layout-pixel scale remains independent of root viewport/device scale; unsupported scaling is rejected before bytes are copied. Mode-bound callback kinds, cancellation, page close and shutdown retain the existing continuation ownership. `supportsDocumentCapture` follows the running native predicate. The developer fixture run option and explicit `runDocumentCaptureFixture` method do not enable production capture. The wrapper requires the matching ABI16 framework; an ABI15 cache cannot satisfy this table.

The gesture fixture option is default off and requires mock Keychain plus
fresh native-owned storage. `runGestureFixture` refuses ordinary runtimes,
private/foreign/closed pages and non-loopback origins. It exposes no ordinary
input-injection capability. The coordinated ABI16 suffix follows retirement and
full-document capture and requires the matching ABI16 cache.

The staged `keyPress` form action uses a separate native capability getter and
kind4 on the existing shared mutation lane. Missing capability fails unavailable;
exact duplicate receipts still reconcile after capability loss. The bounded key
is hashed with its distinct action kind and never retained in receipts. Only an
explicit supported already focused field can be addressed. Event delivery can
have author side effects; native default edits are suppressed after focus or
selection redirection. No focus, activation, IME, modifier or system input is
synthesized. Final ABI assignment and matching native acceptance remain required.
The staged content-hosting opt-in adds native popup delegation. Chromium's popup
blocker remains authoritative; its source-view indicator offers the original
blocked request through Chrome's normal click-through delegate. Allowed child
WebContents are adopted exactly once with their existing opener and browser
context, under weak source/primary-document and epoch checks. A synchronous
rejection destroys only the unadopted child. Reentrant source destruction waits
for Chromium's popup caller to unwind; atomic authorized close returns busy
before consuming its grant during that offer. Menu labels omit credentials,
queries and fragments. The bounded wrapper callback copies its target URL and
never replaces adoption with a new navigation. This draft requires the next
coordinated ABI and matching native acceptance before production enablement.

The selector is the shortest that finds only that element in its document, going up from it: a lasting id; else its tag with a `data-testid` or up to two lasting classes (made-up ones, with three digits in a row, a `css-`/`sc-`-style prefix, mixed-case hashes or state words, are left out), `:nth-of-type` among siblings it would also match, and `>` steps up to an ancestor's id. The pointer and the keys never reach the page while the picker is open (DEV-1206): `ChromiumElementPickerInput`, an `NSView` laid over the page view as its topmost subview (so it moves with the page from host to host and leaves docked DevTools alone), takes the mouse with a crosshair cursor and the keyboard as first responder, giving the keyboard back when it goes. While it's open, whatever hands the keyboard to the page instead (the app focusing the page, `ChromiumPage.focusContent()`, which prefers the picker's view, or the page focusing itself) hands it to the picker's view, which watches the window's first responder; something else in the window, such as the sidebar or the command bar, keeps it until the person clicks the page. Joining a window alone takes nothing: a page staged under a space swipe leaves the keyboard where it is. It hands what it sees on as `ChromiumElementPicker.Command`s (moves in a row count as the last, a press and release within 4 points is a click, a secondary click or a Control-click leaves, Esc, ↑, ↓ and Return; other keys go nowhere, and menu shortcuts still work), which the session passes to the script with its next look, at once when there's input and else every 100 ms; a look a busy world refuses keeps its commands for the next, and one that times out, which may have run, doesn't send them again. An ask to open carries a token, so asking again after a timeout answers for the session it opened instead of toggling it closed. A page has one picker view at a time: a newer session's replaces one an earlier session hasn't taken away yet. A key acts on a move that came with it, and after a pinch or a zoom the pointer's view point is mapped anew. The script turns the view's points into the page's with the screen's pixels per point over the page's `devicePixelRatio` and the visual viewport's pinch, and draws in a layer that takes no pointer events, inside the top modal dialog if there's one. Only trusted events count; ↑ widens to the parent (from a frame's body to the frame), ↓ narrows back or to the child under the pointer, a click or Return picks, Esc or the page's menu leaves.
