# ChromiumBootstrap

Host-only allocator startup and observation, independent of the versioned Chromium framework ABI. App and development-host entry points call `prepareHostAllocator()` before accessing ProcessInfo, Bundle or UI. Failed preparation prints a precise native diagnostic and exits nonzero without initializing AppKit. There is no fallback to loading Chromium with unsafe allocator ordering.

The wrapper verifies that it is on the main thread, that only one thread is alive, and that thread/zone inspection succeeds. It refuses pre-existing delegating or PartitionAlloc zones owned by another startup path. It then invokes the exact pinned upstream `EarlyMallocZoneRegistration` implementation and verifies the delegating default zone. Repeated preparation through this wrapper only verifies its existing expected phase; it never registers twice. The runtime loader checks for the owned delegating zone immediately before `dlopen`, then requires PartitionAlloc to have replaced it afterward. A second framework load is rejected. Missing-file and invalid-URL errors retain their own typed diagnostics.

Registration forwards allocations to the existing system zone until the framework replaces the delegating zone. `Upstream` contains the unchanged Chromium source, headers, retained BSD license, and exact SHA-256/source-pin manifest. `Config/partition_alloc/buildflags.h` is the documented host-only subset of the pinned generated configuration: `USE_PARTITION_ALLOC_AS_MALLOC=1`. This target needs only system Mach/malloc APIs and C++20, with no Chromium runtime link dependency. Never invoke the upstream double-registration escape hatch. Update source hashes and configuration deliberately whenever the engine pin changes.

The read-only entry probe copies live thread count, main-thread status, and the current default malloc zone. It uses the first enumerated zone because `malloc_default_zone()` can denote the original system zone. It releases Mach thread rights and enumeration memory. Debug smoke entry reports `ARX_BOOTSTRAP_ENTRY`; successful preparation and framework replacement report `ARX_BOOTSTRAP_REGISTERED` and `ARX_BOOTSTRAP_FRAMEWORK_VERIFIED` when the runner supplies a nonempty smoke title or Settings acceptance root. Ordinary successful launches remain quiet. The probe's output alone does not establish correct allocator registration.

Fresh-process tests verify actual upstream registration, preserved pre-existing/new allocations, idempotence, and failure without registration for background-thread startup, multiple threads, and foreign registration. They deliberately reject post-load verification when no framework was loaded. Only signed app smoke with the real framework establishes actual replacement and subsequent browser behavior. Test subprocesses never load Chromium or mutate another process.

This target remains outside `ChromiumBridge` and `Native`, preserving existing engine artifact fingerprints. The native framework inputs and ABI do not change for this host startup contract.
