# arx-engine

A macOS-only Swift API over Arx's native bridge to Helium Chromium. The package has no dependencies on Arx's features, services, UI, or domain models.

[Full-document capture](Prototypes/DocumentCapture/README.md) is linked through ABI16 and included in the artifact fingerprint. It captures the current laid-out document with bounded recording, composition and PNG output; unsupported rendering rejects the complete image.

`ChromiumEngine` owns the process runtime and page lifetimes. `ChromiumBridge` declares a versioned C ABI. The independently implemented Objective-C++ source in `Native` is compiled into Chromium with GN; SwiftPM does not compile Chromium. Ardia is a reference, not a dependency.

The source pins and ABI version are in `engine.lock.json`. `make engine-checkout` checks out those exact revisions under ignored `.build/engine`. `make engine-prepare` prepares Chromium, applies Helium's patches, and applies the Arx overlay. `make engine-check` compiles the bridge against Chromium. `make engine-build` checks the bridge, then builds the complete framework with helpers and resources. Set `ENGINE_ARCH=arm64` or `x86_64`; `ENGINE_JOBS` defaults to 8. Compilation preserves a 40 GiB free-space reserve (`ENGINE_MIN_FREE_GIB`) and interrupts only its own build process group if that reserve is crossed; the build can resume incrementally after space is freed. Both architectures require their own build and verification. `make engine-host` bundles a development host with the complete framework; `make engine-smoke` loads a local HTTP fixture in it, checks the title callback and attached view, then quits using a disposable profile. It does not test click/keyboard input, HTTPS, or production signing.

`Licenses/` keeps Helium's `LICENSE` (GPL-3.0) and `LICENSE.ungoogled_chromium` (BSD 3-Clause) unchanged from both pinned repositories: `helium/` from Helium core and `helium-macos/` from helium-macos. Copy them again when `engine.lock.json` moves to new revisions; `Distribution/Licenses/ungoogled-chromium.txt`, which the app's credits show, is the Helium core copy. [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) lists the engine's licences.

`make engine-tools` installs a pinned Python into mise and creates a project-local Python environment. Helium's build needs Python 3.13 with requests and Pillow, curl, zstd, Xcode, and the Metal toolchain. Set `ENGINE_PYTHON` to the Python executable when it is not named `python3.13`. Source preparation downloads Chromium and its toolchains and needs substantial disk space. Interrupted preparation fails with recovery instructions instead of deleting sources. Native edits can be reapplied by rerunning preparation after a successful source preparation.

The build uses Arx's bundle, keychain, and profile identities, and `DEVELOPMENT_TEAM` when supplied. It shows Arx's logo and name, not Helium's (DEV-1100): `Scripts/engine/branding_overlay.py` puts [Branding](Branding/README.md)'s renders at each of Helium's logo destinations, which includes the artwork macOS Now Playing falls back to, and renames Helium to Arx in the string and translation files, with each translation moved to its message's new fingerprint. "The Helium Authors" and `helium://` addresses stay. Preparation stops if Helium's logo or name comes back, and so does `make engine-build` if the built framework bundles Helium's logo or names Helium in its English strings. It does not inherit Helium's team ID or provisioning profiles. The native helpers retain Chromium's sandbox. No command disables sandboxing or certificate validation.

The Swift API can compile and its boundary tests can run without downloading Chromium. Those tests use a test implementation of the C ABI and do not validate Chromium rendering. The main application hosts a page through AppFeature. `make app-smoke` checks that integration separately from the standalone host. A successful native build records a source fingerprint; Xcode embeds only a complete framework matching the current lock and bridge sources.

The host must be an app bundle containing `Contents/Frameworks/Arx Framework.framework/Versions/157.0.8103.78`, including helpers and resources. Loading a framework from an arbitrary external path does not change Chromium’s internal bundle lookup. A host loads the framework executable with `ChromiumRuntime(frameworkExecutable:)`, then calls `run(executable:profileDirectory:onReady:)` before calling `NSApplication.shared` or `SwiftUI.App.main`. Chromium creates its own application class and delegate. In the ready callback it creates pages and attaches their `view` to its UI. The profile directory must belong exclusively to Arx. Runtime shutdown invalidates all pages; a runtime cannot restart within the same process.

HTTP, HTTPS, and `about:blank` navigation are exposed by the native bridge. With extensions enabled, navigation also accepts an enabled extension’s exact `chrome-extension` origin in its actual ordinary profile. Profile-scoped inventory and allowed enable/disable/remove are available. The staged manifest-defined options host requires exact inventory authority; action popups, installation/update consent, native messaging and production distribution have separate acceptance gates. Progress and decisions belong in the [Arx MVP project](https://linear.app/capturecontext/project/arx-mvp-351b79e06a5a).

Helium and Chromium retain their upstream licenses. Shipping a built engine also requires the corresponding source and third-party notices; this package does not grant a separate license to those sources.

## Development binary cache

Another Apple Silicon Mac can run `make engine-fetch`, then build the Swift app without compiling Chromium. The complete framework is verified against the engine source fingerprint and archive checksum and extracted outside the source checkout. See [Artifacts/Engine](../../Artifacts/Engine/README.md). `make engine-cache` refreshes the archive from a completed local source build. This is a development transport, separate from future engine versioning and production distribution.

ABI 3 adds off-the-record context preparation/release and HTTP-cache-clearing reload. Private contexts use unique Chromium OTR identities. Releasing a private browsing identity detaches it immediately, so explicit repreparation starts with fresh storage. The retired native context is destroyed through ProfileDestroyer after its downloads terminate and queued notifications drain. The Swift runtime rejects reuse of a released private identity until explicitly prepared again, preventing fallback to disk-backed profiles.

ABI 4 adds profile-owned download observation and cancellation. Borrowed native snapshots are copied before delivery to Swift. Download GUIDs, target paths, progress, safety state and terminal results come from Chromium; the app never infers completion from file existence. Observer lifetime is independent of WebContents. A closed private window's retired OTR context remains alive until its transfers and posted notifications finish; a newly prepared browsing context with the same logical key is independent. The service and UI policy is described in [DownloadsFeature](../features/Sources/DownloadsFeature/README.md).

ABI5 adds bounded existing-viewport capture and cancellation. It preserves page layout and uses a single physical copy/encoding slot, document and geometry checks, a deadline, and copied immutable PNG output. The service rechecks the original tab revision and current authorization. ABI16 adds a separate full-document snapshot with explicit document geometry and raster scale. The app composes this capability through its live factory; controlled pixel fixtures verify rendered output separately from mock ABI tests.

The standalone smoke uses an explicit ABI5 mock-Keychain option restricted by its host to a fresh owned loopback fixture. Both verified load/shutdown and a native mock-mode marker are required. This avoids an OS authorization dialog blocking an unattended test, but does not validate production Keychain persistence or security. Normal app startup and `make app-smoke` keep the real Keychain. `ChromiumHostTests` covers the disposable-fixture boundary without loading Chromium.

`ChromiumBootstrap` implements guarded first-entry allocator preparation using exact pinned Chromium source. It refuses non-main or already multithreaded startup and foreign registrations, then verifies the delegating zone before framework loading and PartitionAlloc after loading. Failed preparation stops with a native diagnostic before AppKit initialization; ordinary successful startup stays quiet. Call `ChromiumRuntime.prepareHostAllocator()` before Foundation configuration, and stop on false. Host-only sources do not change the native ABI or framework fingerprint. See [bootstrap contract](Sources/ChromiumBootstrap/README.md).

ABI7 provides opt-in profile-scoped extension inventory and revision-checked enable/disable/remove. `make extensions-smoke` exercises only the compiled-in MV3 fixture in native-owned fresh storage. Ordinary app startup supplies the capability; permission escalation is refused, and no Web Store services are enabled. Restart, popup/options, updates and native messaging remain separate acceptance gates. See [native boundary](Native/README.md) and [fixture host](Sources/ChromiumHost/README.md).

ABI8 adds synchronous ordinary-media identity validation at the final focus boundary. It reads the live observer before queued Swift events drain; it does not activate or refresh anything.

ABI9 adds document-bound automation close approval and atomic consumption. The optional service capability has no fallback to unguarded destruction. `make close-smoke` checks real approval, cancellation, wrong-page/replay rejection, immediate navigation/reload invalidation and surviving pages in disposable storage. Native fixtures and Swift/policy tests cover different boundaries; source compilation alone is not native acceptance.

ABI11 adds bounded semantic inspection of loaded ordinary HTTP(S) main documents. Snapshots declare their renderer document and DOM version; opaque references require fresh renderer validation and never authorize a later action. Password/form values, generated names and unsupported surfaces are omitted. Native page/document/scope checks protect final delivery, while renderer handles, physical requests and serialized output have separate limits. See the [inspection contract](Native/inspection/README.md) for privacy, lifetime and soft AX-work versus hard output bounds.

ABI25 adds `inspect_frame`: windows, frames, opt-in form values and bounds. A document projects up to 16384 nodes and each window emits at most 512 from `window_start`, with `totalNodes` and `windowStart` in the result. Windows of one DOM version concatenate. Iframe nodes carry the child frame's ID. The browser maps the renderer's local or placeholder token to the child RenderFrameHost, and only active ordinary HTTP(S) frames of the primary page outside fenced trees are inspectable. Each frame keeps its own renderer pipe, snapshots and references. A newer read of a frame retires only that frame's references, actions route to the snapshot's frame, and a subframe navigation or deletion retires only that frame's work. Form values are opt-in. Password ancestry, file, hidden and `cc-*`, `one-time-code` or password-autocomplete inputs are never read, and checkboxes and radios report only `checked`. Bounds are main-widget viewport points, and out-of-process frames carry none. `make inspection-smoke` verifies windows over a 1500-paragraph page, a same-origin and a cross-site frame with in-frame reference validation, and value privacy, in owned disposable storage.

ABI26 adds three entry points: `capture_offscreen`, `request_pdf` and `cancel_pdf`.
- **Offscreen capture.** A page that isn't in a visible window is kept rendering while hidden (Chromium's hidden capturer count) and its viewport is copied. A page that was never attached is hosted in an ordered-out borderless window for the copy, sized 1280×800 points if it never had a size, and returned detached afterwards. Nothing is shown, focused or selected. A copy that returns an evicted surface, or whose viewport, pixel size or scale changed by the time it was copied or encoded, is copied again until the deadline; only a different document fails it as stale. Chromium's `PrimaryMainFrameWasResized` doesn't fail an offscreen copy, because it also reports a new surface ID or another display's screen info with no size change.
- **PDF export.** Prints the primary main frame through Chromium's `PdfPrintJob` on the frame's own print pipe. No PrintViewManager is attached, so `window.print()` is unchanged; the page does receive `beforeprint` and `afterprint`.
- **PDF source.** Reads the bytes of a page showing `application/pdf` through the profile's URL loader, with its cookies, preferring the cache.

Private pages are refused unless the request sets `allows_private` (ABI56, DEV-971), which only the app's own Print and Save as PDF do; the export and a PDF document's bytes stay in memory. One PDF job runs at a time, and the result is capped at 32 MiB. `make inspection-smoke` verifies capture of an ordered-out and a never-attached page, PDF export, and PDF source bytes against an owned PDF fixture.

ABI31 adds page dialogs (DEV-680). Each page's interactive JavaScript dialogs go through a `PageDialogs` wrapper around Chrome's app-modal dialog manager, which remembers the alert, confirm, prompt or beforeunload dialog it is showing; Arx's own permission sheets register per page the same way. `page_dialog` reports the JavaScript dialog first (it blocks the renderer), otherwise the permission sheet, with a token, its kind, the bounded message, a prompt's default text and a permission's origin. `answer_page_dialog` accepts or dismisses that exact dialog through `HandleJavaScriptDialog` or the permission delegate; prompt text applies only to an accepted prompt. A permission accept allows this time when the permission supports it, otherwise allows; a dismiss never blocks it. The user can still answer either, and whichever answer comes first wins. Unattended runs suppress JavaScript dialogs as before. `make inspection-smoke` verifies an alert, a declined confirm, a prompt answered with text, beforeunload declined (the page stays) and then accepted (it navigates), a dismissed geolocation prompt and an accepted window-management permission against real Chromium.

ABI56 lets the app draw site permission prompts (DEV-963). `ChromiumRuntime.setPagePromptsHosted(true)` hands them over, `onPagePermissionPrompt` reports a page's current prompt token (0 once it's gone), `ChromiumPage.permissionPrompt(token:)` reads it as a `ChromiumPagePermissionPrompt`, and `answerPermissionPrompt(_:decision:accuracy:)` answers it. The engine rechecks every answer as its own sheet would; off, the default, nothing changes.

ABI57 adds `evaluate_translation_script` (DEV-996): the app's page translation scripts run like `evaluate_script`, but in Arx's translation world, a second isolated world with the developer world's credential hooks, and private pages are accepted, so private windows translate. Agent scripts still never reach a private page. `ChromiumRuntime.evaluateTranslationScript` wraps it.

ABI58 (DEV-1009, staged; DEV-996 holds 57 and the coordinator assigns the batch's release number) handles pages that stop answering. `page_unresponsive` is 0 while a page answers, else the number of its current hang: Chromium reports a visible page that left an input unanswered for 15 s (`RendererUnresponsive`), and while a DevTools client is attached, which makes Chromium ignore hangs (DEV-924's request capture), the engine pings a visible page every 5 s in Chrome's internal world and counts 15 s without an answer. `wait_for_page` asks Chromium to check again (a hang still there comes back with a new number), and `end_page_renderer` ends the page's renderer process, as Chrome's Exit Page does. `ChromiumPage.Navigation.unresponsive`, `ChromiumRuntime.waitForPage(_:)` and `endRenderer(_:)` wrap them. `make hang-smoke` checks it against a loopback page that loops on a key. DEV-1016 adds `page_renderer_end`: why a page's renderer last ended, as its number, Chromium's termination status (`ARX_RENDERER_END_*`), the process's exit code and whether the engine ended it itself; `ChromiumPage.Navigation.rendererEnd` reads it on each `page_changed`.

ABI60 (DEV-1111, staged; the coordinator assigns the release number) reports the hovered link for the app's link status: `page_link_hovered(page, document_generation, url, url_size, flags)` posts the link Chromium's status bubble would show (`UpdateTargetURL`, any frame), without its user name or password, or no link once the pointer leaves it or a new document commits; `ARX_HOVERED_LINK_CROSS_SITE` says it's an http(s) link to another site, by ABI43's own test. Swift exposes it as `ChromiumRuntime.onLinkHover` with a `ChromiumHoveredLink`. DEV-1118 adds where a plain click on it navigates (`ARX_HOVERED_LINK_TARGET_KNOWN`, `_NEW_CONTEXT`, `_IN_SUBFRAME`; `ChromiumHoveredLink.target`), from the link's target as its frame reads it. See [native boundary](Native/README.md).

ABI32 adds media seeking, page audio mute and an on-demand position read (DEV-690). Snapshots gain a seek capability when the media session offers SeekTo (controllable media that isn't live). `seek_media` seeks the exact source generation and revision to an absolute time through `MediaSession::SeekTo`, clamped to a known duration, and completes through `media_completed` once the session's position reaches the target. `media_position` reads the session's position, duration and rate once, extrapolated to the time of the read, plus the page's audio mute; position never enters the snapshot, so nothing streams per frame. `set_page_audio_muted` uses `WebContents::SetAudioMuted`. Per-tab volume (DEV-800) is the separate export `ArxEngineSetPageAudioVolume`, outside the ABI table, so older engines still load without it. Chromium removes a muted page's playing player from its media session (outside PiP), so that source disappears until the page is unmuted. Private pages are refused. `make app-smoke` checks a seek on paused media, the position read, and mute and unmute while playing against the owned media fixture.

ABI33 adds `start_download` and its `download_started` reply (DEV-670). It downloads an http(s) URL without credentials in an ordinary observed profile through `DownloadManager::DownloadUrl`, with no page or frame, as a link download the user approved (`CONTEXT_MENU` source, not content-initiated, no login prompt), so Chromium's destination, prompt preference, safe-browsing, dangerous-file and insecure-download checks all apply. The reply comes once, after the item's first `download_changed`: the new GUID, Chromium's interrupt reason when no item was created, or a timeout after 30 seconds, after which a late item is cancelled. Private profiles are refused. `make app-smoke` starts, lists and cancels a real download through MCP.

ABI34 adds the developer tier (DEV-668): `evaluate_script` runs an agent's script in Arx's developer world, an isolated world of the page's main frame where Blink keeps cookies, password, card and one-time-code values and stored credentials unreadable, and awaits a JSON-serializable value. `set_developer_log` and `read_developer_log` keep a page's console and sanitized network log natively, at most 500 entries each, and read them on request, so nothing streams to Swift. Replies redact the page's cookie values. Private pages are refused. See [native boundary](Native/README.md).

ABI30 adds held file choosers (DEV-679). Arx's page delegate now implements `RunFileChooser`. A single or multiple file chooser that a page opens within 3 seconds of an admitted pointer or keyboard action on that page is held instead of cancelled; every other chooser, including folder and save choosers, is still cancelled. `page_file_chooser` reports the held chooser (token, multiple, accept types) and `answer_file_chooser` answers it once with absolute paths, at most 32 and one unless multiple, or cancels it with none. The app checks each file and gets the user's approval first; native code only rechecks path syntax and does no file IO on the UI thread. A held chooser is cancelled after 60 seconds, on navigation and when the page closes. Pointer clicks may now target file inputs. `make inspection-smoke` verifies a pointer click that holds a chooser, an answer the page receives as a `change` with the file's name and size, a cancel the page receives as `cancel`, and a second answer to the same chooser refused as stale.

DEV-1309 shows a person's own file choosers. Before it, every chooser that wasn't held for an automation action was cancelled, so no file input or upload button worked in Arx, and no panel ever opened. Now a chooser opened outside the automation window goes to Chrome's own `FileSelectHelper` in an interactive run: the macOS open panel (or the save or folder panel) as a sheet on the page's window, with the page's accept types, the last folder used and Chrome's checks. An unattended run still cancels it. The page delegate also lists a chosen or dropped folder through `FileSelectHelper::EnumerateDirectory` and reports its window's frame through `GetWindowBoundsInScreen`, so Chrome's 400 by 300 minimum for a file dialog measures the window, not a small page in it. Nothing in the ABI changes. `make inspection-smoke` clicks a plain file input, a button that opens a detached input from script and the same button in a cross-site frame with window events, not automation actions, and requires the open panel for each, which it cancels and the page sees as `cancel`. It also drops a file on the page's drop zone through the view AppKit's own lookup picks, and requires the page to get the file's name and size.

ABI29 adds explicit form state (DEV-678) as form kinds `ARX_FORM_SELECT_VALUES` and `ARX_FORM_SET_CHECKED` over a `FormStateAction` Mojo method. Select-values makes a JSON array of up to 64 exact option values the whole selection of a native multiple select; each must match exactly one option, and a disabled option that would become selected is refused. Set-checked gives a checkbox or radio an explicit state with input and change events and clears a checkbox's indeterminate state; a radio can't be unchecked. Both check the snapshot's DOM version, password ancestry, disabled and inert state and layout in the same task, and return `ARX_FORM_UNCHANGED` without any event when the state already matches. `make inspection-smoke` verifies a checkbox, a radio group, a refused radio uncheck, a multiple select, an order-insensitive unchanged selection and refused disabled and unknown options against real Chromium.

ABI28 adds typing and key chords (DEV-677) as form action kinds `ARX_FORM_TYPE` and `ARX_FORM_KEY_CHORD`. Both focus the reference first and consume the snapshot. Typing puts the caret at the end of an input, textarea or contenteditable reference and sends each character as a keydown, keypress and keyup guarded by the existing keypress hooks: text fields reuse the guarded keypress with a fresh baseline per character, and contenteditable uses the same guard with a check that focus and the selection stay inside the reference and away from password ancestry. A redirect stops the rest of the text and reports `possiblyDispatched`. A chord (`"<modifiers>:<key>"`) guards text and editing keys on an editable reference the same way, keeps Blink's defaults for navigation keys (Tab, Escape, Page Up/Down, F1–F12) and for Enter or Space on a control, and lets Control, Alt and Meta chords reach page listeners with every default suppressed, so no clipboard, undo or editing command runs. `make inspection-smoke` verifies typing into an input, a textarea and a contenteditable, a refused line feed in a single-line input, a keydown listener that moves focus into a password field mid-typing, a Control+K shortcut seen only by the page, Tab and Escape closing a modal dialog.

ABI27 adds pointer input and non-consuming hover (DEV-663, DEV-669). The form action entry point takes three more kinds: `ARX_FORM_HOVER`, `ARX_FORM_POINTER_CLICK` and `ARX_FORM_DRAG`, with a canonical ASCII payload (`x`, `y`, `tx`, `ty`, `to`, `clicks`, `modifiers`, `steps`). The renderer checks the reference, document and DOM version, then sends real mouse events through the frame's own widget in the same task; Blink's hit test must land on the reference (or, for a point, the snapshot's document), otherwise the result is `ARX_FORM_OBSCURED`. A drag that starts HTML drag and drop is captured in the widget and completed in the renderer, so no platform drag session starts. Selects, file and color inputs and password ancestry are refused. A dispatched hover keeps its snapshot; the next action still checks the DOM version, so a hover that mutates the page retires its references. `make inspection-smoke` verifies hover, a mutating hover, consuming clicks, double click, an obscured target, a coordinate click, a pointer slider and HTML drag and drop against real Chromium.

ABI16 stages explicit profile retirement through a separate opt-in run entry point and bounded typed snapshots. The default runtime remains unconfigured. Consent-bound targets are quarantined before recording a kernel boot-session UUID and removed only after a later authoritative boot, with exact inode checks across data/cache roots. The Swift API reports retirement, restart pending and verified erasure separately. The isolated app factory now supplies durable root-bound identity and consent integration. Main integration still requires a combined ABI16 build, ownership review and signed packaged startup/reboot acceptance.

Local CRX install/update APIs retain opaque runtime-issued verified candidates through explicit one-use consent. The normal CRX3 verifier, immutable staged bytes, profile/inventory identity, native permission warnings and physical installation ownership are preserved. Production availability is independently advertised and disabled until coordinated native acceptance. `make extension-install-smoke` exercises compiled signed packages in newly owned mock-Keychain storage; wrapper and script tests do not substitute for that runtime gate.

ABI22 gives Arx pages extension window IDs and indexes: the app reports which pages each Arx window shows (its visible space in sidebar order) and extensions then see `windowId`, `index` and window-scoped `tabs.query` and `chrome.windows` results, scoped to the page's own ordinary profile; an extension popup's current window is the window of the page it was opened for. In unattended runs a main-frame HTTP challenge is cancelled like the others, WebAuthn and FedCM prompts are refused and reported per document (`ChromiumPage.Navigation.userActionRequests`), and Chromium's shutdown watchdog reports a forced exit to the app first. See [native boundary](Native/README.md).

ABI21 lets extensions reach Arx pages through the tabs API and cancels unattended HTTP authentication prompts. A Chromium overlay lets the embedder supply tabs outside Chrome's window list; `tabs.sendMessage`, `tabs.get` and `tabs.query` then see the current ordinary profile's own live pages, never another profile's or a private page. In an unattended run a subframe or subresource challenge is cancelled before a login prompt is built and no credentials are sent; `page_authentication_cancellations` reports how many were cancelled for a page's current document (`ChromiumPage.Navigation.authenticationCancellations`). Interactive prompts are unchanged. See [native boundary](Native/README.md).

ABI20 adds developer unpacked extensions: `load_unpacked_extension` loads an absolute folder into the exact ordinary profile named by a current inventory revision through Chromium's `UnpackedInstaller`, and `ARX_EXTENSION_RELOAD` rereads an installed unpacked extension from its own folder through `manage_extension`. New statuses separate a missing folder, an unreadable folder or manifest, and a Chromium load error whose bounded reason arrives as `{"error": …}`. Inventory rows report `canReload` and `sourcePath` for unpacked extensions. See [native boundary](Native/README.md).

DEV-824 adds an optional `iconPath` to every inventory row: the manifest icon nearest 32px, joined to the extension's folder without touching the disk. It is additive JSON, so the ABI version is unchanged; engines built before it leave the field out and the site menu shows letter tiles. `ChromiumExtension` accepts only an absolute path without `..` components.

Its follow-up adds `icons` and `actionIcons`, the manifest's icons and the action's default icons as `{"size in pixels": path}`. `ChromiumExtension` accepts at most 16 sizes of 1 to 4096 pixels, written as plain numbers, each with a path `iconPath` would accept; `ChromiumExtension.iconSizes` keys them by pixels. `ChromiumRuntime.extensionActionIcon(_:on:scale:)` reads `ArxEngineCopyExtensionActionIcon`, looked up at run time outside the ABI table: the PNG of the icon an extension set for the page with `setIcon` or a declarative rule, copied once its size is known and dropped if it changes between the two calls or passes 2 MiB. Engines without these fields or the export give empty maps and nil, and tiles draw `iconPath`. A component extension adds `componentIcon`, its icon's PNG in base64, because its files live in the engine's resources; `ChromiumExtension` accepts it only for a component location and at most 16 KiB decoded (`componentIconData`).

ABI19 adds developer tools: `open_devtools`, `inspect_link_context`, `close_devtools` and `devtools_is_open` host Chromium's bundled DevTools frontend in a separate native window per inspected page, attached through `DevToolsUIBindings` to that page's tab `DevToolsAgentHost` in its own browsing context. `configure_devtools` supplies localized titles and enables Inspect Element on non-link context menus. `reload_bypassing_cache` revalidates one page without clearing its profile cache. See [native boundary](Native/README.md).
ABI19 adds unattended runs: `set_unattended` (before `run`) suppresses page JavaScript dialogs with Chromium's default reply, keeps pages on before-unload, and starts Chromium with occluded-window and renderer backgrounding disabled so a transparent host keeps rendering. `unattended_dialog_count` reports only how many dialogs were suppressed. Sandboxing and certificate validation are unchanged. `Arx --headless` uses it; see the root README.

Native-origin extension options publication carries a short-lived exact page/profile/extension/generation rollback proof. A failed synchronous native post-publication check revokes that offered session before native destruction; navigation, ordinary close, or the next actor turn settles the proof. Repeated or stale revocation cannot close a repurposed page. The engine and AppFeature remove only that owned initial session and the Little Arx made for it (DEV-1185).

ABI35 adds saved passwords (DEV-708): Chromium's password manager runs for ordinary profiles (each its own `Login Data`), never for private pages. `sign_in_credentials` lists the accounts saved for exactly the page's origin, and `sign_in_attempt` fills one through Chromium's `actor_login`, submits the form and reports only an outcome; a password never crosses the ABI. `password_save_offered` and `answer_password_save` replace Chrome's save bubble. See [native boundary](Native/README.md).

ABI36 adds saved passwords in Settings (DEV-721): `list_saved_passwords`, `save_saved_password`, `remove_saved_password`, `reveal_saved_password` and `import_saved_passwords` work on one ordinary profile through Chromium's `SavedPasswordsPresenter` and `PasswordImporter`. Replies carry sites, usernames and counts. `ArxEngineCaptureWholePage(page, request, limits, done, context)` and `ArxEngineCancelWholePageCapture(request)` (DEV-1172), outside the ABI table, capture a shown page's whole height the way DevTools' "Capture full size screenshot" does (`page_capture_bridge.mm`):
- **How:** Arx's own DevTools protocol session sends `Page.getLayoutMetrics`, then `Page.captureScreenshot` with `captureBeyondViewport` and a clip from the document's top-left corner. The clip is in DIP: the CSS size scaled by the browser zoom, which Chromium's own full page screenshot skips. Frames, video, canvas and WebGL come out as they show on screen, and protected video stays blank.
- **What the page sees:** it lays out at its whole height for that one frame, sees the resize, and goes back to its own size before Chromium replies. Its WebContents view clips the grown page view in the meantime.
- **Limits:** the image is cut at `maximum_dimension` (at most 16384 physical pixels, the largest texture Apple GPUs take), then at `maximum_pixels`, and the snapshot reports `cut`. A reply of another size than measured is `ARX_CAPTURE_UNSUPPORTED`.
- **Slot:** it holds the engine's one capture slot. A canceled or timed-out capture answers at once. Once its screenshot is out, it keeps the slot and its session until Chromium's screenshot returns, because Chromium puts the page's size and preferences back just before. A crashed renderer, or a navigation that swaps the page's widget, drops that reply, so those drain at once.
- **Stale and refused:** a navigation, a hidden page, or a change of scale, zoom or page area makes the capture `ARX_CAPTURE_STALE`, and the view follows a page area resized meanwhile. With DevTools open on the page, the capture is `ARX_CAPTURE_UNSUPPORTED`, since the screenshot would reset the device toolbar's emulation.
- **App:** `ChromiumRuntime.captureWholePage(_:limits:)` and `supportsWholePageCapture` reach it. Capture Page and Capture Full Page take it over ABI16's recorded document when it's there, and fall back to that document when it fails; MCP's `fullDocument` keeps the recorded document.

Downloads a quit would lose (DEV-1130) are the export `ArxEngineLostOnQuitDownloadCount`, outside the ABI table, so older engines still load and the app counts only its own list's private transfers. It counts, synchronously on the main thread, transfers in progress (paused ones included) in private contexts, and ordinary ones Chromium couldn't continue from their bytes on disk: no ETag or Last-Modified to ask If-Range with, `Accept-Ranges: none`, fetched through a service worker (which Chromium always restarts), transient or Save Page As. `Scripts/tests/test_private_profile_lifetime.py`'s `lost-on-quit` scenario runs the count on the native code against the download double. A missing Accept-Ranges alone doesn't count, since many servers take ranges without saying so. `ChromiumRuntime.lostOnQuitDownloadCount()` reads it; the quit confirmation warns about them.

Quitting keeps the others (DEV-966). When the profiles go down after a quit, Chromium's download managers cancel every transfer still in progress, paused ones included, delete its partial file and record it as cancelled (`DownloadManagerImpl::Shutdown`). `StopAllDownloads`, which runs only at quit and before that teardown, removes Arx's observers, then pauses and interrupts (`DOWNLOAD_INTERRUPT_REASON_CRASH`) each ordinary transfer that Chromium can continue and that is writing to its intermediate file. The overlay adds `DownloadItemImpl::IsWritingToIntermediateFile()`, since every other internal state also reads IN_PROGRESS and Chromium would ignore or refuse the interruption there. The pause writes the transfer's progress to the profile's in-progress download database at once; an interruption alone waits for a 10-second timer that never fires during teardown. The interruption keeps its bytes on disk and makes the cancel skip it, and the next launch reads the paused entry back as interrupted and resumable. Chromium lets go of the file on the download sequence, whose tasks the thread pool skips at shutdown, and a skipped one would delete it. So the quit waits, at most 3 seconds, for that sequence to reach a task posted after the interruptions. The app hears nothing of it until then. One with all its data is finishing and has nothing to resume. A dangerous or insecure transfer waiting for a decision keeps Chromium's cancel, which deletes its file. So does every transfer of a profile torn down while Arx runs (a private window closing, an erased profile), which goes through `StopDownloads`. `Scripts/tests/test_private_profile_lifetime.py`'s `quit-interrupts` and `teardown-cancels` scenarios run both against a manager double that shuts down in Chromium's order; the app smoke's download resume launches cover it end to end.
