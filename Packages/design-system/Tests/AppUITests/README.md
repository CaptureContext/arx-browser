# AppUITests

Tests AppUI's accessibility presentation and sidebar rendering with Swift Testing, without running VoiceOver.

- `ContrastTests` reads the color assets and checks WCAG 2 contrast in light and dark appearance: primary text on the sidebar at every chrome tint, and dimmed text and icons under Increase Contrast.
- `RenderCountTests` (DEV-902) holds the command bar, the window chrome and Settings to render-count ceilings, counted through `RenderTrace`: moving the command bar's selection or changing its results, another tab's title, a navigation and a load in the chrome, and one Settings switch or a value in another pane. Each ceiling is today's count; lower it when a change renders less. The tests print each count. They need a window server.
- `SidebarRenderCountTests` hosts a sidebar of 71 rows in a window kept off every screen and counts row body evaluations: a selection change, rename or new tab runs only the rows it changes, and an unchanged row still sends to the newest action handler. They need a window server.
- `SidebarScrollCostTests` (DEV-1235) measures what one frame of scrolling the sidebar's list costs the main thread: it hosts a sidebar of 400 open tabs off screen, scrolls it a step at a time and prints the steps' median, p90, p99 and worst milliseconds, with the main thread's CPU time and instructions per step beside them. Compare instructions when the Mac is busy: wall time doubles under load and they don't move. It prints numbers and asserts nothing, so it only runs with `ARX_SIDEBAR_SCROLL_COST=1`; run it on a Release build (`swift test -c release -Xswiftc -enable-testing --filter SidebarScrollCostTests`) and on both sides of a change. `ARX_SIDEBAR_SCROLL_TABS`, `ARX_SIDEBAR_SCROLL_STEP` (points a frame), `ARX_SIDEBAR_SCROLL_PASSES` and `ARX_SIDEBAR_SCROLL_REACH` (stay within that many points of the top) shape the run. It measures the main thread only, not what the window server spends on the blurred edges. Its `switchingSpace` (`ARX_SIDEBAR_SWITCH_COST=1`, and `ARX_SIDEBAR_SWITCH_JUMPS=1` to slide past several spaces at once) hosts the pager with six spaces and reports the worst frame of a space switch while the sidebar slides and the worst once it rests. `SidebarPagerRenderCountTests` holds the fixes they led to: a scroll near either end of the list runs neither the pager's body nor the sidebar's, selecting the next space builds no row, a slide past several spaces builds only the one it lands on, and the selected space's neighbours and the last few spaces visited stay mounted. `SidebarPagerMountPlanTests` covers which spaces those are, a step at a time. `jumpingQuickly` (DEV-1310, `ARX_SIDEBAR_QUICK_JUMP_COST=1`) prints the worst frame of each of five jumps to the next space made 180 ms apart from a rested sidebar, each space one never visited: a jump to a space that isn't built ahead builds it in that frame.
- `CommandBarSiteIconFetchTests` (DEV-1311) hosts the command bar with a recording icon loader: listing bangs and highlighting each of them read only stored icons, a visited page's row may fetch as before, a scoped search lets the field fetch its site's icon once, and leaving the scope asks only for the stored icon again. An offscreen window never ends a replaced view's task, so the fetch stopping is the cache's test. It needs a window server.
- `SidebarSiteIconDemandTests` (DEV-940 follow-up) hosts the docked sidebar with a recording icon loader: at launch only the shown space's on-screen rows and its Favorites may fetch, the mounted neighbouring spaces and other profiles' Favorites read only stored icons, rows far below the fold and a collapsed folder's rows ask for nothing, switching space or opening a folder fetches what then shows, and a hidden sidebar fetches nothing.
- `SidebarKeyboardNavigationTests` covers where the arrow keys take focus: reading order past collapsed folders, the list's ends, and the folder rules for ← and →.
- `AccessibilityTextTests` covers what VoiceOver reads for sidebar rows (kind, selected or expanded state, folder nesting) and command bar results.
- `ArxControlsTests` checks the controls' corner rule and size mapping. `ArxControlsSnapshotTests` writes PNGs of every control in every state, the raised button and group included, in light and dark, when `ARX_DESIGN_SNAPSHOTS` names a directory, and Settings' drill-down rows at rest, hovered and pressed (DEV-773). `CommandBarKeyHintSnapshotTests` does the same for the command bar's "Ask an agent ⇥" hint, at rest and hovered, alone and in the palette and address field, and with a long address in the live field. `CommandBarHintLayoutTests` (DEV-954) checks that the field ends where the hint begins in the palette and the address field at narrow and wide sizes, takes the full width without the hint, keeps the end of a long address and its caret in view when the hint comes in or goes while it's being edited, and that the hint's worked-out width matches its layout. It needs a window server. `URLBarSnapshotTests` draws the URL bar's copy-link and site-menu buttons in the sidebar and Little Arx layouts. `SidebarTopStyleSnapshotTests` draws the URL bar idle, hovered and focused and the Favorites grid with and without an open favorite on the chrome, in the default, a strong and a neutral tint; `URLBarActionVisibilityTests` checks when the URL bar's actions show (DEV-788).

Listening with VoiceOver, keyboard walkthroughs and input methods stay manual checks.

Every suite that lays out AppUI views takes `.renderTurn` (DEV-1080). `RenderTrace` and `SidebarRenderTrace` each keep one count for the whole process, and a hosting test spins the main run loop to let SwiftUI settle, which runs any main-actor test that is waiting. Without the turn, a pager laid out by another suite during a navigation recording added its two history arrows to `RenderCountTests`' counts on a busy machine. A new hosting suite takes the turn too.

`ChromeSplitButtonSnapshotTests` draws the chrome split button beside the URL bar, at rest and with each part hovered and pressed, in light and dark (DEV-768).

`ArxToastSnapshotTests` draws toasts over a page card in two chrome tints, with and without actions, in light and dark (DEV-769). Its `windowCorner` render puts one at a browser window's corner, under a transparent title bar. `ArxToastPlacementTests` checks that `arxToast` measures its insets from the view's edges, not its safe area, so a toast in a titled window sits as far below the top as in from the trailing edge (DEV-823).

`SidebarLibraryFilterSnapshotTests` draws the Library's Filter button (quiet, open, counting, symbol only) and its chips at rest, hovered and pressed, in light and dark (DEV-770).

`LocalTabSnapshotTests` draws local-network tab rows, selected and not, beside ordinary ones and with the highlight off, and the developer header over a square-cornered viewport, in light and dark (DEV-786).

`SidebarMediaPanelSnapshotTests` draws the Library's Media page with media playing, paused and muted, and in ArxPiP, and with nothing playing, in light and dark (DEV-783).

`SidebarTabAudioSnapshotTests` draws tab rows with their speaker (playing, muted, turned down), the speaker's volume popover and Media rows with volume sliders, in light and dark (DEV-800). `SidebarTabAudioTests` checks when the speaker shows and which symbol it draws.

`SidebarSplitSnapshotTests` (DEV-1006) draws a pinned split row in Pinned, one in a folder, and a split of a Favorite and an open tab with the tile and the row both highlighted, light and dark, when `ARX_DESIGN_SNAPSHOTS` names a directory. `SidebarDropLayoutTests.theMiddleOfAPinnedTabsRowFormsASplit` checks that the middle of a pinned or folder tab row forms a split while its edges still reorder.

`ArxHeaderBarSnapshotTests` draws the header bar (DEV-782, DEV-790, DEV-797) with Close and Back squircles, with text controls, a pane's bar with its icon tile, its search collapsed, expanded empty and holding a query, a narrow bar whose title truncates before its controls, every raised control (square and text buttons, a grouped pair, `ArxSegmentedControl` and the search button) at rest, hovered, pressed, disabled, focused and selected, a segment's tooltip, the expanded search, the chat panel's controls at its size, the chat composer's + tile, `ArxModalScaffold` at rest and scrolled under its bar, and a bar over a translucent surface at rest and scrolled (DEV-806), in light and dark. Hover and press show the inset squircle. Offscreen drawing doesn't render the system's soft scroll edge (DEV-807), so content under a scrolled bar shows sharp there; `ArxScrollEdgeTests` checks the edge in the layer tree instead.

`ArxScrollEdgeTests` checks that `ArxScrollEdgeFade` is off at rest and grows in over its height as content scrolls under a bar (DEV-763, DEV-782), and that `arxScrollBar` gives its scroll view AppKit's soft top pocket, as tall as the bar, with its variable blur and its separator off, read from the view and layer tree offscreen (DEV-807). It also scrolls 60 steps and checks that the separator hider looks at the pockets at most twice while the pocket stays the same with its separator off, and that the feature flags in `ArxScrollEdgeOptions` read as documented (DEV-808). It also lays two bars side by side in one Settings-style window and checks that each pocket has a backdrop group of its own, which its blur draws in (DEV-808). It checks that `ARX_SCROLL_EDGE=progressive` selects the progressive blur, that its mask is opaque down to its ramp and eases to clear across it, that it's off at rest and comes in over the first 24 points of scrolling, and that a bar drawing its own edge hides AppKit's pocket, which otherwise blurs the bar's height with a hard cut. It checks that the progressive edge is the default and replaces only the top edge: the bar's pocket is hidden and its blur drawn, while a modal footer keeps the system's soft edge with its separator off. The other tests host their views with `ArxScrollEdgeOptions.soft` through the `arxScrollEdgeOptions` environment value, to check the system's edge. It checks that `ARX_SCROLL_EDGE_TUNER=1` turns the progressive edge on with its tuner, that the tuner's values list one per line and reset to the built-in ones, and that the blur takes a new radius live.

`SiteIconPlaceholderTests` checks that a site tab with no icon shows the placeholder, a loaded icon wins, and chats, folders, keyless items and views that don't opt in keep their symbols (DEV-809).

`TourSiteGlyphTests` checks that the tour's sample favicons round-trip through an item's `symbol` and that no other symbol is read as one (DEV-791).

`OnboardingTourSnapshotTests` writes each tour page at its demo's key frame, light and dark, at the onboarding window's size, when `ARX_DESIGN_SNAPSHOTS` names a directory (DEV-1300).

`BrowserEmptyPageSnapshotTests` draws a pane with no page, which shows the Arx mark in place of the globe, in the default and a strong chrome tint, and the Settings tiles with the Arx pane's mark beside symbol tiles, in light and dark (DEV-829).

`AppLinkFieldsSnapshotTests` draws an App Links handler's fields with an app picked and its "Catches …" line, empty with its prompts, and with a web scheme and the rule it breaks, and a Run script route empty, filled and with a long failure, in light and dark, when `ARX_DESIGN_SNAPSHOTS` names a directory (DEV-862).

`AppLinkPromptSnapshotTests` draws the portrait app link prompt (DEV-872), Land with its script shown and Always allow and Open "App"?, in light and dark, when `ARX_DESIGN_SNAPSHOTS` names a directory.

`PagePromptSnapshotTests` draws the site permission prompts (DEV-963) one by one and side by side: notifications; camera and microphone with Allow Once; location with Allow Once and its accuracy; an upgrade to precise location; clipboard from an embedded frame. It writes `page-prompt-<kind>-<appearance>.png` and `page-prompts-<appearance>.png` in light and dark when `ARX_DESIGN_SNAPSHOTS` names a directory.

`LinkStatusToastSnapshotTests` draws the link status (DEV-1111) at a page card's bottom-left corner, light and dark: a short and a long address (truncated in the middle), both inside an action, and a download.

`SidebarDropLayoutTests.aTabGroupsRowTakesADropIntoTheGroup` (DEV-911): a tab group's row takes a drop into the group in its middle and before it at its edge.

`SidebarPressActivationTests` (DEV-914, DEV-976, DEV-994): the flag is on unless set to `0`, `false`, `no` or `off`. With it off, a press registers nothing and installs no monitor, and real mouse events on a row and a Favorite tile select nothing on the press and select on release. With it on, a plain press on a hovered, unselected tab selects it once and its click then does nothing more; modified presses, double-clicks and a row the pointer left wait for release. One serialized suite, since the flag and monitors are app-wide.

`SidebarLiveCalendarTests` (DEV-804): overlapping events share their group's lanes and events that only touch don't. `SidebarLiveCalendarSnapshotTests` writes the Live Calendar card, light and dark, when `ARX_DESIGN_SNAPSHOTS` names a directory: a made-up day with all-day and overlapping events at 2:20 PM, a read that failed, and one still loading.

`SiteMenuSnapshotTests` draws the site menu with two hidden elements (DEV-1019), one with a selector too long for its row, in light and dark, when `ARX_DESIGN_SNAPSHOTS` names a directory.

`SidebarRowMotionTests` checks when sidebar rows and Favorites animate (DEV-1187): new, closed, moved and revealed rows spring; another profile's Favorites, the first fill, a drop landing in Favorites and Reduce Motion change at once; a collapsing space and the flag off keep the change's own animation. Its hosted suite reads the decisions a real BrowserSidebar and FavoritesGrid take, in Debug builds. `SidebarRowMotionSnapshotTests` writes a new tab sliding in and a closed tab collapsing out as frame strips (50 ms apart) and 50 fps GIFs, in light and dark, when `ARX_DESIGN_SNAPSHOTS` names a directory.

`TabSwitcherScrollingTests` hosts ⌃Tab's switcher off screen and checks that its list keeps the card's inset at both ends, scrolled to the last tab and to one the arrows reach, as DESIGN.md › Lists says (DEV-1318).

`TabSwitcherSnapshotTests` draws ⌃Tab's recent-tab switcher (DEV-544) over a page card, the previous tab chosen, with a tab of another space, an unloaded tab, a chat tab and a long title, in light and dark, when `ARX_DESIGN_SNAPSHOTS` names a directory.

`SidebarHoverPanelTests` place the hover card beside its row and check the hover delay: a second before the first preview, none with Shift down (DEV-1029) unless `ARX_SHIFT_HOVER_PREVIEW` is off, or right after another preview closed; the flag is registered and on by default.

`SidebarHoverPreviewOwnerTests` keep a window to one hover preview (DEV-1288): moving the hover from folder to folder, then to a tab, a Favorite and the Library's downloads, shows exactly one at every step, the old one ordered out before the new one shows; a held preview (search engaged, keyboard, pointer on it) refuses one a passing pointer opened at once and gives way to a settled one.

`HideElementToastHoldTests` and `HideElementToastClickTests` (DEV-1315): Hide Element's toast holds its place, solid, while the pointer is over it, whatever is outlined; and clicks on a grid across the whole toast, collapsed and open, over a stand-in page view that takes the first click, in a window that isn't key, reach the toast and never the page, while each control answers. The click tests need a window server. `HideElementToastSnapshotTests` also writes `hide-element-pointer-over-toast-{before,after}-*` (the reported state and the fixed one) and `hide-element-faded-over-footer-*` when `ARX_DESIGN_SNAPSHOTS` names a directory.
