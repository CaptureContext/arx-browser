# AppUI

Provides native shared browser presentation and exports LocalUIExtensions.

## Boundaries

May depend on core, dependencies, and extensions. Must not depend on services or features.

## Public surface

UnavailableContentView presents a caller-supplied title, symbol, and description. It does not interpret browser engine state; that belongs to ViewerItemFeature. Exports.swift exposes the selected shared UI foundation. AppUI attaches package-resources-cli’s build plugin from `Forks/package-resources-cli`, whose declared inputs make incremental builds update generated declarations. Its `.packageresources` configuration generates public typed accessors for the module-owned color and string catalogs; generated Swift stays in build output. `_PackageResources` is re-exported for `Color.resource`, `String.localized`, and `Text(localized:)`. Add images to the target’s asset catalog to obtain generated image accessors through the same plugin.

BrowserSidebar composes URLBar, FavoriteTile, and recursive SidebarRow views. SidebarItem is a presentation value with stable tab/folder identities; SidebarAction reports user intent to the owner. Sidebar rows use native typed drag sessions with a stable insertion line: a two-point rule with a small ring at its leading end. SidebarDropLayout resolves both the preview and committed move from the same pointer coordinates; rows never rearrange during a drag. A folder's middle accepts nesting, while its upper and lower edges accept insertion. Horizontal pointer position chooses indentation at subtree boundaries, including appending after the final child of an expanded folder. The regular-tab area accepts before-row and end-of-list drops, including the blank area below its last row and empty lists. New Tab is excluded from drop targeting. A folder only expands after a 650 ms hover over its center, and fills with the accent while a drop would land inside it. Typed transfers bridge favorites, rows, folders, and spaces. Drag sources allow moves within the app and disable exporting identity-only payloads to other apps. The caller validates and applies moves. Tab rows use a continuous 10-point radius for selection, hover, and drag previews. Their trailing button appears only on row hover, with its own hover background. `isAtInitialState` and selection choose between reset, remove-pin, and close actions. Hosts reset a pinned page to its saved destination and clear its cached navigation state without deleting the pin. Hosts declare `dev.capturecontext.arx.sidebar-item`, conforming to `public.data`, in their exported UTIs; the preview's XcodeGen spec supplies this declaration. A change in the tab tree runs only the bodies of the rows it changes (DEV-732): BrowserSidebar hands its rows an `Equatable` input and one `SidebarActionRelay`, which keeps its identity while carrying the window's latest `onAction`, `sidebarTabHoverChanged` and `browserLinkActions`. Rows read none of those from the environment, because the window sets new closures on every pass, and BrowserSidebar reads the hover and link handlers only in `SidebarRelayEnvironment`, an empty view that hands them to the relay, so new closures run no BrowserSidebar body either (DEV-937). `SidebarRenderTrace` emits a Points of Interest signpost for each row body, and for the pager's and each BrowserSidebar's body, and in Debug counts them for tests. `RenderTrace` (DEV-902) does the same by name for `CommandBar` and its result rows, `URLBar`, `BrowserHistoryControl`, `BrowserChromeBackground`, `SettingsSection`, `SettingsRow` and `SettingsToggle`. Rows sit in a `LazyVStack`, so a space builds only the rows on screen, and measure their frames (`SidebarRowFrames`) only while a drag needs them: while the window's `SidebarDragPreviewModel` has a drag, or a drop session is over the list, whose placement is worked out again once the frames arrive (DEV-937). BrowserSidebar also owns keyboard focus among its rows, a `FocusState` over `SidebarItem.ID` (DEV-731). ↑ and ↓ move it through the visible rows in reading order, children of collapsed folders left out. → expands a collapsed folder or moves into an expanded one's first child, and ← collapses an expanded folder or moves to a row's parent, as in Finder's list view (`SidebarKeyboardNavigation`). Moving focus never selects a tab; Space still does. Split View rows are skipped, since each member takes focus on its own. Keyboard focus draws the accent ring Favorites use, a click's focus none, and the list scrolls to keep the focused row in view.

`SidebarItem.isUnloaded` (DEV-873) fades a tab row's icon and title to `BrowserMetrics.Row.unloadedOpacity` while it isn't selected, and VoiceOver reads it as an unloaded tab.

`SidebarItem.keepLoaded` (DEV-932) is a web tab's site and whether its profile keeps it loaded; tab rows and Favorite tiles then offer Always Keep This Site Loaded as a checked menu item that sends `setSiteKeptLoaded`.

SidebarPager keeps a shared 40-point toolbar above the horizontally paged spaces. it hosts the window’s native close/minimize/zoom buttons and the sidebar toggle on the leading edge and right-aligns back, forward and reload on the same centerline, with 16-point symbols, 28-point hover targets and a draggable background. The native controls move with a collapsed or hover-revealed sidebar and return to their original parent when the host is removed. The URL bar, favorites, and workspace disclosure form each space’s pinned header. Scroll geometry brings in Arx's progressive edge (`ArxProgressiveEdge`, the chrome veil) under the header only when rows pass underneath (DEV-826). Collapsing a workspace hides its saved tree while retaining the active saved tab; open tabs stay visible. SidebarFolderIcon animates its front flap between closed and open shapes.

An optional SidebarLibrary replaces the spaces with a rail and a panel, reached by swiping past the first space or from the switcher's first button. SidebarTrack is the one axis behind both: a swipe moves it by measured numbers, measured frame by frame (DEV-1310, `SidebarTrackSwipeTests`): where the track stands is a function of how far the fingers have gone since they came down and of nothing else, half as far as they go (`follow`), one stop either way from where the swipe set out (the stop the track rested on, or the one it was landing on when the fingers caught it), and past that, or past the last space, a give that grows ever more slowly and never stops dead (`give(past:stiffness:)`, 14 points for 200 of fingers; softer toward a Create a Space page on offer, which opens only from the last space); only the track's first stop, the open Library or the first space without one, is a firm stop, since nothing shows past it. Let go while the fingers were still moving in the last 60 ms, at 5 points a second or more, and the track goes on the way they were going, one stop past a slide they caught going the same way, so a second quick swipe reaches the space after the first one's; let go held still, it goes to whichever stop shows more. Every landing is on one critically damped spring that starts at the speed the track had, whichever way it was going, held only to the fastest that doesn't pass its stop, and runs frame by frame, so another swipe can catch it anywhere. `SidebarTrackView` reads a swipe as across or along the sidebar once the fingers have gone 3 points, not from their first move, and a swipe uncovers the next space (`revealedSpace(from:)`) only once the track is 0.02 of a page toward it. The stop is committed (the space selected, the Library opened or closed) only once the spring lands, on the next run-loop turn, because selecting a space rebuilds much of the window on the main thread and doing it at release froze the sidebar for several frames; a swipe that catches the spring first cancels it, and a selection made elsewhere wins. DEV-1310: between spaces the spring is critically damped with a response of 0.2 s (`spaceResponse`; opening and closing the Library keeps `BrowserMetrics.Library.transitionDuration`), and it has landed within half a point of its stop, about 270 ms after a release at rest. A slide to a selection made elsewhere starts its clock at the first frame it draws (`SidebarTrack.restartSettling`), because the update that selects the space holds the main thread and a spring timed from before it drew its first frame most of the way along. ## Controls

`Controls/` holds Arx's own controls, for Settings first and for any screen that wants them. All of them use `ArxControlShape`, the app's corner rule: continuous corners at 0.28 × the control's smaller side (`ArxControlShape.cornerRadius(for:)`). The rule covers every control in the chrome too (DEV-749): toolbar and sidebar buttons, the URL bar, sidebar rows, Favorites, fields, chips, key caps and icon tiles draw `ArxControlShape`, and `BrowserMetrics` derives their radii with `cornerRadius(forSide:)` where a number is needed. A dragged favorite's preview draws the same shape as a tile and as a row, so its corners follow its size while it morphs. Panels, cards, the window, the chat panel, rows inside rounded panels, content blocks and app icon marks keep their own radii; `ArxControlShape`'s documentation lists them. They come in three sizes, `ArxControlSize` small (22 pt), regular (28 pt) and large (34 pt). A style without a size follows SwiftUI's `controlSize`: mini and small map to small, and large and extra large map to large. Every control fades when disabled, draws the accent ring when focused (Arx draws it because custom styles get no system ring), and keeps its VoiceOver name.

- `ArxButtonStyle` (`.buttonStyle(.arx)`, `.arx(.primary, size:)`) is a filled button with no stroke, .'s dialog buttons. `.primary` uses the accent fill and `.secondary` a subtle tint of the text color. `.destructive`, or a secondary button with `role: .destructive`, keeps the subtle fill and uses red text. Hover lightens it and pressing darkens it. `ArxButtonLabel(title, systemImage:, keyHint:)` lays out a symbol, the title and an `ArxKeyHint` chip (`.return`, `.escape`, or any key). The chip matches the button's prominence and size. It only shows the key, so the button still needs its own `keyboardShortcut`.
- `ArxRaisedButtonStyle` (`.buttonStyle(.arxRaised)`, `.arxRaised(.item, size:, isSelected:)`) is a raised toolbar control (DEV-797): a glassy squircle (`ArxRaisedShape`, continuous corners at 0.34 × its height, rounder than `ArxControlShape`) with a translucent fill a touch lighter at the top, a hairline edge, a lighter rim along the top and a soft shadow (`ArxGlassTile`, which any toolbar-like view can draw behind itself, such as a search field). Hover and press light a squircle inset 4 points from the tile's edges, with corners concentric with the tile's (its radius less the inset) (DEV-806): lighter when hovered, darker when pressed; the tile itself never changes. The chat composer's +, send and stop, the chat header's tiles, Back and Close, the search button and bar text controls all draw it. `ArxRaisedGroup` puts related actions in one glassy squircle, each with `.arxRaised(.item)`, which only draws the same inset fill, 4 points inside the group's tile: lighter when hovered, a darker inset squircle when `isSelected`. `ArxSegmentedControl` (`ArxSegment`) is a switcher built on the group, whose selected segment keeps its darker inset fill. Its segments are icons, whose hovered segment shows its title in a small tooltip under it after a short wait, or text labels (`ArxSegment(_:title:hint:)`, DEV-1308), which show a tooltip only for a `hint`, as Send Feedback's Vulnerability does. `ArxIconActionGroup` (`ArxIconAction`) puts a bar's actions as icons in the same group, each naming itself in that tooltip on hover (DEV-872), for a header whose labelled buttons would crowd its title, such as the Extensions sheet's; both draw `ArxTooltip`, which waits a moment before it shows and swaps at once between neighbours. `ArxRaisedTile` is the older light card surface (hairline `pageBorder`, `selection` fill) that cards such as the chat composer and messages keep; `isTranslucent: true` draws a material under a thinned fill, for the composer, which the transcript scrolls under (DEV-826). Tooltips come from `help`. Header bars use `.arxRaised(.square)`, a squircle as wide as it's tall for an icon such as Close or Back, and `.arxRaised(.capsule)`, a text control padded for a bar's height (a capsule until DEV-797, a squircle since); `.arxRaised(.round)` is deprecated and draws `.square`. A raised button shows its focus ring only when focus came to it from Tab (`ArxKeyboardFocus`), so a sheet's first button, which the sheet focuses on opening, doesn't light up; `ArxButtonStyle` follows the same rule. `.arxRaisedControlHeight(_:)` sizes the raised controls inside to one height unless a button is given a size of its own; header bars set it to `ArxHeaderBarMetrics.controlHeight` (36 points), so every raised control on a bar matches.
- `ArxFloatingGlass` is the raised glass that controls floating over a page or a list sit on (DEV-1275, DEV-1272): `.arxFloatingGlass(cornerRadius:)` draws an `ArxGlassTile` over its own piece of `BrowserChromeBackground(textured: false)`, so a theme tints it but its texture stays on the window, with a soft shadow. `ArxGlassSearchField` is a 36-point search field on it (a magnifier, the caller's plain text field with its prompt drawn in the secondary color, a trailing view such as a match count, which keeps its width while the text gives way, and `accessories`, `.arxRaised(.item)` controls touching at its end, 4 points in, so their squircles sit concentric with its corners, such as the find bar's Previous and Next). Its `onEscape` answers Escape while its field is being edited, from a key monitor, before the window dispatches the key, so nothing else in a browser window takes it first (DEV-1297); the find bar closes with it and a folder's preview dismisses. And `ArxGlassCloseButton` is Close as an `.arxRaised(.square)` as tall, 6 points beside it. A folder's hover preview and the find bar (`BrowserMetrics.FindBar`) search with them.
- `ArxTextFieldStyle` (`.textFieldStyle(.arx)`, `.arx(size:, systemImage:)`) is the inline field, like the sidebar's search: plain text on a filled rounded background, with no border and an optional leading symbol. Use it for fields inside a row. A field that takes a whole row stays `SettingsTextField`, whose title is a caption.
- `ArxDropdown(title, selection:, options:)` is a pop-up choice drawn as an Arx button. It opens `ArxSuggestionList` under itself in a non-key child panel (`ArxSuggestionPanel`). Arrow keys move the highlight and Return chooses. Esc, any other key (such as Tab), a click elsewhere, scrolling, or the window moving or resigning key closes it. Use it where a system pop-up looks out of place, such as inside a rule's row. - `ArxHeaderBar.swift` is the collapsed header bar of every modal, Settings pane and page (DEV-782, DEV-790, DEV-797): a glassy squircle Close (Escape) or Back (⌘[) button (`ArxHeaderBarLeading`, `ArxHeaderIconButton`), an optional icon tile for a pane (`ArxHeaderBarIcon`, 30 points), the title in bold over an optional subtitle, then the bar's own controls on the trailing edge, such as `.arxRaised(.capsule)` text controls. The bar draws no background. `ArxHeaderSearch` is a squircle button with only a magnifier (⌘F) that expands into a wide field of the same glass with continuous corners (`ArxHeaderBarMetrics.searchWidth`, 300 points) and stays open while it holds a query; Escape, its clear button or leaving it empty folds it back and clears the query.
- `ArxScrollEdge.swift` is the soft edge content scrolls under. `.arxScrollBar { bar }`, applied to a `ScrollView`, pins the bar over its top as a safe-area bar with `.scrollEdgeEffectStyle(.soft, for: .all)`, so content scrolls edge to edge beneath it and the system's soft scroll edge blurs it there, a variable blur that eases out below the bar (DEV-807): no opaque bar, no tint band, no divider. Only a safe-area bar gives AppKit's scroll view a pocket on that edge; a safe-area inset or an overlay gets none. The style reaches the scroll view from any view above it. AppKit's soft pocket draws a 0.5-point separator along its lower edge, the line DEV-790 saw, so `ArxScrollPocketSeparator` (`ArxScrollPocketSeparator.swift`) finds the scroll view behind the bar and sets its pockets' private `allowsSeparator` to false when it finds the scroll view and when either is laid out at a new size. It doesn't watch scrolling or mark anything for layout: AppKit keeps the pocket, with its separator off, while content scrolls (DEV-808). It also gives each pocket a backdrop group of its own (`ArxPocket-<id>`, the private `backdropGroupName`): AppKit puts every pocket in a window into one group, and backdrop layers in a group share one capture, so with two bars in a window, such as Settings' sidebar and pane, a pocket blurred another's capture and showed the plain background, or a solid color with the hard style, instead of the content under it. A sheet has one pocket, which is why its edge looked right. Without that switch, on a later macOS, the system's edge shows as it is. Bars get the progressive edge on top by default (DEV-808), and the system's soft edge on the bottom, over a modal's footer. `ArxScrollEdgeOptions` reads `ARX_SCROLL_EDGE` (`progressive`, the default, or `soft`, `hard` or `automatic` for the system's edge on both, or `off`; the progressive edge is `ArxVariableBlur` and `ArxProgressiveEdge`: a backdrop layer with Core Animation's private `variableBlur` filter (`ArxVariableBlur`, radius 2) under a veil of the surface's background, both at full strength in the top 55 % and easing out to nothing at the bar's lower edge, from the scroll view's top edge down to the bar only, so content below the bar is never touched, and coming in only as content scrolls under the bar (`ArxProgressiveEdge.reveal(scrolledBy:)`, in tenths over the first 24 points), in place of the system's edge, which on macOS 26 is mostly a uniform blur that stops at the bar's lower edge; with `progressive` the hider also hides the top pockets themselves, and with `off` all of them, since they keep blurring the bar's whole height with a hard cut at its lower edge even with `scrollEdgeEffectHidden(true)`), `ARX_SCROLL_EDGE_TUNER=1` (the progressive edge plus `ArxProgressiveEdgeTuner`, a floating panel with sliders for its blur radius, plateau and veil, each value shown, Copy values and Reset; it keeps its values in `ARX_SCROLL_EDGE_TUNING` and is a tool for finding them, not a setting), `ARX_SCROLL_POCKET_HIDER=0` (keep AppKit's separator) and `ARX_SCROLL_POCKET_ADAPTIVE=0` (no color scheme adaptivity in the pocket) once at launch, from the environment or from Arx's defaults. Pass `background: nil` over a translucent surface, such as the chat panel or the Library. `.arxScrollBar { bar } footer: { footer }` also floats `footer` over the bottom as a safe-area inset, as a chat's composer: content scrolls and overscrolls under it, its bottom pocket is hidden, so no blur with a hard cut or line shows there, and the footer draws its own see-through surface, such as `ArxRaisedTile(cornerRadius:, isTranslucent: true)`, a material under a thinned fill (DEV-826). The hider looks for its scroll view from the view behind it up to the window's content view, nearest first, and failing a frame match takes the largest scroll view lying within its frame, so a scroll view narrower than its background is found too. It also watches each pocket's `hidden` (KVO, no work while scrolling) and hides it again on the next run-loop turn when AppKit shows it by itself, as on hovering a bar or rubber-banding in a window on screen, which brought the blur and line back under the chats' bars (DEV-826). `ArxProgressiveEdge` takes a veil (`.color`, `.translucent` or `.chrome`, the sidebar's tint), an edge (`.top`, or `.bottom` over a footer) and an optional ramp in points, for a tall header that stays at full strength under its controls; the sidebar's header and footer use it with the chrome veil (`SidebarScrollEdgeMetrics`) in place of a material faded in with a gradient, which ghosted and tinted (DEV-807). `.arxBarBackground(_:fade:)` and `ArxScrollEdgeFade` (DEV-782) remain for a bar that has to be opaque: an opaque background with a gradient hanging below it that grows in over the first 14 points of scrolling (`ArxScrollEdgeFade.opacity(scrolledBy:)`). Header bars no longer use them. `ArxModalScaffold { bar } content: { … } footer: { … }` puts the two together for a modal: the bar, scrolling content padded by `ArxModalMetrics.contentPadding`, and an optional pinned footer, which the system's soft edge softens content above. Every Settings sheet uses it through `SettingsSheet`, and the Extensions manager draws the bar over its own two-column layout.

## Validation

`make build-package` compiles this target as part of the complete local package graph. `make preview` launches the standalone AppUI harness, and `make test-preview` validates its model-editing transactions. Production model validation remains in BrowserCoreTests. AppUI holds only presentation state; the preview owns its fixture reducer and shares validated editing operations with SidebarFeature.

Features can configure row interactions through `SidebarItem.Interactions`, disclosure through presentation snapshots, and cancellable edge/folder/space hover delays through `sidebarInteraction`. Hover previews for tabs, Favorites and folders appear only when the window supplies `sidebarHoverPreviews` (tab metadata, an optional page picture and, for pages that aren't loaded, an optional `summary` from the site, DEV-730); without it rows keep plain tooltips. A window shows one hover preview at a time, whatever its kind (DEV-1288): every `sidebarHoverPanel` asks the window's `SidebarHoverPreviewOwner` before it shows, and showing orders the previous panel out in the same turn of the main thread, before the new one is ordered in.
