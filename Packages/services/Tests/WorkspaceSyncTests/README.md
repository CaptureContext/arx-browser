# WorkspaceSyncTests

Two-device convergence, the repair pass, account changes, category toggles and Delete from iCloud, on SQLiteData's mock CloudKit container (`@testable import SQLiteData`). Temporary directories only.

`WorkspaceStoreSyncTests` (DEV-977) cover the store with sync: a preference saved through the store reaches iCloud through its own connection, the attached copy takes preference writes only without sync, a save cut short between the two files still loads and its preference rows become the next save's base, a reload that fails validation keeps the base local saves diff against, a profile this Mac retired stays out when sync brings it back, and the client reads what sync wrote. `WorkspaceRepairTests` include a pin beside a Favorite, removed only once iCloud has both. `RefusedSaveTests` (DEV-1207) replay a first upload CloudKit refused, as it did against a Production container without Arx's schema. The rows stay, nothing is queued for deletion, the next launch sends them again, and the first sync of a category leaves a backup. `edit(_:_:)` writes as Arx's own code, which may delete synced rows.

`RefusedSaveTests` (DEV-1207, DEV-1209) answer the organization's first upload as Production without Arx's schema did: no row is deleted, the rows iCloud never confirmed (with or without a last known record) are sent again at the next launch, and a send whose rows iCloud refused shows the category as `refused` until a later launch's send is saved. `CloudKitSchemaTests` (DEV-1209) read every synced table's columns from the migrations and fail when `CloudKit/arx.ckdb` lacks a record type or field; with `ARX_RECORD_CLOUDKIT_SCHEMA=1` (`make cloudkit-schema`) they write the file instead.
