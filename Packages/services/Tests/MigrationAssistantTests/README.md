# MigrationAssistantTests

Fixture-based service tests. A fixture adapter returns a fixed snapshot with valid, duplicate, invalid and repeated records, and an in-memory `FixtureDestination` applies batches through `BrowserOrganization.applyingMigration` and records the idempotence ledger in the same write.

Coverage: a Mac without supported browsers offers no sources; inspection keeps repeated URLs and reports invalid data without writing; execution commits each category into the destination space and keeps existing tabs; a failed category gives a partial result whose retry with the same plan commits only the remainder, and a third run changes nothing; every commit failing is a failed run; cancellation during the first commit keeps it and reports the rest as not started; a changed snapshot, unknown source and wrong-profile destination never commit; unreadable sources are reported. No browser data or network access is used.

`MigrationBrowserSourcesTests` covers the Arc and Chromium readers with made-up files shaped like the real ones; no browser data is committed. It also covers new profiles, routes, the profile mapping (a renamed new profile, an existing one, the receiving profile passwords follow, no rename on a later run, a passwords-only run that still makes the mapped new profile once and is cancelled by a Cancel during that, and a missing profile refused), repeated URLs, each discovered browser's bundle identifier and last-used date from a temporary home folder, and the unsupported-browser list (Safari always, Firefox only with its folder), and that unchecked sources are on unless `MigrationUncheckedSources` is NO.

`SafariDataTests` (DEV-840) build a binary `Bookmarks.plist` and `SafariTabs.db` and `History.db` from the table definitions in macOS 27's SafariShared: the Favorites bar to favorites and the rest to bookmarks with folders, Reading List, an empty folder and a link directly under the root; an unknown plist; tab groups of the default profile and a profile, ungrouped tabs of open windows, profile windows' unnamed groups from `windows_unnamed_tab_groups` with their owning profiles, the restored windows after a quit, hidden groups, deleted tabs and private windows left out, and a database without its tables; each profile's history at its latest visit; reading again gives the same snapshot; no tabs database; a folder without readable files (as without Full Disk Access) is offered but throws; Safari offered only with unchecked sources; and `FullDiskAccessClient.checking` answering by whether the file opens and opening the Privacy_AllFiles pane. No real Safari data is read. `ARX_MIGRATION_REAL_ARC=1` additionally runs the Arc reader against this Mac's file and prints only counts.

`ArxTransferTests` round-trips an archive into a clean browser, comparing nested and empty folders, order, Unicode, repeated URLs and saved versus current URLs. It also covers repeat imports, partial failure and retry, refused files, preferences, and bookmarks HTML. The Chrome-style and Firefox-style HTML samples are written by hand to match those browsers' output, not captured from them.

`ArxTransferVersion2Tests` covers version 2: history and the Tab Archive stay out of the file unless included, the summary, a round trip that brings archived tabs into the mapped space (or the destination space when theirs wasn't exported) with their dates, groups and positions, history to the mapped profile, extensions reported for a manual reinstall, a repeat import that commits nothing, a version 1 file still importing, and entries without a usable date.

`CredentialMigrationTests` covers passwords and sign-ins (DEV-650) with a throwaway secret and `Login Data` and `Cookies` databases built in the test: the key and blobs match values made independently with Python's `hashlib` and the `openssl` CLI; a cookie decrypts only with its key and `host_key`; an erased key fails; a profile reads into sites with counts (never-saved, session-only, expired and undecryptable rows handled); records don't print their values; hosts group only under the source's domain cookies (`k12.ca.us` sites stay apart); a damaged password copy never hides a readable one; selection and per-site outcomes; and, through `CredentialMigrationClient.running` with a fake Keychain reader and writer, no Keychain read without a writer or for an unlisted profile, no second ask after a denial, several profiles with one Keychain read (an unlisted one refusing the read before it), records used once, undo by batch with full cookie keys, passwords staying undoable when cookies fail after them, the account store merged, per-cookie results grouped into sites with a partly refused site and a site with some unreadable cookies reported as sign in again, and `discardAll`. No real Keychain item, profile or cookie is read. `theReceivingProfileFollowsTheRouteAndTheLedger` covers the receiving profile for the current space, a ledger-created profile, one not created yet and a routed space.

`MoreBrowserSourcesTests` (DEV-896) covers every `ChromiumBrowser` row reading bookmarks and history from its own folder (Opera from its root), new rows waiting for the unchecked sources switch, their Keychain items, Firefox and Zen history (hidden, unvisited and non-web pages left out; new visits keeping the snapshot ID), Firefox logins under PBES2 and the older PKCS#12 scheme, a primary password reported and not guessed, DER parsing and damage, Firefox cookies (milliseconds, SameSite, scheme, containers and partitions left out), Safari's `Cookies.binarycookies` (expired and truncated files) and, through `CredentialMigrationClient.running(sources:)`, Firefox and Safari moving into a profile with no Keychain read. The NSS values and the cookie file were made with Python's `hashlib`, `hmac` and `struct` and the `openssl` CLI, not by the readers under test.
