# BrowserDownloadsClient

Application-owned download queue contract. UI reducers use stable download identities and value snapshots; native download managers remain in ChromiumBrowserEngine. Cancelling a presentation subscription never cancels a transfer.

`DownloadQueue.downloads` contains ordinary profile history. `privateDownloads` is separate, memory-only, and must be exposed through explicit private-transfer controls rather than All Profiles or MCP inventory. `activeCount()` synchronously reads actual native ordinary and private transfers, paused ones included, for the quit confirmation's line about downloads that will stop (DEV-966), including work whose observation events have not arrived yet. `unresumableCount()` is how many of them quitting would lose, read synchronously from the engine's `ArxEngineLostOnQuitDownloadCount` (DEV-1130): private transfers in progress, and ordinary ones Chromium couldn't continue from their bytes on disk (no ETag or Last-Modified, `Accept-Ranges: none`, transient or Save Page As). An engine without that export counts only the presentation ledger's private transfers (`DownloadQueue.lostOnQuitCount`), which can lag. `snapshot().activeCount` is presentation state and can lag native work. Quitting no longer cancels transfers: the engine's shutdown leaves them interrupted and resumable. Cancel All operates directly on native managers, including transfers absent from the current presentation snapshot. `start(profileID, url)` downloads an http(s) URL into an ordinary profile with Chromium's usual destination, prompts and checks, and returns the transfer's ID once it exists (`couldNotStart`, `startTimedOut` or `unavailable` otherwise). Only approved MCP requests call it.

`BrowserDownload.sourceTabID` (DEV-1116) names the tab whose page started a transfer while that tab is open. It is never saved; a viewer uses it to show a transfer its navigation became.

`removeHistory` (DEV-647) forgets a profile's finished transfers that started at or after a moment (nil for all time) from the Downloads list, for Clear Browsing Data. Files and transfers in progress stay.

DEV-892: `setPaused` pauses an in-progress transfer or resumes a paused or resumable interrupted one, `moveToTrash` moves a finished file to the Trash and removes it from the list, and `removeFromList` forgets a finished transfer here and in Chromium's history, refusing with `unavailable` on an engine that can't (it would come back after a relaunch). `BrowserDownload.isPaused`, `canPause` and `canResume` come from the engine on each change and are never persisted. The live client (ChromiumBrowserEngine) needs the engine's `ArxEngineDownloadControl`, `ArxEngineSetDownloadPaused` and `ArxEngineRemoveDownload` exports; with an older engine nothing can pause and removal stays app-side.
