# BrowserExtensionsClient

Ordinary-profile extension inventory and management boundary. Depends only on BrowserCore and the dependency wrapper; no native implementation or UI. Installation consent is a transient native-verified authority, separate from inventory management.

The live, test and preview defaults are unavailable. A verified runtime may explicitly inject a client with a live ordinary-profile authorization predicate. Inventory tokens and revisions are short lived and never persisted. Enable, disable and remove return a refreshed authoritative inventory; cancellation or failure is not proof that an already-started native mutation was rolled back. Refresh before retrying. Manifest-defined options requests consume the same exact inventory/profile/revision authority and return a refreshed token without requiring a mutation revision. The separate live options capability defaults off. Action popups, native messaging, private extension controls and Apple Passwords remain separate surfaces.

Signed local CRX intake reads only the explicitly chosen regular file, rejects symlinks/pipes, caps each read and retained bytes at 32 MiB, and rejects size/identity/timestamp changes during intake. Prepare verifies immutable copied bytes before returning a prompt; only explicit resolve can install/update. Full prompt equality plus adapter-retained opaque native authority prevents reconstruction/replay from metadata. Cancellation does not release native physical ownership before cleanup. Action popup hosts, native messaging, private extension controls and Apple Passwords are outside this surface.

ChromiumExtensionsAdapterTests cover authority, profile deletion, fail-closed permission reasons and authoritative completion. ExtensionsFeatureTests cover presentation lifecycle and confirmation.

`unpackedAvailability` and `loadUnpacked` are the developer folder capability, false by default and independent of CRX installation. A folder load consumes the exact displayed inventory authority, like a mutation, and returns refreshed inventory. `directoryMissing`, `directoryUnreadable` and `invalidManifest(reason)` keep the native distinction so the UI can say what to fix. Reload is `BrowserExtensionAction.reload` through `manage`, allowed only for rows whose `canReload` came from native inventory. The client does not know about developer mode; its consumer gates the controls.

`availability` is a live MainActor predicate, read through `isAvailable`; the Boolean initializer remains available for fixed fixtures. A retained client must follow startup and shutdown rather than cache capability at construction. The Chromium adapter forwards its runtime predicate directly.

`installationAvailability` remains independently false by default. Retained clients recheck both runtime readiness and current ordinary-profile ownership before/after async work. A canceled/stale verified prompt is explicitly invalidated; permission escalation is never approved by enable or refresh. Service tests cover bounded growing input, symlink/FIFO/oversize refusal, exact one-use consent, decline/drain refresh and profile loss.

Chrome Web Store installs (DEV-765) are a third capability, `webstoreAvailability`, false by default and read through `isWebstoreAvailable` together with installation. `webstoreInstallRequests` delivers the store's Add to Chrome requests to one consumer (AppFeature); a newer consumer replaces the previous stream. A `BrowserWebstoreInstallRequest` carries only the profile and item ID. The adapter keeps the native token, and the request is used once: `prepareWebstoreInstallation` against the exact displayed inventory returns the same kind of verified prompt as a package, while `declineWebstoreInstallation` tells the store the user cancelled. Requests still unanswered when their stream ends are declined.

Store updates (DEV-776) are `webstoreUpdateAvailability` and `prepareWebstoreUpdate`, read through `isWebstoreUpdateAvailable`. A `BrowserWebstoreUpdateRequest` names an installed store extension in the exact displayed inventory; preparing it returns an update prompt whose candidate has `permissionIncrease`, or fails with `.upToDate`, which leaves the inventory usable for the next check. Resolve or cancel it as any other prompt.

`ExtensionUpdateReviews` (DEV-1210) is the record of store updates the automatic check turned down for asking more permissions, and of offers the person declined, kept in user defaults through `@Shared(.extensionUpdateReviews)` as JSON (at most 64 of each). `offered` marks an update unless that version was declined, `declined` moves it to the declined list, `withdrawn` drops it when the store offers nothing newer, and `reconcile(with:)` drops a profile's entries whose extension is gone or has another installed version. Other profiles' entries are never touched by an inventory, so two Arx builds sharing defaults don't clear each other's.

Installs by ID (DEV-845) are `webstoreImportAvailability` and `prepareWebstoreImport`, read through `isWebstoreImportAvailable`, for extensions brought over from another browser. A `BrowserWebstoreImportRequest` names a store item that isn't in the exact displayed inventory; preparing it downloads and verifies the store's package (engine ABI47) and returns a new-install prompt with no store page involved. Resolve or cancel it as any other prompt: nothing installs without the user's answer.

Extension icons (DEV-824): inventory rows carry an optional `iconPath`, the manifest icon nearest 32px inside the installed extension's folder. Engines older than DEV-824 leave it out. `icon` reads it through `BrowserExtensionIconReader`, off the main actor, refusing relative paths, `..` components, a final symlink, non-regular files and anything over 512 KiB. The default returns nil, so consumers fall back to a letter tile. Engines with the follow-up also report `icons` and `actionIcons` by size; `BrowserExtension.iconPath(pixels:)` picks the smallest action icon that covers the tile, else the manifest's, else the largest of either, else `iconPath`. A component extension's files live in the engine's resources, so its row carries `bundledIcon`, the PNG itself, which tiles draw when its path can't be read.

`setContentBlocking(isOn, blocksCookieBanners)` (DEV-884) turns Arx's content blocking (Helium's uBlock Origin) on or off in every profile and selects its cookie notice lists. `BrowserExtension.allowedInPrivate`/`canAllowInPrivate` and the `allowInPrivate`/`disallowInPrivate` actions carry Chromium's per-extension incognito switch (DEV-889).
