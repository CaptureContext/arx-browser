# BrowserEngineClient

Injectable browser commands and navigation observations using BrowserCore tab identities. open reuses a tab session, command navigates/back/forward/reloads/stops, close releases a session, and events provides a cancellable snapshot stream. BrowserNavigation includes back/forward availability.

The default dependency reports an unavailable engine. AppFeature installs ChromiumBrowserEngine.client once the native runtime is ready. Native objects stay outside this contract; BrowserSurfaceClient isolates presentation attachment.

Depends on BrowserCore and _Dependencies. Must not import features, AppUI or Chromium. ViewerItemFeature and IntegrationFeatureTests cover consumers; packaged runtime behavior is checked with make app-smoke.

prepareProfile initializes isolated persistent storage without loading a page, allowing space reassignment to fail before source tabs are closed.

Automation uses `snapshot` without loading a page, and `openAuthorized`/`commandAuthorized` with a final MainActor authorization closure. Implementations must recheck authorization after asynchronous waits immediately before native side effects. Command authorization also validates the expected live session revision. Ordinary browser APIs remain separate.

`closeAuthorized` is an optional capability and defaults to nil. Its arguments are tab identity, expected session revision (nil only for a dormant tab), a live authorization predicate, and a synchronous completion callback. It must obtain document-bound native before-unload authority, recheck authorization after awaiting it, and consume that one-use authority atomically with native disposal. False means the page refused closure; stale/unavailable authority throws. The completion callback runs after disposal and Swift ownership cleanup, before any suspension or return, so a caller can commit archive/reset metadata without a reopening gap. A pending native open is not a dormant tab and must be rejected. The ordinary `permitsClosing`/`close` pair is not a substitute for this capability.

TabMoveAuthorizationClient is a deny-by-default MainActor host check for cross-profile staging and Undo. The app must validate the captured transaction and reject private, closing, borrowed, or other-window source sessions before each native step and immediately before commit.

The additive link-menu stream/current/dismiss closures default to unavailable. `BrowserLinkContext` is source-bound ephemeral input, never a selected-tab lookup or a persisted/MCP record.

Profile retirement is unavailable by default. Its explicit request binds a profile UUID, consent request UUID, and captured journal revision; `acknowledges` requires the exact durable retired record and a newer revision. Awaiting startup, quarantine pending, restart required, verification pending, erased, and blocked are distinct states. A queued retirement never means data has been erased. The app persists intent before dispatch and reconciles uncertain outcomes before reopening that profile. Retain-data removal does not require this capability.

`ProfileRetirementPersistenceClient` supplies private durable consent/acknowledgment operations and a live transaction authorization predicate. `blockProfileRetirement` prevents future admissions before authorized closes begin. A durable native record with the exact profile/request and a revision newer than consent acknowledges irrevocable retirement, including blocked cleanup of an already retired record. A rejected queue, active record, different request or undurable snapshot never acknowledges consent. Acknowledgment means the profile cannot reopen; only the native erased state confirms website-data removal.

ABI34 developer tier (DEV-668): `developerTierIsAvailable`, `evaluateScript` (checks the final authorization immediately before the engine call and returns a `BrowserScriptOutcome`), `setDeveloperLog` and `readDeveloperLog` (`BrowserDeveloperLog` with typed console or network entries). All default to unavailable.

ABI57 (DEV-996): `evaluateTranslationScript` runs the app's page translation scripts in the tab's translation world, private tabs included, with no authorization step: only the app's own translation calls it.

Saved passwords (DEV-708, `BrowserPasswords.swift`): `passwordsAreAvailable`, `savedAccounts` (account IDs and usernames, never a password), `signInWithPassword` (checks the final authorization immediately before the engine fills and returns a `BrowserPasswordSignInResult`), `passwordSaveOffers` and `answerPasswordSave`. All default to unavailable.

Saved passwords in Settings (DEV-721, `BrowserSavedPasswords.swift`): `savedPasswordsAreAvailable`, `savedPasswords` (an ordinary profile's sites and usernames and its "never saved" sites, under a listing token), `savePassword` (a `BrowserPasswordEdit`: a new site or a listed ID, a username and the `BrowserPasswordFieldID` of the field holding the password), `removeSavedPassword`, `revealSavedPassword` (`.copy` or `.show` into a lent field, after the engine asks the device owner) and `importPasswords` (a Chrome or Apple Passwords CSV; `BrowserPasswordImportSummary`). `BrowserPasswordFields` is the main-actor registry of lent AppKit fields, held weakly, so a typed or revealed password goes between AppKit and the engine without passing through Swift state. Failures are `BrowserSavedPasswordFailure` cases, never values. All default to unavailable.

Autofill (DEV-875, DEV-893, `BrowserAutofill.swift`): `autofillEvents` streams a tab's suggestions (`BrowserAutofillSuggestions`: session, field rectangle, selection, items naming accounts, addresses or masked cards) and their end, with the Settings list a Manage item asks for. `acceptAutofillSuggestion`, `selectAutofillSuggestion`, `dismissAutofillSuggestions` and the app-wide `setAutofillAuthentication` answer them. Values stay in the engine.

Addresses and cards (DEV-893, `BrowserAutofill.swift`): `autofillDataIsAvailable`, `autofillListing`, `saveAutofillAddress`, `saveAutofillCard` (a `BrowserAutofillCardEdit` whose number is in a lent `BrowserPasswordFieldID` field) and `removeAutofillData` per ordinary profile, and the app-wide `setAutofillProducts`.

Credential migration (DEV-830, `BrowserCredentialImport.swift`): `credentialImportIsAvailable`, `importPasswordRecords`, `importCookies`, `checkCookies` and `undoCredentialImport`, all unavailable by default. Only the migration assistant's credentials step calls them; MCP and the agent tools never do. Records redact their descriptions; replies carry `BrowserPasswordKey` and `BrowserCookieKey` values, never a password or cookie value.

Focused link (DEV-713, `BrowserFocusedLink.swift`): `focusedLink` reads the http(s) link with keyboard focus in a tab's current document, in any frame, with the tab's profile and its session and document revisions, so a caller can reject an answer that arrives after the tab changed, as with `BrowserLinkForceClick`. It defaults to nil.

Form edits (DEV-1084, `BrowserFormEdits.swift`): `formEdits` says whether the tab's page holds form input a person typed and hasn't sent, in any frame, cross-origin ones too: `.clean`, `.typed` or `.unknown`. Nil when the engine can't check (an engine built before it, a WebKit page, no live page). No input is read out of the page.

Site settings (DEV-716, `BrowserSiteSettings.swift`): `siteSettingsAreAvailable`, `siteSettings` (an ordinary profile's permission defaults, site exceptions and default and per-host zoom), `changeSiteSettings` (one `SiteSettingsEdit`, returning the fresh listing) and `siteSettingsChanges`, which yields a profile whenever its site settings change from anywhere, a page's permission prompt included, once it has been read.

Profile data (DEV-647, `BrowserProfileData.swift`): `profileDataIsAvailable`, `countBrowsingData` and `clearBrowsingData` (a set of `BrowsingDataKind`s since a moment, nil for all time; clearing returns the kinds the engine couldn't fully clear), `downloadSettings` and `changeDownloadSettings` (a folder, nil to keep it, and whether to ask where to save). All default to unavailable.

Page actions (ABI48): `documentType` tells a tab's committed document as `.web` or `.pdf`, a PDF also while it's loading (DEV-819); `extensionActionsAreAvailable` and `runExtensionAction` run an extension's toolbar action for a tab at a screen point, its popup opening there, for the site menu's extension tiles (DEV-828). They default to nil, false and unavailable. `extensionActionIcon` (DEV-824 follow-up) answers the PNG of the icon an extension set for a tab with `setIcon` or a declarative rule, which the site menu's tile draws before its icon file; it defaults to nil, as an engine without the export answers.

Site data (DEV-633): `siteDataIsAvailable`, `siteDataScope` (the registrable domain a page's data belongs to, such as `example.co.uk`) and `clearSiteData` (that site's `.cookies`, with its site storage, and `.cache`, all time; returns the kinds the engine couldn't fully clear), for the URL bar's site menu. All default to unavailable.

Cross-site links (DEV-727, `BrowserCrossSiteLink.swift`): `ChromiumBrowserEngine.onCrossSiteLink` offers a plain click on an http(s) link to another site in an ordinary tab of a visible window, with the tab's profile and its session and document revisions. Returning true cancels the navigation and keeps the tab where it was; AppFeature opens the link where Settings › Links say for Favorites and for pinned tabs (Peek, Little Arx or a new tab, DEV-1239).

App links (DEV-857, ABI50, `BrowserExternalLink.swift`): `ChromiumBrowserEngine.onExternalLink` offers a tab's link for another app, such as `claude://…`, before Chrome asks or launches anything, from a tab of a visible window (ordinary or private), with its profile, document revision, the requesting origin and whether a gesture or a redirect started it. Returning true means Chrome shows no dialog and launches nothing; AppFeature takes the links an Air Traffic Control handler matches and, since DEV-1259, any other link macOS has an app for.

Tab unloading (DEV-873): `tabUnloadingIsAvailable` and `unloadTab(tab, reason)`, unavailable by default. `unloadTab` asks the engine to unload a hidden tab's page in place for a `TabUnloadReason` (`inactive`, `memoryPressure`, or `windowClosed` once no open window holds it, DEV-1104) and answers a `TabUnloadOutcome` (`unloaded`, `alreadyUnloaded`, `kept` by the engine's rules, `busy` while loading, `unavailable`). An unloaded tab keeps its session: `snapshot` reports `navigation.isUnloaded` with no `documentRevision`, and `open` loads it again. DEV-1107: `tabHoldsUnsavedInput(tab)` says whether closing the window holding it would keep it for unsaved input, so the window asks it first; `windowClosedAnswered` then unloads it anyway. False by default and on engines without the export.

Security components (DEV-874, `BrowserSecurityComponents.swift`): `securityComponents` lists the CRLSet, PKI metadata and certificate error assistant with the version the engine uses, read from the engine's user data directory (`BrowserSecurityComponent.installed(in:)`; Chromium keeps one directory per version, holding a `manifest.json`; the install date is that directory's, because unpacked files keep the package's own timestamps). The app installs it with its runtime directory; it defaults to an empty list. Settings › Developer shows it while developer mode is on.

DEV-898: `processTable` lists Arx's processes for the Task Manager, sampled by `BrowserProcessSampler` (`proc_pid_rusage` footprint and CPU time, child processes, and each helper's `--type=` switch, as `Scripts/core/process_metrics.py` does), with the tabs and extensions the engine reports in each renderer; `endProcess` ends a renderer. DEV-924: `networkDetailsAreAvailable`, `setNetworkCapture` and `readNetworkCapture` keep and read a tab's request headers and bodies for `browser_logs`. All default to unavailable, for engines built before them.

`appendLinkExtensionItems` (DEV-890) adds extensions' `chrome.contextMenus` items for a still-current link menu to the app's `NSMenu`; the engine runs the chosen one.

Back/forward history (DEV-878): `cloneNavigation(source, copy)` gives a new tab's first page another tab's history, for Duplicate Tab and tabs reopened from the archive under a new identity; call it before the copy opens. `forgetNavigation(profile)` is Clear History's, and `discardNavigation(tab, profile)` Reset Tab's. Both do nothing by default.

`BrowserNotificationClick` (DEV-885) is a finished click on a site's web notification: its profile, origin, whether it came from a service worker, whether the site already showed a tab, and whether the notification outlived its page.

WebKit pages (DEV-877, `PageEngineClient.swift`): `PageEngineClient` (`pageEngines`) tells the engine showing a tab's page, moves a page between Chromium and WebKit, and streams `ProtectedMediaRequest`s and `PageEngineChange`s. It prints a WebKit page with WebKit's print panel and saves one as a `WebKitPageSaveFormat` (DEV-1199). The default has no WebKit pages; `PageEngineRouter` supplies the live one.

Device choosers (DEV-905, `BrowserDeviceChooserClient.swift`): `deviceChoosers` streams each tab's WebUSB, WebHID, Web Serial or Web Bluetooth request (`BrowserDeviceChooser`, nil when it closes), answers it with chosen indices or none, scans again for Bluetooth, and lists and revokes a profile's `BrowserDeviceGrant`s. Unavailable by default.

`BrowserCastClient` (DEV-927, `\.cast`): a tab's Cast picker (`BrowserCastPicker`: the devices found, each with its state, kind, the modes it takes, what it casts and any problem) as `events(menuTitle)`, and `show`, `choose`, `stop` and `close`. Unavailable by default: with nobody listening the engine opens no picker and a site's Cast button fails at once.

Hide Element (DEV-1019): `elementHidingIsAvailable`, `startElementPicker(tabID)`, `hiddenElements(tabID)` (`BrowserHiddenElements`: `{hostname: [filter]}`, with `filters(for:)` taking a host's own and its parent domains' lines, as uBlock applies them, and `selector(of:)` for what follows `##`) and `showHiddenElement(tabID, filter)`.

Arx's own element picker (DEV-1201): `elementPickerIsAvailable` and `pickElement(tabID, accent)`, which runs until the picker ends and answers `BrowserElementPick`: `unavailable`, `closed`, `hidden(filter:)` or `refused(filter:)` (the element went from the page, but the engine wouldn't save its line).

Hide Element's mode (DEV-1298): `hideElements(tabID, accent, cursor)` is an `AsyncStream` of `BrowserElementHidingEvent` (`unavailable`, `opened`, `hidden` with the element's `BrowserHiddenElementDescription`, `refused`, `target`, `described`, `shown`, `key`) that ends when the picker closes; `elementHidingCommand(tabID, _)` sends `unhide`, `describe`, `listOpen` and `close`.

Hosted site permission prompts (DEV-963, ABI56, `BrowserPagePermissionPrompt.swift`): `setPagePromptsHosted` asks the engine to hand ordinary site permission prompts to the app (false when it can't), `pagePermissionPrompt` reads a tab's current prompt by token (variant, origins, the permissions by name with Chromium's wording, Allow Once, the location choice and whether it's quiet), and `answerPagePermissionPrompt` answers that token with Allow, Allow Once, Block or Dismiss and, for a location prompt that offered a choice, the accuracy. Dismiss never blocks.

DEV-1009: `BrowserNavigation.unresponsive` says a page stopped answering. `waitForPage` asks the engine to check again; `endRenderer` ends the page's renderer process. A command that leaves or stops the document (`Command.leavesTheDocument`: a new address, back, forward, a history entry, reload, stop) ends a hung page's renderer first, and so do closing and `permitsClosing`, so no way out waits on a page that doesn't answer.

DEV-1016: `BrowserNavigation.rendererEnd` says why a page's renderer last ended (`crashed`, `outOfMemory`, `killed`, `endedByArx`, `launchFailed`, `other`), whether other pages' renderers ended within a tenth of a second too (`isShared`), and whether it ended three times within a minute on its own (`isRepeated`). The Chromium adapter keeps a `RendererEndHistory` across pages for the last two, and tells a page again when a later end makes its end shared. After it ends a renderer (`endRenderer`, or a command on a hung page), the next command that leaves the document waits, at most two seconds, until the page reports that renderer gone, so the reload or navigation doesn't reach the dying one; a cancelled caller stops waiting and its command doesn't run, and the pending end stays visible to every command until it's seen or the wait runs out. The command isn't authorized again after the wait, since the end it caused moves the page's revision; a newer command that leaves the document wins over one still waiting, which ends cancelled.

`BrowserHoveredLink` (DEV-1111) is the link under the pointer in a tab's page, as Chrome's status bubble shows it: the tab, its profile, whether it's private, the URL without credentials and whether it goes to another site, and where a plain click navigates (`target`: the page, a frame in it, a new tab, or unknown; DEV-1118). Nothing stores it.

DEV-1316: `setExtensionPopupWindows` hands the engine the app's window for extensions' action popups (`BrowserExtensionPopupWindows`: `makeWindow`, `resizeWindow` and the `closing` rule). It defaults to false, as an engine without the export answers; that engine keeps its popover.
