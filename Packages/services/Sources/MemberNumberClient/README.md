# MemberNumberClient

Claims the identity card's member number (DEV-701) from Arx's server, `arx-browser-backend`, at `ArxService.backendURL()` (`ARX_BACKEND_URL` points it at a local `pnpm dev`).

- `signIn` opens Apple's web sign-in in a private Little Arx (DEV-1323) and returns its ID token. It asks for no name and no email. The client asks `MemberSignInWindow` for the window: AppFeature reads its `requests`, opens the authorize address in a private Little Arx (AppFeature's internal `PrivateLittleArx`, a private profile of its own), takes the redirect to `dev.capturecontext.arx.auth` from that window only, and answers with `finish(_:with:)`. Closing the window is `.cancelled`; ten minutes without an answer, or a second sign-in while one is open, is `.signInFailed`. `ASWebAuthenticationSession` isn't used: with Arx as the default browser the system handed the sheet straight back to Arx, which returned the authorize address itself.
  - **Apple** (DEV-1313): Apple's web sign-in with the Services ID as the client, `response_type=code id_token`, `response_mode=form_post`, no scope, and a fresh `state` and `nonce`. Apple posts its answer to Arx's server at `v1/apple/callback`, which redirects to `dev.capturecontext.arx.auth:/apple` with only the token and the state. The app checks the state and the token's `nonce` claim; the server verifies the token. The native sheet is gone: its entitlement is for App Store apps only, and Arx ships with Developer ID.
  - Google's sign-in was removed (DEV-1323). A saved number that names Google doesn't decode, so the card asks for a number again.
- `claim` sends `POST /v1/accounts` with `{"provider", "idToken"}` and the `yyyy-MM-dd` day Arx was installed on this Mac as `memberSince` (DEV-1323), and returns `MemberNumber` from `{"idx", "registeredOn", "memberSince"}`: the account's member-since day, the earliest any of its Macs sent. A server from before that refuses the extra field with `400`, so the claim sends once more without it. The token is never kept.
- `load` and `save` keep the number, days and provider in UserDefaults (`MemberNumber`), per Mac: it doesn't sync through iCloud. The server gives the same account the same number on every Mac, so another Mac claims it with its own sign-in.
- `availableProviders` offers Apple only when Info.plist's `ArxAppleServicesID` (from `ARX_APPLE_SERVICES_ID` in `.env`) holds a Services ID. It's empty by default, and a build without it offers no sign-in and says so. Every build, signed or not, offers what's configured.
- `Failure` is what the card says: cancelled, offline (no answer), refused (any answer but 200 or 201), signInFailed, unavailable.

`MemberNumberRequests` holds the requests and answers without a network or window, for `MemberNumberTests`. The test value fails on any call; the preview value answers #42.
