# BrowserMediaClient

Boundary for the Library's Media page and ArxPiP. `liveValue`, `testValue` and `previewValue` are unavailable. AppFeature explicitly supplies the runtime-bound Chromium adapter for ordinary-profile playback controls, manual video PiP and separately supported automatic entry. Availability follows native startup and shutdown. This contract module creates no native window.

An adapter must emit an initial snapshot with a positive revision and ordered replacements while observation remains active. Source identity is the existing tab, its profile and a media generation; navigation, session replacement and player teardown invalidate the generation. Events must contain at most one video-PiP source. Removal, renderer crash and runtime shutdown publish cleanup before observation ends. Production composition withholds private sources and actions. No media metadata or automatic preference is persisted here.

`perform` must revalidate source identity, revision, current action support and private/profile ownership on the final native actor immediately before dispatch. Its asynchronous completion must be bounded, with `timedOut`/`requestFailed` for unconfirmed PiP entry/exit. Snapshots remain authoritative even when a command is acknowledged. Cancellation must prevent work that has not reached Chromium; canceling UI observation never closes playback or its tab. Return-to-source is an application ownership operation, not a native browser lookup. A `seek` request carries its absolute time and is valid only with one. `position` reads a tab's position and audio mute once, on request; it must not be polled into feature state. `setMuted` acts on the tab's ordinary page, whether or not it has media.

The source-supported native seam in Chromium 156.0.8078.47 is `content::MediaSession::GetIfExists`, `GetMediaSessionInfoSync`, `GetMediaSessionActionsSync`, `AddObserver`, `Resume(kUI)`, `Suspend(kUI)`, and `EnterPictureInPicture`/`ExitPictureInPicture`. Arx's `WebContentsDelegate::EnterPictureInPicture` must forward to `PictureInPictureWindowManager::EnterVideoPictureInPicture`; its exit must be scoped to the manager's current source, and native Return-to-Tab must post the stable Arx tab identity through the owned manager activation hook. Generic page activation is not a media activation. Calling `PictureInPictureWindowController::Show()` directly is invalid without the renderer-created session/surface. The existing manager handles a single native overlay and returns the prior source without pausing when replacing it. UI callbacks must be posted after Chromium observer stacks unwind, following the existing bridge convention.

Manual media-session entry can invoke a website's registered action handler; only the fallback with one eligible video player is guaranteed by that path. A handler can request Document PiP, which this video-only contract does not enable. Native success must be confirmed by video-PiP observation. PiP-specific play/pause can use `VideoPictureInPictureWindowController::Play`/`Pause` for the selected video; ordinary media controls use the MediaSession route. The site permission key is the committed top-level page origin; the controller’s `GetOrigin()` is instead the actual player-frame origin and must not silently replace that key. Automatic entry additionally requires a supported `kEnterAutoPictureInPicture` action and explicit Arx per-profile/exact-origin opt-in. The current content path has separate eligibility, visibility, primary-frame, capture and feature-flag checks; manual entry must never masquerade as automatic entry. `BrowserInitiatedAutomaticPictureInPicture` is experimental in the pinned Blink runtime feature definitions; this contract does not enable that flag.

Chromium's macOS overlay owns its Views widget/NSWindow and consumes the existing player's `viz::SurfaceId` and Mojo media remote. It is floating, resizable and marked visible on all workspaces. These source properties do not prove fullscreen, Stage Manager, display movement or VoiceOver behavior. Its native Close button may pause when play/pause is supported; Return to Tab and replacement do not pause. `WebContentsImpl::RenderViewTerminated` already calls the exit delegate on renderer crash. The bridge must still invalidate the generation and publish removal. Player teardown needs explicit bridge cleanup: `PictureInPictureSession::OnPlayerGone` alone only hides controls. DRM/protected media, site opt-outs, multiple-player pages and Document PiP remain unclaimed until native fixtures establish support.

Reference source paths: `content/public/browser/media_session.h`, `content/browser/media/session/media_session_impl.cc`, `content/browser/picture_in_picture/video_picture_in_picture_window_controller_impl.cc`, `content/browser/picture_in_picture/picture_in_picture_session.cc`, `chrome/browser/picture_in_picture/picture_in_picture_window_manager.cc`, and `chrome/browser/ui/views/overlay/video_overlay_window_views.cc`. The native implementation and owned video fixtures are integrated. Fullscreen, Stage Manager, display movement, VoiceOver and protected-content acceptance remain separate.

The C seam is a borrowed per-page media snapshot callback (page ID, media generation, revision, playback/action flags, private/video/PiP state, title/origin), a revision-checked media command carrying a request ID with bounded completion, and a source-activation callback carrying page ID/generation. Swift copies callback data and maps existing engine page ownership to tab/profile identities. Neither video pixels nor an overlay/window handle crosses the ABI. Owned signed application fixtures additionally exercise playback, PiP replacement, navigation/player invalidation and private metadata policy. Those fixtures do not establish every OS presentation or protected-content path.

Private-media policy: Arx's unique OTR profiles are classified by Chromium as `kOtherOffTheRecordProfile`. The upstream `ChromeMediaSessionClient::ShouldHideMetadata` check only covered primary incognito/enterprise-isolated profiles, which missed Arx's private contexts. The integrated native overlay changes that policy to `IsOffTheRecord()`, and the unique Arx OTR fixture verifies the native hide flag. Private media controls/PiP remain withheld pending OS metadata and presentation acceptance. Constructing another MediaSessionClient after Chrome initialization is invalid because the singleton constructor checks that no client exists. The adapter must withhold private-source actions until this policy is fixed and tested; source inspection alone is not an observed OS disclosure test.

`activations()` carries only native Return-to-Tab events for current source identities. Consumers must revalidate their observation epoch and visible profile scope before routing the source window. Stopping observation does not exit PiP or pause playback.

`isSourceCurrent` is a synchronous MainActor read of the authoritative native source, defaulting to false. Call it immediately before taking focus, after validating app-owned presentation and profile identities. Queued media/navigation snapshots cannot prove the generation survived a same-URL reload. This read must not refresh observation, activate a page or run a nested event loop.

`availability` is a live MainActor predicate; `isAvailable` reads it on that actor. The Boolean initializer remains a convenience for fixed fixture/default capabilities. Hosts can install the client before runtime readiness without permanently caching an unavailable value, and must make availability false when runtime or host ownership ends.

Automatic dispatch uses `MediaSession::EnterAutoPictureInPicture`, never the manual entry function. Pinned Chromium routes the registered site handler with `contentoccluded` and grants only a scoped PiP request token. The native boundary rechecks playing-video capability and the actual source NSView/window visibility before dispatch and when a delayed handler returns. The owned runtime fixture waits for transient activation to expire, checks visible-source refusal, observes successful hidden-source entry with no general user activation, verifies a missing handler does not advertise automatic support, and rejects a delayed callback after the source becomes visible. These checks do not establish OS presentation or protected-media support.

`supportsVolume` and `setVolume` (DEV-800) scale an ordinary tab's audio output, 0 to 1, on top of the page's own volume. They are unavailable by default and on engines built before per-tab volume, so callers hide volume when `supportsVolume()` is false.

A source in a call (DEV-948, ABI54) has `BrowserMediaSource.call` with the microphone and camera its site reports, and may offer `toggleMicrophone`, `toggleCamera` and `hangUp`, which the engine hands to the site's Media Session handlers. A call's Picture in Picture can be the site's own Document PiP window, so a valid snapshot allows a call in PiP without video.
