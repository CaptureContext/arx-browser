# WebKitBrowserEngine

WebKit pages for protected video and music (DEV-877). Sites on Settings › Advanced › WebKit's list (`WebKitPagePreferences`) show in a `WKWebView`, where macOS's FairPlay plays Netflix, Spotify, Disney+ and other DRM services at Safari's quality, since Arx has no Widevine module.

- `PageEngineRouter` sits behind the app's one `BrowserEngineClient` and `BrowserSurfaceClient`. It opens a tab in WebKit when its address is listed, moves a tab there when a typed address or `move` (the site menu, the fallback prompt, a followed link) says so, and back to Chromium when a typed address isn't listed or Back leaves WebKit's first entry. A Chromium page that reaches a listed site any other way (a link within the site, a redirect, a script, Back and Forward) moves once its address shows the site or it asks for protected media there (DEV-1000); Back from WebKit then reopens the Chromium page at the listed address, where its saved history ends, and steps back once it reports, so the history before and after stays (or opens the page before when the history didn't come back). A page the router showed in Chromium at a listed site (Back, or a move to Chromium), or one that refused to leave, stays there until it leaves that site. The new page a move back to Chromium opens starts at Chromium's initial `about:blank`, which isn't leaving the site (DEV-1188). A navigation the browser started counts only once it commits, and a move checks that the page is still on the site before it starts. A page the router kept in Chromium at a listed site, or one that refused to leave, never moves when its protected media fails: the request goes to the app, which offers WebKit with a prompt, as for any other Chromium page (DEV-1188). A streaming site's video falls back to WebKit with a prompt, never silently. A capability probe never reports: the engine answers it as Chrome does and keeps the tab (DEV-1205). Each request says why it came (`ProtectedMediaRequest.reason`, DEV-1211): media that can't play, or keys made with no media wanting them, which the app offers WebKit for only on a streaming site. The `FairPlay` log category says where each request went. Moving closes the tab's Chromium page, so nothing reaches a document the tab no longer shows, and Back opens that page's address again; a move that waited for cookies gives way to a newer navigation, and an authorized open is checked again after it. Every other client call goes to Chromium, which has no page for a WebKit tab: agents, DevTools, extensions, autofill and Chrome's site settings don't reach WebKit pages. `formEdits` answers nil for a WebKit tab, so the app keeps its own script there (DEV-1084). `pageEngines` is the `PageEngineClient` the app's reducers use.
- `WebKitPages` keeps each tab's `WebKitPage` and each profile's data store: one persistent `WKWebsiteDataStore` per ordinary profile, named by `dataStoreIdentifier(for:)`, and one non-persistent store per private profile until it's released. Before a page moves to WebKit, the site's cookies are copied from the profile's Chromium store with a time limit (`cookieTimeLimit`), so a sign-in comes along. Clear Browsing Data, the site menu's Clear Cookies and Clear Cache, and profile retirement clear WebKit's store too (`clearData`, `removeData`). Clearing never makes a store a profile doesn't have (a private profile's lives only with its pages; an ordinary profile's is looked up among the stores on disk). `WebKitDataStores` reaches WebKit's stores; its live `remove` and `identifiers` first make a non-persistent store, because WebKit's class methods for identified stores don't set WebKit up and crashed (SIGSEGV in `WTF::RunLoop::dispatch`) when one was the first WebKit call in the process, as profile retirement is in a run that never opened a WebKit page. WebKit has no public before-unload, so a WebKit page closes without asking.
- `WebKitPage` uses Safari's user agent, WebKit's element full screen and Picture in Picture, opens popups as tabs (a popup's `window.opener` doesn't follow) and saves downloads into the Downloads folder (`WebKitDownloads`), outside Arx's Downloads list. Find reports whether there's a match, not how many.
- `WebKitPageMenu` (DEV-1199) puts Arx's page menu in WebKit's context menu: `WebKitPageView` hands the menu to its page before it opens. Where WebKit offers Back, Forward and Reload (the page's background, or a player drawn over it, as Netflix's is), the page menu's commands take their place: Back, Forward, Reload, Save As…, Print…, Share… and View Page Source, those the host allows now, chosen as the Chromium page menu's are. A video's own menu gets them after its items; link, image and text menus stay WebKit's. Exit Full Screen comes first while the page is in full screen. Cast and Translate aren't offered: WebKit pages have neither. Inspect Element is WebKit's, shown while `WebKitPages.isInspectable` (developer mode) is on. Print uses WebKit's print operation; Save As writes Safari's web archive, the main resource's HTML or a PDF on Page Setup's paper (`WebKitPageDocuments.swift`), and refuses once the page shows another address.
- `SharedHistory` (DEV-1293) is one tab's history across its two engines. The engine a tab doesn't show has no page, so the router keeps what the WebKit page had (`WKWebView.interactionState` and its entries) beside the Chromium page: ahead of it after Back from WebKit's first entry, behind it after a typed unlisted address or Open in Chromium left WebKit. The Chromium page's navigation offers it, with entry ids far outside both engines' own, so Back and Forward are enabled exactly when there is somewhere to go and the history list shows it. Back, Forward and the list's entries cross to it, and so does the Chromium page's own swipe through `setSharedHistory` and `onSharedHistorySwipe`. A Chromium page that followed a link to the listed site keeps that entry; reaching it again shows the WebKit page as it was instead of loading the site in Chromium. The restored WebKit page goes back to the Chromium page; one shown by Back goes forward to it too, with the WebKit entries the typed address replaced hidden. A new navigation from the Chromium page drops what was ahead of it, and only the nearest page of each engine is kept. WebKit pages list the Chromium page on either side in their history and swipe lists.
- `HistorySwipe/` (DEV-1203, `ARX_WEBKIT_SWIPE`, on by default) replaces WebKit's own back and forward swipe with the Chromium pages' one. `WebKitPageView` hands its scrolls to `WebKitHistorySwipe` first, which follows the touchless path of the native gesture (`Packages/engine/Native/gestures`): a precise scroll's deltas stand in for finger travel, and `WebKitSwipeOwnership` keeps the native thresholds (a fifth of the trackpad commits, the list opens at half as far again after a 300 ms hold, too much vertical travel gives the scroll back). The page decides first, as Chromium's renderer does: `WebKitSwipeScript`, in a content world of its own, answers each sideways wheel with whether something under the pointer scrolls that way (a carousel, a map, a wide table) or prevented it, and whether its `overscroll-behavior-x` lets the overscroll out. Only a first unconsumed answer that lets it out admits the swipe; a later consumed wheel takes it back, and a page that never answers keeps its scrolls. A frame can't see the page around it, so a swipe that starts over an embedded frame stays the frame's, and any main-frame navigation ends a held swipe. `WebKitSwipePanel` is a Swift copy of the native `panel.mm`: the arrow in a ring that fills, then the history list. The router says where Back and Forward go and performs the swipe with the commands ⌘[ and ⌘] send, so a swipe back from the first WebKit entry reopens the Chromium page the tab came from, and the list ends with that page. There's no page preview, as on Chromium pages. Off, WebKit's own swipe runs and can't leave WebKit.
- `WebKitContentRules` fetches uBlock Origin's default lists from their publishers every four days, converts them with `ContentRuleConverter` (network filters, exceptions and element hiding, ordered so `$elemhide` and `$generichide` turn off only element hiding; no regular expressions, scriptlets or procedural selectors; a filter for entity domains only, `example.*`, which WebKit can't match, is left out rather than applied everywhere but its exceptions, DEV-1202) and compiles one WebKit rule list each. Pages follow Settings' Content blocking and Block cookie banners switches and each site's exception, read from the profile's site settings.

Depends on BrowserCore, BrowserEngineClient and BrowserSurfaceClient; never on ChromiumEngine. AppFeature composes it with `ChromiumBrowserEngine`.

A page's JavaScript alert and confirm dialogs show `WebKitPages.dialogButtons` (DEV-1291): services have no string catalog, so BrowserWindow sets AppUI's OK and Cancel; until then they're `WebKitDialogButtons.untranslated`.
