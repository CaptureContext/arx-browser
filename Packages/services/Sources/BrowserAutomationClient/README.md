# BrowserAutomationClient

Authenticated local IPC and browser-metadata projection shared by AppFeature and the MCP helper. No MCP SDK types or native renderer handles enter feature/domain state.

`BrowserAutomationHost` owns a mode-0700 directory and mode-0600 Unix socket. Both peers require the same effective user ID; every envelope also authenticates an app-issued 256-bit random credential against its persisted SHA-256 digest. Client-provided display names do not establish identity. A fresh app epoch and helper session reject old sessions after restart. Stop, revoke, cancellation, request timeout and an observed peer disconnect cancel pending continuations. Idle/crashed helper sessions expire after 45 seconds, with a helper heartbeat every 15 seconds. The app never replays a mutation after reconnecting.

Requests are limited to 64 KiB, responses to 256 KiB, connections to 32, pending app requests to 16, pending requests per helper to four, and helper sessions to four per client / 32 total. Pending requests expire after 30 seconds. Frames are newline-delimited, contain one JSON envelope, and cannot carry multiple operations. Malformed payloads produce bounded errors without reflecting input. Socket directories/symlinks with unsafe ownership or permissions are rejected. Only an owned, refused stale socket can be replaced.

`AutomationInventoryBuilder` projects permitted canonical organization before pagination. Profile grants include every space, folder, tab and Favorite of the profile, including ones created later. Space grants include contained folders/tabs, but never profile Favorites; Favorites otherwise need individual tab grants. Tab grants bind the original profile and location. Private windows and temporary presentations are outside the canonical workspace. Inventory does not load, select or capture pages. URLs omit userinfo, query and fragment, set `urlSanitized`, and omit non-HTTP(S) or oversized URL values. Titles and URL paths can still be sensitive: this is not universal secret detection. Tab revisions include grant revision, ownership/location, full URL **inside the hash only**, and live engine revision. Folder revisions bind the complete ordered subtree, parent relationships, names and owning space/profile; navigation and disclosure changes do not invalidate a folder move. Child hashes are memoized when building the inventory. A projection resolves every tab's location and folder membership in one pass; `item(_:kind:client:organization:snapshots:)` derives one item alone, with the same authority checks, for calls that target one item. Tab items and revisions are memoized in bounded process-wide caches keyed by their complete input (grant revision, the tab's disclosed fields and location, and its session revision, URL and document epoch), so any change misses the cache. Tests bind `AutomationInventoryBuilder.$derivations` to count projections, location walks and revision digests. Pagination fingerprints only the permitted projection, with deterministic encoding, and exposes no excluded counts.

Trust model: this is for explicitly trusted local assistant applications running as the same macOS user. It is not a sandbox against a compromised same-user process, debugger, administrator or stolen client configuration. The user must store copied client credentials privately. Network listeners, remote clients, direct cookies, credentials, browser-form APIs and clipboard reading are absent. The application does not log credential/configuration values or raw tool inputs/results. Activity is bounded operation/outcome metadata owned by AppFeature.

Tests cover forged credentials, scope and profile changes, filtered pagination, query-only revision changes, stale sessions, revoke/stop, unsafe directory permissions and frame bounds. The helper process fixtures use synthetic credentials and an isolated temporary host, never the user's browser workspace.

Completed responses remain subject to authorization. `BrowserAutomationHost.respond` compares the captured client record with live preferences and checks server state, session identity and the monotonic request deadline before releasing a result to IPC. Its application response callback denies by default. The production callback re-derives the result's permitted items (the whole projection for inventory pages) from the current canonical workspace and native session revisions; changed titles, paths, query-only navigation, ownership, or pagination invalidate a queued result. Data pages (history, archive, downloads) are the exception: a download's progress or a new visit moves the list moments after it's read, so a page is released while it answers its own request and every item it carries is still one the client may read, from the same profile (`AppFeature.State.automationDataPageValidation`); an item that's gone or a grant that no longer covers it still holds it back. This is a final MainActor release check, not a promise to retract bytes already released to the socket/helper. It does not supply an authentication quarantine or an authenticated-session signal.

Socket connect/read/write use nonblocking descriptors with explicit deadlines and cancellation checks; concurrent clients do not occupy Swift cooperative workers while waiting for I/O. Connect and frame writes allow two seconds, the server allows two seconds for an incoming frame, and a client allows 35 seconds for the app response. Accepted and connecting sockets require successful `SO_NOSIGPIPE` configuration, and every send also uses `MSG_NOSIGNAL`. A stop can cancel I/O before a disabled frame is delivered, in which case the caller receives a disconnected failure. Socket peer monitors finish before the descriptor is released.

Close responses are the narrow exception to requiring the completed command's target in current inventory. AppFeature must hold an exact operation-bound close receipt proving its own archive/reset, current original scope and post-close generation. The host still checks the captured client record, session and deadline; a revoked or disconnected request cannot release that receipt. This exception never grants inventory access to removed tabs or bypasses checks for other commands.

Screenshot grants are independent and default off, including when decoding an older saved client. Screenshot-enabled clients add the synchronous native document epoch to tab inventory revisions; ordinary inventory behavior stays unchanged. Image responses receive a final exact JSON frame-size check after live authorization and before continuation release, with no suspension between them. The app additionally requires the page's native host to remain visible through this release; previously captured pixels are not retained for a disconnected request.

Semantic page reads require a separate default-off `allowsPageContent` grant in addition to metadata read and explicit ordinary tab scope. Content-enabled inventory revisions include the synchronous native document epoch; metadata-only revisions remain unchanged. Before releasing any response, the host rechecks the captured client record, session, deadline and live app authority, then bounds the exact encoded IPC frame. Content/name text never enters activity logs.

An exact-tab grant does not disclose its containing space or folder. Those IDs and their revision contribution appear only when the containing space is also granted. Hidden ancestry edits preserve the permitted projection and its cursor; moving the tab outside every explicitly granted location still removes access at execution and response release. Close requests retain a separate exact private location binding through native approval.

Click-only requests preserve dispatch uncertainty across cancel/timeout/revoke and helper connection loss. The host marks submission synchronously inside the final live authorization callback and retains at most its existing 16 pending operation records. Post-submission failures release only caller-owned operation metadata, never page data or fresh browser state. Other reads and browser-command replies keep their existing authorization rules.

The host emits `inspectionReleased` synchronously after final scope/document authority, the conservative 80 KiB inspection-result delivery budget and exact IPC encoding checks. AppFeature alone records that connection's latest released snapshot. Denied or oversized results never become clickable; no native scope UUID is accepted from clients or sent in MCP payloads.

Form interactions share click submission uncertainty and existing host admission/deadlines. beginForm verifies the captured connection/client/grant and marks submission synchronously; cancellation before it is notDispatched, while later interruptions preserve known native disposition or possiblyDispatched. Mutation binding is SHA256 over domain-separated, length-prefixed canonical fields including kind, target, snapshot/reference and exact payload. Only the digest enters app replay records; bounded values remain in pending execution and are discarded at terminal/revoke/disconnect.

Click, form and scroll submissions share one host phase guard, pending limit and response boundary. beginScroll can mark only a matching scroll request under the current session/grant/deadline. Cancellation, revocation or transport loss preserves possible dispatch after that mark; known unchanged remains precise. Scroll digests use explicit axis plus the normalized-zero IEEE-754 bit pattern inside canonical length-prefixed fields. No page offsets are retained in receipts.

Besides `hello`, `ping`, `request`, `cancel` and `disconnect`, the IPC carries `grants`, which returns the client's `AutomationGrantSummary` so the helper can follow grant edits without reconnecting, `changes`, which returns the granted tabs' revisions (`AutomationChangeDigest`) through the app-supplied `changes` callback for resource subscriptions, and `focusedTab`, which resolves the opt-in focused-tab alias through the app-supplied `focusedTab` callback (denied without the opt-in, `notReady` when no granted tab is focused, `authenticationProtected` during the sign-in lock).

`AutomationInventoryBuilder.profiles` names the profiles a client can see, and `changes` builds the digest from the same permitted projection as inventory, so it never contains ungranted tabs.

`AgentSetup` is shared by the `arx` command and the app: the agents (Claude Code, Claude Desktop, Codex, Cursor), the setup request and private credential file, and each agent's Arx entry (`claude mcp add` arguments, the Codex table, the JSON `mcpServers` entry, with `"type": "stdio"` for Cursor). `CommandLineTool` installs, updates and uninstalls the `arx` copy at `~/.local/bin/arx`, recognizes Arx's own copy by its `ArxMCP` code-signing identifier, checks a PATH value, and gives the shell profile line.

`RealHomeGuard.check(_:)` runs before every agent-tools write (`CommandLineTool`, `AgentSetup.write`, AgentToolsClient's files and `claude`). While tests run, it reports and throws for any path inside the real home folder, resolving `..` and symbolic links first.
