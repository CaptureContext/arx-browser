# AgentToolsClient

What the app needs to set up outside agents. Onboarding and Settings use it through OutsideAgentsFeature, and the `arx` command uses it too.

- `CommandLineToolClient` (`@Dependency(\.commandLineTool)`) installs, updates and uninstalls `~/.local/bin/arx`, a copy of the app's `Contents/Helpers/ArxMCP`. The file operations are `CommandLineTool` in BrowserAutomationClient, which `arx setup command` shares. A copy is written next to the destination and renamed over it. Only Arx's own copy, recognized by its `ArxMCP` code-signing identifier, or a link left by an older `arx setup command`, is ever replaced or removed. `status()` also reports whether `~/.local/bin` is on the login shell's PATH. An app opened from the Dock only has launchd's PATH, so the shell is asked with `-l -i -c`, with a 3-second limit. It also reports the profile line for zsh, bash or fish.
- `AgentAppsClient` (`@Dependency(\.agentApps)`) finds each supported app and adds Arx to it. Every entry runs `~/.local/bin/arx mcp --client <agent>` and holds no secret. The app writes the agent's credential to its own private file (`AgentSetup`). The sources below were checked on 8 November 2026:
  - **Claude Code:** `claude mcp add --scope user --transport stdio arx -- <arx> mcp --client claude`, after `claude mcp remove --scope user arx`. Claude Code stores the server in `~/.claude.json`, which Arx only reads. `claude` is looked for in `~/.local/bin` (the native installer), `/opt/homebrew/bin`, `/usr/local/bin` and `~/.claude/local`. Without it, only the snippet is offered. Source: https://code.claude.com/docs/en/mcp
  - **Claude Desktop:** `mcpServers.arx` in `~/Library/Application Support/Claude/claude_desktop_config.json`. Claude Desktop must be restarted. Source: https://modelcontextprotocol.io/docs/develop/connect-local-servers
  - **Cursor:** `mcpServers.arx` with `"type": "stdio"` in `~/.cursor/mcp.json`. Source: https://cursor.com/docs/context/mcp
  - **Codex:** `[mcp_servers.arx]` in `~/.codex/config.toml`, which the CLI, the IDE extension and the app share. A `CODEX_HOME` set only in a shell isn't visible to Arx. Source: https://learn.chatgpt.com/docs/extend/mcp
- `AgentSkill` is the `arx-browser` skill: how to work with Arx's MCP tools (the loop, grants, approvals, errors, sign-in handoffs). `Skill/arx-browser/SKILL.md` is the source and `AgentSkillText.swift` compiles the same text in, so the `arx` command needs no resource bundle; `AgentSkillTests` fails while they differ, and BrowserAutomationTests' `AutomationGuidanceTests` fails when the skill names a tool the server doesn't have. Connecting Claude Code or Codex, from `arx setup` or from the app, also writes it to `~/.claude/skills/arx-browser/SKILL.md` or `~/.codex/skills/arx-browser/SKILL.md`; a failure there doesn't undo the connection. Only a `SKILL.md` that says `name: arx-browser` and carries `AgentSkill.ownershipMarker` (an HTML comment) is replaced or removed, so a skill someone else wrote under the same name stays. `arx guide` prints it. Claude Desktop and Cursor have no skill folder to write, and get the compact version in the server's `instructions` (`AutomationTools.instructions`). Every change to the MCP tools updates the skill, bumps `version`, and keeps the instructions in step. Sources: https://code.claude.com/docs/en/skills, https://developers.openai.com/codex/skills
- `AgentSiteSkill` is a skill per site agents use often: `arx-gmail`, `arx-google-docs`, `arx-google-sheets`, `arx-linear`, `arx-github` and `arx-notion`, each in Arx's tool terms (which address reads a sheet as a table, which controls change an issue). Their `SKILL.md` frontmatter adds `sites:`, hosts with an optional path (`docs.google.com/spreadsheets`); a host covers its subdomains. `Skill/<name>/SKILL.md` is the source and `AgentSiteSkillText.swift` compiles the same text in; `AgentSiteSkillTests` fails while they differ, and `AutomationGuidanceTests` fails when one names a tool the server doesn't have. Each has its own `version`, raised with every change. `AgentSkill.install` and `remove` write and delete them beside `arx-browser`, with the same ownership rule. The MCP server names the matching one in its first answer about that site's page and serves it as `arx://skills/<name>`; `arx guide <name>` prints one.
- `AgentConfigFiles` holds the file locations, the exact entry shown before writing, and the writes. Writes go through Files, so a linked file stays linked and keeps its permissions. Other entries and settings are kept. A file that isn't valid JSON is never replaced.

## Automated runs

`liveValue` is inert (`.unavailable`) outside an app bundle, which includes every `swift test` run, since Swift Testing sets no XCTest keys. It's also inert for XCTest runs, smoke fixtures (`ARX_ENGINE_PROFILE`, `--arx-…`), headless runs and `ARX_SKIP_AGENT_TOOLS`. `liveValue` read during a test reports a test failure (IssueReporting's `isTesting`, which also recognizes `swiftpm-testing-helper`) and returns the inert client. `testValue` is unimplemented. Tests build `.files(home:…)` over a temporary folder with stand-in helpers and a recorded process runner. Every write also passes `RealHomeGuard` (BrowserAutomationClient), which refuses and reports any target inside the real home folder while tests run. This covers installing and uninstalling `arx`, each agent file, running `claude` (which edits `~/.claude.json` whatever home it's given) and the credential file.
