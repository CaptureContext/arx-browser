# AppUI preview interaction tests

Tests the preview's organization-editing commands against BrowserCore fixtures: same-parent and favorite reordering, nested-folder moves, pinning and unpinning, retained favorite selection across spaces, same-profile favorite selection when switching spaces, reset/remove tab behavior, and atomic rollback for cycles or invalid folder destinations. Run `make test-preview` or the AppUIPreview scheme's test action. The full `make test-all` gate includes these tests. These tests validate model transitions; pointer and keyboard behavior is exercised in the preview app.

Resource tests exercise generated localized strings with typed placeholders and resolve light/dark color variants from the built AppUI resource bundle.

SidebarDropLayoutTests exercise pointer placement independently of model moves: folder edges versus centers, nested indentation and end-of-folder insertion, regular-tab positions, blank and empty regular sections, and exclusion of the New Tab button. Physical pointer testing still verifies drag-session delivery and visual feedback.

DesignSnapshotTests render the sidebar, a window with the page card, the command bar (in a 1440-point window, at its default width), the onboarding welcome page with its Skip Setup footer and the onboarding default-browser page (before and after Arx is the default), the onboarding import summary (choosing, importing and a partial result), each onboarding tour page at its demo's key frame (and the chats demo once more before a suggestion is chosen, `onboarding-tour-chats-suggestions`) offscreen in light and dark appearance and write PNGs for visual review. They are skipped unless `ARX_DESIGN_SNAPSHOTS` names an output directory; with `xcodebuild test` pass `TEST_RUNNER_ARX_DESIGN_SNAPSHOTS=<dir>`. They assert nothing about pixels, and hover states are not captured.

`ChromeTintTests` always run: the default tint must match the `browser.sidebarTop/Bottom` and `pageTop/Bottom` asset colors in both appearances, and neutral, default and vibrant tints (drawn under selected, hovered and resting rows and a page card) must render differently. With `ARX_DESIGN_SNAPSHOTS` set they also write `chrome-tint-{neutral,default,vibrant}` and `chrome-appearance-editor` PNGs in light and dark.

`OnboardingWelcomeRenderingTests` always run: the settled welcome page and the default-browser page draw over their background and differ between light and dark, and the default-browser page changes once Arx is the default. The import summary draws each of its states differently. Each tour page draws its key frame, differently in light and dark and from the other tour pages.

`TourVideoExport.swift` holds `TourVideoExporter`, which draws `TourDemoScene` frame by frame with `ImageRenderer` over the window background and writes H.264 MP4s through AVAssetWriter, offscreen and without interaction. `TourDemoRenderingTests` always run: Peek exports to a non-empty 640 × 360, 30 fps video of exactly one 8-second loop (written under `build/Tests` and removed afterwards), and every demo's key frame differs from its first frame and between light and dark, and repeats one loop later. `TourVideoExportTests` run only when `ARX_TOUR_VIDEOS` names an output directory (`TEST_RUNNER_ARX_TOUR_VIDEOS` with `xcodebuild test`); `make tour-videos` sets it and writes `<demo>-light.mp4` and `<demo>-dark.mp4` at 1280 × 720 and 30 fps into `build/tour-videos/`. Resource tests also load the onboarding strings for every `OnboardingStep`.
