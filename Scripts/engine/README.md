# Engine builds

`make engine-checkout`, `make engine-prepare`, and `make engine-build` fetch pinned Helium sources, prepare Chromium, apply the independent Arx bridge, and build the complete native framework. Python modules separate configuration, checkout validation, source edits, and build orchestration. Generated sources and outputs stay under ignored `.build/engine`. No distribution signing or publishing is performed.

`make engine-upstream`, `make engine-bump` and `make engine-anchor-check` (`upstream.py`, `anchors.py`) automate moving to a new Helium release (DEV-955): they find a helium-macos release newer than the lock, move the pins, and run the overlays on a sparse tree of only the files they open, fetched from Chromium's Gitiles with Helium's patches applied, so the nightly workflow can report missing anchors without the 30 GB tree. The workflow runs them through `automation.py`, which imports nothing macOS-only, on GitHub's Ubuntu runner. See DEVELOPMENT.md › Engine updates.

`make engine-tools` creates the build Python environment. `make engine-check` compiles just the bridge and its generated prerequisites. `make engine-host` bundles the built framework with a Swift development executable; `make engine-smoke` verifies a local fixture load and clean shutdown. Both hosts require stable Apple Development signing and an interactive session. They are not distribution builds.

`artifact.py` records completed build identities. `embed.py` copies only a matching framework into the Xcode app, preserving resources and helper bundles. `make app-smoke` exercises that real app; `make engine-smoke` exercises the separate host.

Engine smokes run without content blocking (`ARX_ENGINE_CONTENT_BLOCKING=0`, which the host applies before the engine starts), except the extension, extension install and site settings smokes, which test it (`smoke.keeps_content_blocking`). On a fresh profile Helium's uBlock Origin reloads itself once after its first run and then fetches lists from the network; reference-keypress-smoke's first phase lost a report request to that. None of the fixtures' own URLs match a rule in uBlock's default lists.

`make engine-cache` uses `archive.py` to package only a complete, matching local framework into ignored `.build/engine-archives/<source fingerprint>/`, with architecture validation and a checksum, source and release URL manifest in `Artifacts/Engine/`; it prints the `gh release` command that publishes the archive. `make engine-restore` uses `cache.py` to verify and safely unpack a local archive into ignored `.build/engine/prebuilt/`, preserving internal links and executable bits. `cache.py` selects a matching source build first and a restored artifact second; embedding, app smoke, and the standalone host share that selection. Source-build fingerprints and stamps are unchanged. No Chromium checkout is needed to restore. See [cache setup](../../Artifacts/Engine/README.md) for another Mac and refresh instructions.

The standalone engine host uses a distinct `.engine-host` bundle identifier so Launch Services and Dock metadata cannot collide with Arx.

`fetch.py` uses a verified local archive (built or downloaded here, then a copy beside the manifest) or downloads the manifest's release URL, checks size and SHA-256 before unpacking, then restores it. `bundle.py` validates the complete pinned runtime layout and Mach-O architectures without changing build fingerprints. `make engine-validate` checks the selected source/restored engine, and `make build-app-runtime` requires and validates the engine in an unsigned app. `make test-runtime` runs the signed engine and app smoke checks separately from `test-all`; logs including preflight and timeout failures live in `build/logs/runtime/`. The [cache README](../../Artifacts/Engine/README.md) documents CI setup and the validated architecture matrix.

ABI7 adds the extension bridge to the overlay/object gate. Its public capability stays disabled pending a packaged disposable MV3 fixture; the active native build must not receive overlays from this staging branch.

`make extensions-smoke` runs the developer-only ABI7 host fixture. It requires native-owned fresh storage and mock Keychain plus exact worker/DNR, profile isolation, mutation, permission guard, removal, private refusal and clean-shutdown markers. The caller-supplied profile directory must remain absent. `link_context_overlay.py` adds a browser-only coordinate proof to ContextMenuParams and sets it only after proven root-widget transformation. The field is absent from renderer IPC; site properties cannot forge it. It is fingerprinted with the native sources. `make link-context-smoke` requires the matching rebuilt/signed framework and fresh owned fixture storage; it never drives the user browser or requests fixture href destinations.

`site_settings_bridge.mm` (ABI38, DEV-716) needs no overlay either: it uses `HostContentSettingsMap`, `HostZoomMap` and `ChromeZoomLevelPrefs` as they are. `make site-settings-smoke` (`site_settings_smoke.py`) checks it with owned disposable storage.

`focused_link_bridge.mm` (ABI37, DEV-713) needs no overlay: it runs a read-only script through `RenderFrameHost::ExecuteJavaScriptInIsolatedWorld` in Chrome's internal world of the focused frame. `make focused-link-smoke` (`focused_link_smoke.py`) checks it against owned fixture pages.

`hovered_link_bridge.mm` (ABI60, DEV-1118) needs no overlay either: it runs a read-only script through `RenderFrameHost::ExecuteJavaScriptInIsolatedWorld` in the Chrome-internal world of each live frame of a page, for its `:hover` link and that link's target, and the hovered-link report waits for the answers (250 ms at most).

`widevine_answer_overlay.py` (DEV-1144) answers Widevine without a CDM behind `media::kArxWidevineAnswer` and records a missing library CDM on its document; `protected_media_overlay.py` reports it as failed playback once a media element in the document or a same-origin frame of its page wants keys and as keys without media until then, and never reports a page's first EME question (DEV-1211). A refused `requestMediaKeySystemAccess` reports only when nothing in the document was granted a protected key system within 3 seconds and the document is still shown (not in the back/forward cache or prerendering) when they're up, and `MediaCapabilities.decodingInfo` never reports, so bot detection that probes every key system isn't offered WebKit (DEV-1205); with the feature off, that refusal is failed playback only once a media element wants keys (DEV-1211). It upgrades a tree prepared with its DEV-877, DEV-1144 or DEV-1205 version. `page_media_overlay.py` (DEV-1144), applied after `inspection_overlay.py`, copies `Packages/engine/Native/page_media` to `components/arx_page_media`, creates a `PageMediaAgent` for each outermost main frame and registers the `PageMediaHost` binder. See the Native README's "Widevine answered without a CDM" and "Page media bridge". Tests: `test_widevine_answer_overlay.py`, `test_page_media_overlay.py`, `test_protected_media_overlay.py`.

`media_freeze_overlay.py` adds truthful actual-PiP and exact-page media scheduling
reasons to Performance Manager. The native ordinary-media observer owns the
candidate lease before hiding; it does not authorize automatic entry or restart
paused playback. The overlay also inserts four tests into Chromium's existing
FreezingPolicy graph suite. Python harness tests execute extracted production
lease, reference-count, selection and cleanup code without launching Chromium.
Graph tests and signed fixtures require their respective native build/run; a
syntax check does not establish runtime acceptance. These native inputs and the
overlay are included in the source fingerprint and require a framework rebuild.

`document_capture_prototype.py` and its budget overlay remain opt-in and outside shipping overlay/artifact inputs. Marked isolated copies receive resource admission before Paint Preview image conversion and bounded incremental PNG serialization; applying to the configured source is refused. See the DocumentCapture prototype README for the deliberately restricted rendering subset and unresolved page-paint/runtime resource acceptance.

`document_capture_overlay.py` includes the capture path and owned native fixture in the coordinated ABI16 build/fingerprint. The isolated prototype helper still refuses shared/unmarked trees. `make document-capture-smoke` requires the matching rebuilt signed framework, native-owned fresh profile storage, host-owned disposable root and every pixel/state/invalidation marker.

`gesture_overlay.py` is part of normal native preparation and preserves Chrome's
installed responder and desktop handling. Every Arx Page installs the controller;
the explicit fresh native-owned mock-Keychain fixture enables synthetic points. Its queue identity/ACK seam is browser-only. Native progress
and the session-history scrubber share one-use ownership and source invalidation.
`make gesture-smoke` requires every native arbitration/navigation/cancellation

uses synthetic browser points plus real renderer input; physical NSTouch/device

The native compile gate checks the gesture controller, panel and fixture plus
the patched event queue, input routers, widget host and macOS delegate before

`document_recording_overlay.py` stages capture-only admission in RecordPaintCanvas and transient Blink recording controllers. Its header/patches are fingerprinted. Native checks include the touched canvas/controller/chunker units; sanitizer peers execute actual admission prefixes before deterministic allocation counters. Ordinary painting has no active capture budget. The document smoke runner requires the independent recording-limit-and-repaint marker as well as complete-document pixels and invalidation cases.

The owned document fixture now includes horizontal/fractional-scroll, fixed/sticky placement, lazy/no-fetch, loading metadata, and 125% zoom cases, plus whole-result canvas/opacity-animation/child-frame rejection. All preserve before/after page reports and viewport pixels. Fixed/sticky are verified through actual pixels rather than denied by position alone. Native runtime execution is pending; negative-overflow, non-default pinch, protected/animated image cases and late-stage cancellation remain explicit coverage gaps.

`extension_install_overlay.py` adds a default-off verified pre-install prompt to explicit embedded CRX updates while preserving ordinary updater behavior and the standard verifier. Its exact anchors are fingerprinted with native inputs. `build.check_native` checks the new install bridge and pinned CrxInstaller units. Developer signed-package fixture generation remains behind the separate native-owned/mocked fixture option.

`make extension-install-smoke` runs the separate signed-CRX developer fixture in fresh native-owned mock-Keychain storage. It requires every consent/verification/update/isolation phase and clean shutdown; the runner refuses mixed fixture modes and caller-profile creation. Only the exact index route is served. A matching coordinated native build is required.

`background_pages_overlay.py` (DEV-944) adds `ChromeProcessManagerDelegate::SetEmbedderBackgroundPageRefusal`, a plain function the delegate asks about each regular profile before allowing extension background pages there; off-the-record contexts are never asked. `engine_bridge.mm` installs one for the bootstrap profile `Arx-Bootstrap`, which never shows pages, so its copy of Helium's uBlock Origin component no longer keeps a renderer. uBlock is a split-incognito extension, so private contexts never used that copy. Without a hook Chrome's policy is unchanged. The overlay is fingerprinted with the native inputs; a changed upstream anchor stops the build (`Scripts/tests/test_background_pages_overlay.py` pins the anchors against the Helium-patched source).

`bangs_overlay.py` switches off Helium's omnibox !bangs (DEV-687). Helium's `add-native-bangs.patch` makes every TemplateURLService load start `Bangs::BangManager`, which (since Helium 0.21) loads `<Helium services>/bangs.json` through a shared SimpleURLLoader cache whenever `helium::ShouldFetchBangs` allows it, and retries failures. Arx never uses Chromium's omnibox and resolves bangs from its own bundled list, so `LoadBangs` now always takes Helium's own "don't fetch" branch and answers with an empty catalogue: no loader is created, nothing is requested, no retry is scheduled, and no bang keywords join the TemplateURLService. The rest of Helium's bang code stays and compiles. The overlay is fingerprinted with the native inputs; a changed upstream anchor stops the build (`Scripts/tests/test_bangs_overlay.py` pins the anchor against the Helium-patched source).

`startup_metrics_overlay.py` compiles Chrome's TPM benchmark out on macOS (DEV-894). `ChromeBrowserMainExtraPartsMetrics::PostBrowserStart` in `chrome_browser_main_extra_parts_metrics.cc` posts `crypto::MaybeMeasureTpmOperations` 45 seconds after every launch (Chromium 157 samples it only on Stable; an unbranded build's channel is unknown, so it always runs): it creates, signs with and deletes Secure Enclave keys in the login keychain (about 0.6 s of browser-process CPU) only to record `Crypto.TPM*` histograms, which Arx never uploads. Windows keeps the call; device-bound session keys and every other user of the unexportable-key provider are unchanged. The engine also starts with two metrics-only or unused features off (`--disable-features` in `engine_bridge.mm`): `GatherProcessRequirementMetrics` (a code-signing self-check that only records `Mac.ProcessRequirement.*`) and `AutofillAiWalletPrivatePasses` (Google Wallet passes in Autofill AI, which made every ordinary page's autofill client ask LocalAuthentication whether device re-auth is available, synchronously on the UI thread). The overlay is fingerprinted with the native inputs; a changed upstream anchor stops the build (`Scripts/tests/test_startup_metrics_overlay.py` pins the anchor against the Helium-patched source and, when a prepared tree exists, against it).

`services_overlay.py` compiles out Helium's services (DEV-930). Helium kept them dormant behind a consent pref Arx never sets, so a stray pref or a Helium change could have started requests to Helium. `ShouldAccessServices` now always answers no, so every `helium::Get*URL` helper (extension proxy, web store snippets, spellcheck dictionaries, browser and component updates, uBlock assets, bangs) returns `GetDummyURL()`, `https://helium-services-are-disabled.qjz9zk`. `GetServicesBaseURL` ignores the services-origin pref and returns the same host, and `kHeliumDefaultOrigin` and Helium's update feed base are that host, so `services.helium.imput.net` and `updates.helium.computer` aren't in the binary. Chromium's crash upload URL (`crash.helium.computer` in official builds) is empty, so Crashpad keeps reports on the Mac for Arx's own crash reports (DEV-887), and extension update pings are tied to `arx-pings-are-disabled.invalid`. Component updates (DEV-874) and uBlock Origin's lists (DEV-884) have their own paths that don't call these helpers. A changed anchor stops the build (`Scripts/tests/test_services_overlay.py`, which also checks the anchors against the pinned source when it's on the Mac).

`hosts.py` (`make engine-hosts [ARGS=<framework>]`, DEV-930) lists every host hard-coded in the engine framework's binaries (the framework, helpers and libraries; compressed `.pak` resources aren't read) into `build/logs/engine-hosts.txt`, and fails on any Helium host (`helium.computer`, `imput.net`), in a URL or bare, and on any Google URL host missing from `allowed-hosts.json`. Each allowed host has a reason and is one Chromium needs for something Arx uses: Chrome Web Store installs, component updates, Google search for a profile that picks it, WebAuthn, device-bound sign-in cookies, certificate fetches, and links that are only opened when clicked. `"review": true` would mark one kept until someone confirms nothing fetches it, and the check prints those; none are left. Google hosts for features Arx doesn't have (Chrome Enterprise, tab context sync, Lens image search, Google Safe Browsing's relay) are taken out of the engine by `services_overlay.py` instead of allowed. Bare Google host names (HSTS preload and pinning tables) are data and only listed. `make engine-build` runs the check before it marks a build complete.

`password_manager_overlay.py` (DEV-708) undoes Helium's forced `credentials_enable_service`, keeps passkeys off, adds `//chrome/browser/arx:*` to `actor_login`'s delegate visibility and adds an embedder save-prompt hook to `ChromePasswordManagerClient`. `password_smoke.py` (`make password-smoke`) runs the engine host against `Scripts/core/password_fixture.py` with two profiles, a private page and the mock Keychain: save then fill, a one-time-code step, a same-origin frame, frame, document and origin changes, Never, profile isolation, private pages and a refused password. The user's fill (DEV-875) follows the save: the fixture account's suggestion for a focused username field carries only the account, a fill that would ask the device owner is refused and leaves the field empty, a fill without asking signs in, Down then Return fills from the keyboard, Escape closes, and a private page is offered nothing. Then Settings (DEV-721): list, an edit through a lent field proven by an agent sign-in, add, a duplicate refused, rename, remove a password and a "never saved" site, stale and missing reveals refused before any prompt, a Chrome CSV into profile B (proven by a sign-in there, with a skipped row), an Apple Passwords CSV with an `OTPAuth` column into profile C, the same file with changed passwords reported as conflicts and kept, a CSV without a password header refused, per-profile lists and no list for a private profile. CSVs are written outside the profile and removed. `/password/rotate?to=<suffix>` sets the site's password to the probe plus that suffix. It fails if the probe password, or anything that contains it, appears in any reply, log, error or file of the disposable profile.

`native_messaging_overlay.py` (DEV-889) adds Arx's own and Chromium's per-user folders, and Arx's system folder, to the native messaging host lookup. `extension_uninstall_overlay.py` (DEV-889) lets Arx confirm `chrome.management.uninstall` with its own sheet. `private_extension_routing_overlay.py` (DEV-889) lets one profile have several private windows' off-the-record contexts in webRequest's routing (`CrossContextData`): each keeps its pairing with the profile when another closes, so a spanning extension allowed in private windows keeps hearing their requests. `content_blocking_overlay.py` (DEV-884) adds `js/arx.js` to Helium's uBlock Origin. `cast_overlay.py` turns Chrome's Cast back on (DEV-927). Helium builds without mDNS and service discovery; `build.configure` now writes Helium's `args.gn`, turns `enable_mdns` and `enable_service_discovery` (Chromium's macOS defaults) back on with `enable_cast_discovery`, which fails if either `=false` line is missing, and then runs `gn gen`. Nothing else in Helium's args changes. The overlay undoes only what exists to build without them: ungoogled-chromium's `fix-building-without-mdns-and-service-discovery.patch` (the emptied `DnsSdDeviceLister` and the registry's service discovery client) and `disable-dial-repeating-discovery.patch` (DIAL's SSDP search and its repeat), and restores the production Google and YouTube origins the Cast and DIAL providers compare a page's origin with, and the legacy `https://google.com/cast#` presentation prefix, which domain substitution had rewritten; they are compared, never fetched, and listed in `allowed-hosts.json`. It also makes `chrome_browser_main_extra_parts_views.cc`'s Media Router dialog getter ask Arx's picker first (`Native/cast_hooks.h`). `check_native` compiles the restored discovery files, `service_discovery_client_mac.mm` (only in the graph with the flags on), the views file and `cast_bridge.mm`. Turning the flags on also builds Chromium's `chrome.mdns` extension API (allowlisted extensions only) and DevTools' Cast device provider, as in Chrome. It needs a fresh `gn gen` and a full engine rebuild. `Scripts/tests/test_cast_overlay.py` pins the anchors, repeatability and the args edit.

`bfcache_media_session_overlay.py` keeps a page's Media Session after Back or Forward restores it from the back/forward cache (DEV-960). The restored document's `navigator.mediaSession` still holds its metadata and action handlers and never sends them again, but `MediaSessionImpl::DidFinishNavigation` reset the browser's copy in the frame's `MediaSessionServiceImpl` as for a new document, so the title, artist, artwork and the previous track, next track and seek buttons were gone until the page set them again (Chrome does the same). For a navigation that `IsServedFromBackForwardCache()`, the session now calls the service's new `DidRestoreFromBackForwardCache`, which keeps metadata and actions and still clears the playback state, since the players come back paused. Anything the page sets after the restore replaces what was kept, and every other navigation resets the service as before. `media_bridge.mm` keeps the restored document's artwork to match. `check_native` compiles both session files, and `make back-forward-cache-smoke` checks the track, artist, artwork and buttons after Back and after Forward, and that a change the page makes after a restore wins. `Scripts/tests/test_bfcache_media_session_overlay.py` pins the anchors and repeatability.

`file_stream_guard_overlay.py` stops a shutdown crash in Chromium's own `net::FileStream` (found by engine batch 4's media smoke). On the Mac its `Context` guards its descriptor against `close` with its own address, and drops the guard in `CloseFileImpl`. A FileStream that goes away hands the Context to a `CloseFileImpl` task. When the thread pool skips that task at shutdown, the Context is deleted without it, and its `base::File` closes the still-guarded descriptor: EXC_GUARD (GUARD_TYPE_FD, CLOSE) on a worker thread. The Context's destructor now drops its own guard when it still holds the file. `check_native` compiles the file, and `Scripts/tests/test_file_stream_guard_overlay.py` pins the anchor and the guard it names.
