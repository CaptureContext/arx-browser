# macOS container

The Arx macOS application target links the root `Application` package product. `main.swift` forwards startup. XcodeGen generates `Info.plist` and `Arx.entitlements` from `.xcodegen/macOS.yml` and includes both in the project navigator. Edit the YAML and run `make project`; the generated files are ignored. All application composition belongs in AppFeature.

The minimum macOS version is 27. The bundle identifier is `dev.capturecontext.arx`; Debug builds are Arx Dev, `dev.capturecontext.arx.dev`, named "Arx Dev" (`ARX_DISPLAY_NAME`) with `AppIcon-Dev.icon`, their own Keychain item (`ARX_STORAGE_KEY_SERVICE` and `ARX_STORAGE_KEY_ACCOUNT`, read by the engine from Info.plist) and Chromium folder (`CrProductDirName`), and no update feed (DEV-1013, [DEVELOPMENT.md › Arx Dev](../../DEVELOPMENT.md#arx-dev)). The development build command disables code signing. XcodeGen reads the signing team from `DEVELOPMENT_TEAM`, loaded by mise from the optional local `.env`. Run `make project` after changing it. Without a team, project generation still supports unsigned builds.

The Info.plist principal class is Chromium's BrowserCrApplication. The embedding build phase copies a complete, current local engine framework with its resources and helpers. Without one, unsigned compilation still works and emits a warning; launching requires `make engine-build` followed by rebuilding the app. Stale embedded engines are removed.

The macOS App Sandbox is disabled for this Chromium host. Chromium's renderer sandbox remains enabled. Debug builds disable Hardened Runtime for the development framework; Release keeps it enabled. Developer ID signing, helper entitlements, notarization and the disk image are handled by `make dmg`; see the [scripts README](../../Scripts/README.md#release-disk-image).

The app's entitlements also carry iCloud (CloudKit, container `iCloud.dev.capturecontext.arx`) and push notifications for later sync work. Their container and push environments come from the `ARX_ICLOUD_ENVIRONMENT` and `ARX_APS_ENVIRONMENT` build settings, `Development` and `development` by default. Signed builds embed a provisioning profile through `PROVISIONING_PROFILE_SPECIFIER = $(ARX_PROVISIONING_PROFILE)`, set only on this target; a signed Arx Dev without its profile is signed without iCloud and push, which the build drops from the generated entitlements (DEV-1013); see [provisioning profiles](../../Scripts/README.md#provisioning-profiles-and-icloud).

The member number's sign-in client comes from `.env` into Info.plist: `ArxAppleServicesID` (`ARX_APPLE_SERVICES_ID`, Apple's web sign-in, DEV-1313). Empty leaves sign-in out. Google's sign-in was removed (DEV-1323). The app claims no Sign in with Apple entitlement: Apple signs in on the web ([DEVELOPMENT.md › Signing](../../DEVELOPMENT.md)).

`AppIcon.icon` is the shipping Icon Composer document, using the approved vector key design. It contains separate SVG layers for the keycap and mark. The target selects `AppIcon` through `ASSETCATALOG_COMPILER_APPICON_NAME` in `.xcodegen/macOS.yml`; Xcode compiles its appearances and sizes into the app. Edit this document for future app-icon changes, and `AppIcon-Dev.icon`, Arx Dev's blue copy (Debug's `ASSETCATALOG_COMPILER_APPICON_NAME`), with it. Arx Dev always shows its own icon in the Dock. The exploration sources remain under `Design/AppIcon/VectorKey`.

Settings › Appearance offers a dark and a light Dock icon (DEV-839). Both are renditions of this document in AppUI's `Images.xcassets` (`appIcon.dark`, `appIcon.light`, at 1x and 2x). After changing the icon, export them again with Icon Composer's `ictool`, for each of `dark`/`Dark` and `light`/`Default` and each scale:

```bash
ictool Containers/macOS/AppIcon.icon --export-image --output-file Packages/design-system/Sources/AppUI/Resources/Images.xcassets/appIcon.dark.imageset/appIcon-dark@2x.png --platform macOS --rendition Dark --width 512 --height 512 --scale 2
```

`ictool` ships inside Xcode, in `Contents/Applications/Icon Composer.app/Contents/Executables/`.

`Credits.rtf` is generated by `make credits` from `THIRD_PARTY_NOTICES.md`, `LICENSE` and `Distribution/Licenses/`, and lands in the app's Resources. AppFeature's About Arx item shows it as the About panel's credits; don't edit it by hand. `Scripts/tests/test_credits.py` fails when it's out of date or a resolved package has no notice.

The Arx target builds the thin ArxMCP tool entry point and embeds/signs it at `Contents/Helpers/ArxMCP`. Python is used only by an independent protocol test fixture, never shipped.

The authoritative XcodeGen input declares camera, microphone and location usage
messages and matching hardened-runtime entitlements. These declarations allow
macOS to present its own privacy consent after a website receives Arx's explicit
site permission; they do not grant either site or system permission. Actual
signed permission/device behavior remains a separate runtime acceptance gate.

Languages (DEV-1291): Info.plist declares `CFBundleDevelopmentRegion` `en` and `CFBundleLocalizations`, which must list English and exactly the languages `Localization/languages.json` ships (`make check` fails otherwise). macOS picks the app's language from this list, and every bundle inside the app follows it: AppUI's strings, AppKit's own menu items, Sparkle and the engine. A language not listed here is never shown, however complete its translations are. `InfoPlist.xcstrings` translates the usage descriptions above into `<lang>.lproj/InfoPlist.strings`; its English must match `.xcodegen/macOS.yml` and `Scripts/core/privacy.py` word for word, which `make check` also checks. See `.agents/LOCALIZATION.md`.

Casting (DEV-927): `NSLocalNetworkUsageDescription` names casting, and `NSBonjourServices` lists `_googlecast._tcp`, the Bonjour service Chromium's Media Router browses for Chromecasts. macOS asks for Local Network access the first time a Cast picker opens, and refuses to browse a Bonjour type the bundle doesn't list. DIAL's SSDP search needs only the Local Network permission. `Scripts/core/privacy.py` keeps the same values for the engine host.


`make external-consent-smoke` is an explicit DEBUG-only mock-Keychain app mode.
It uses a uniquely registered inert owned handler for real protocol lookup and
Chrome dialog acceptance; native interception suppresses all OS dispatch in that
fixture process. It does not validate real external-application launch.

`main.swift` also declares `ArxAppIntents`, the app target's `AppIntentsPackage`, so Xcode's App Intents metadata includes the packages' Shortcuts actions (DEV-929). The Info.plist registers the `arx` URL scheme beside http and https for `arx://open`, `arx://little` and `arx://space`.

`Arx.sdef` is Arx's AppleScript dictionary (DEV-909), named by the Info.plist's `OSAScriptingDefinition` with `NSAppleScriptEnabled`; its Cocoa classes live in AppFeature's `AppleScripting.swift`.
